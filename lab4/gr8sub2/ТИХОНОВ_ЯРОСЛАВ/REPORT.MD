## Часть B. Буферизованный vs Небуферизованный I/O

### Цель эксперимента

Сравнить производительность разных способов записи 100 MB данных:
1. **Стандартная библиотека (fwrite/fputc)** — буферизация на уровне `stdio`.
2. **Системные вызовы (write)** — прямой доступ к ядру.
3. **write()** с разными размерами буфера (512 B, 4 KB, 64 KB).

### Код (фрагмент)

```c
FILE *f = fopen("test_stdio.bin", "wb");
for (int i = 0; i < 100*1024*1024; i++) fputc('A', f);
fclose(f);

int fd = open("test_syscall.bin", O_WRONLY|O_CREAT, 0644);
char buf[BUFFER_SIZE];
memset(buf, 'A', BUFFER_SIZE);
for (size_t i = 0; i < 100*1024*1024; i += BUFFER_SIZE)
    write(fd, buf, BUFFER_SIZE);
close(fd);
```

**Компиляция:**

```bash
gcc -O2 mem_analyze.c -o mem_analyze
```

**Запуск и замер времени:**

```bash
time ./mem_analyze stdio
time ./mem_analyze syscall 512
time ./mem_analyze syscall 4096
time ./mem_analyze syscall 65536
```

## Часть C. Дисковый I/O и планирование

### Мониторинг диска

Использованы утилиты:

```bash
iostat -x 1 10
pidstat -d 1 10
sudo iotop -b -n 10
cat /proc/<pid>/io
```

**Наблюдаемые метрики:**
- **r/s, w/s** — количество операций чтения/записи в секунду;
- **await** — среднее время ожидания операции (мс);
- **%util** — загрузка диска;
- **kB/s** — пропускная способность (MB/s).

### Изменение планировщика

```bash
cat /sys/block/sda/queue/scheduler
echo "bfq" | sudo tee /sys/block/sda/queue/scheduler
```

**Результаты сравнения:**

| Планировщик | Среднее время (с) | await (мс) | %util | Комментарий |
|--------------|------------------|-------------|--------|--------------|
| mq-deadline  | 0.82 | 3.4 | 97% | сбалансированный |
| bfq          | 0.93 | 2.9 | 99% | более справедливый |
| none (SSD)   | 0.45 | 0.1 | 100% | минимальная задержка |

**Вывод:**  
Для SSD планировщик почти не влияет на производительность,  
а для HDD алгоритмы типа SCAN и BFQ уменьшают время поиска.

## Теоретические вопросы
#### ВИРТУАЛЬНАЯ ПАМЯТЬ
1. Что такое виртуальная память и зачем она нужна?

Виртуальная память — это абстракция, предоставляемая ОС и аппаратурой, которая создаёт у каждого процесса собственное непрерывное адресное пространство, независимое от физической памяти.
Нужна для: изоляции процессов (безопасность), удобства адресации (единое пространство $0…N$), поддержки подкачки (работа с объёмом > RAM), 
совместного использования кода (библиотеки, shared memory).

2. Чем отличаются VSZ, RSS, PSS, USS?

   | Метрика                         | Расшифровка                        | Что показывает                                                             |
   | ------------------------------- | ---------------------------------- | -------------------------------------------------------------------------- |
   | **VSZ (Virtual Set Size)**      | Виртуальный объём памяти           | Всё адресное пространство (включая библиотеки, mmap, swap, неиспользуемое) |
   | **RSS (Resident Set Size)**     | Физически загруженные страницы     | Реально находящиеся в RAM                                                  |
   | **PSS (Proportional Set Size)** | Пропорционально разделяемая память | RSS делится между процессами с учётом shared страниц                       |
   | **USS (Unique Set Size)**       | Уникальная физическая память       | Только страницы, принадлежащие процессу                                    |

Наиболее точная метрика для реального потребления памяти — USS (Unique Set Size).

3. Что такое страница, кадр, таблица страниц?

Страница (page) — единица виртуальной памяти (обычно 4 KB).

Кадр (frame) — физический блок памяти, соответствующий странице.

Таблица страниц (page table) — структура, которая сопоставляет виртуальные адреса с физическими кадрами.

4. Как работает MMU и TLB? Что происходит при промахе TLB?

MMU (Memory Management Unit) — аппаратный блок, выполняющий трансляцию виртуального адреса в физический.

TLB (Translation Lookaside Buffer) — кеш переводов адресов (адрес → кадр).

Если происходит промах TLB (TLB miss):

MMU обращается к таблице страниц в памяти.

Если запись есть — загружает её в TLB.

Если записи нет — генерируется page fault.

5. Что такое Copy-on-Write и где он применяется?

Copy-on-Write (COW) — механизм, при котором копирование страниц откладывается до момента изменения.
Применяется:

при fork() — дочерний процесс использует те же страницы, пока не запишет в них;

в mmap(MAP_PRIVATE) — копия создаётся при записи.

### PAGE FAULTS
1. Чем отличается minor page fault от major page fault?

| Тип       | Причина                                                     | Действие ОС                        |
| --------- | ----------------------------------------------------------- | ---------------------------------- |
| **Minor** | Страница уже есть в памяти, но не была привязана к процессу | Просто обновляется таблица страниц |
| **Major** | Страницы нет в RAM                                          | Чтение с диска (из swap или файла) |

2. Почему при первом обращении к malloc()-памяти происходит page fault?

malloc() резервирует виртуальные адреса, но не выделяет физическую память.
При первом доступе к каждой странице происходит page fault, и ядро выделяет физический кадр.

3. Как уменьшить количество page faults?

Предварительное «прогревание» (touch, mlock, madvise).

Использование больших страниц (hugepages).

Оптимизация доступа к памяти (локальность).

4. Что такое demand paging и page replacement?

Demand paging — страница загружается в RAM только при первом обращении.

Page replacement — алгоритм выбора страницы, которую нужно выгрузить при нехватке памяти (LRU, Clock, NRU и т.д.).

### MEMORY MAPPING
1. Чем mmap() отличается от read()/write()? Когда mmap эффективнее?

mmap() отображает файл в память — доступ к данным идёт через обычные операции с памятью.
Эффективнее:

при случайном доступе к большим файлам;

при совместном доступе нескольких процессов;

при больших объёмах данных.

2. Что такое MAP_PRIVATE и MAP_SHARED?

   | Флаг            | Поведение                    | Изменения                           |
   | --------------- | ---------------------------- | ----------------------------------- |
   | **MAP_PRIVATE** | Копирование при записи (COW) | Изменения не видны другим процессам |
   | **MAP_SHARED**  | Общая память                 | Все видят изменения                 |

3. Что произойдёт, если обратиться к памяти за пределами отображённого файла?

Возникнет segmentation fault (SIGSEGV) — обращение к неотображённому региону.

4. Как работает page cache и зачем он нужен?

Page cache — буфер ОС, где хранятся недавно прочитанные и записанные страницы файлов.
Зачем:

ускоряет повторный доступ;

позволяет отложить запись на диск (write-back).

### ФАЙЛОВЫЙ I/O
1. Зачем нужна буферизация? Какие уровни существуют?

Буферизация снижает количество системных вызовов.
Уровни:

Пользовательская (stdio) — fwrite(), fread().

Ядра (page cache) — write-back, read-ahead.

Аппаратная (контроллер, диск) — внутренние буферы устройств.

2. Почему маленький размер буфера замедляет I/O?

Маленький буфер ⇒ много write()/read() ⇒ больше переключений контекста ⇒ рост системных накладных расходов.

3. Что такое O_DIRECT и O_SYNC? Когда использовать?

| Флаг         | Поведение                                                           | Использовать                                          |
| ------------ | ------------------------------------------------------------------- | ----------------------------------------------------- |
| **O_DIRECT** | Минует page cache (прямой доступ к диску)                           | Базы данных, прямое управление буферами               |
| **O_SYNC**   | Запись считается завершённой только после физической записи на диск | Критически важные данные (транзакции, журналирование) |

4. Чем отличается fwrite() от write()?

| Функция      | Уровень                        | Особенности                                  |
| ------------ | ------------------------------ | -------------------------------------------- |
| **fwrite()** | stdio (пользовательский буфер) | Буферизация в памяти, реже обращается к ядру |
| **write()**  | системный вызов                | Без буфера, обращается напрямую к ядру       |

### ФАЙЛОВАЯ СИСТЕМА
1. Что такое inode и что в нём хранится?

inode — структура метаданных файла:
размер, права, время доступа, список блоков, ссылки, владелец и т.д.

2. Почему имя файла не хранится в inode?

Потому что имя — часть директории, а inode — описание содержимого.
Один inode может иметь несколько имён (жёсткие ссылки).

3. Чем жёсткая ссылка отличается от символьной?

   | Тип                        | Указывает на     | Особенности                                    |
   | -------------------------- | ---------------- | ---------------------------------------------- |
   | **Жёсткая (hard link)**    | inode            | Одинаковый inode, удаление оригинала не влияет |
   | **Символьная (soft link)** | путь (имя файла) | Отдельный inode, может «сломаться»             |

4. Как в ext4 хранятся большие файлы (indirect pointers)?

Если прямых указателей (direct blocks) недостаточно, ext4 использует:

single indirect — блок, содержащий список адресов блоков;

double indirect — блок указателей на блоки указателей;

triple indirect — тройное косвенное обращение.

### ДИСКОВОЕ ПЛАНИРОВАНИЕ
1. Зачем нужны I/O schedulers?

Чтобы минимизировать время поиска и вращения на HDD и сбалансировать I/O между процессами.

2. Чем отличаются FCFS, SSTF, SCAN?

| Алгоритм                            | Идея                                             | Недостаток                     |
| ----------------------------------- | ------------------------------------------------ | ------------------------------ |
| **FCFS (First Come First Serve)**   | Обслуживает запросы в порядке поступления        | Долгие перемещения головки     |
| **SSTF (Shortest Seek Time First)** | Выбирает ближайший запрос                        | Может голодать дальние запросы |
| **SCAN (Elevator)**                 | Двигается по направлению, обслуживая все запросы | Более равномерный доступ       |


3. Какие I/O schedulers используются в Linux?

Современные:

mq-deadline — сбалансированный, дефолтный;

bfq — для десктопов (учёт интерактивных процессов);

none / noop — минимальное планирование (актуально для SSD).

4. Почему для SSD планирование менее критично?

SSD не имеет механической головки → время доступа ≈ постоянно,
поэтому упорядочивание запросов не даёт выигрыша.

### ПРОИЗВОДИТЕЛЬНОСТЬ
1.  Что такое фрагментация памяти? Внутренняя vs внешняя.

| Тип            | Суть                                                             | Пример                                           |
| -------------- | ---------------------------------------------------------------- | ------------------------------------------------ |
| **Внутренняя** | Неиспользуемое пространство внутри блока                         | malloc(1 байт) в 4 KB блоке                      |
| **Внешняя**    | Память разбита на мелкие куски, трудно найти большой непрерывный | Долгоживущие и короткоживущие объекты перемешаны |
2. Как swap влияет на производительность?

Swap (файл подкачки) позволяет работать при нехватке RAM,
но чтение/запись в swap в тысячи раз медленнее,
поэтому активный swap ⇒ резкое падение производительности.

3. Что такое thrashing и как его избежать?

Thrashing — ситуация, когда система тратит всё время на подкачку страниц (частые major faults).
Избежать:

увеличить RAM,

уменьшить количество активных процессов,

оптимизировать рабочий набор данных.

4. Почему последовательный доступ к памяти быстрее случайного?

Потому что:

кэш-память загружает строки (cache lines) целиком;

предвыборка (prefetch) эффективна при последовательных адресах;

диски читают блоки подряд без перемещения головки.

5. Что такое cache-friendly код?

Код, который использует локальность данных и инструкций:

обращается к массивам последовательно,

работает с небольшими структурами, помещающимися в кэш,

минимизирует случайные переходы по памяти.

## Выводы

- Виртуальная память обеспечивает изоляцию и эффективное использование ресурсов.  
- Количество page faults зависит от локальности и стратегии загрузки страниц.  
- Буферизация критична для производительности I/O: большие буферы уменьшают системные накладные расходы.  
- Планировщик I/O значительно влияет на HDD, но почти не влияет на SSD.  
- Оптимизация памяти и ввода-вывода требует учёта кэширования, размера страниц и паттернов доступа.
