### 1. Почему VSZ намного больше RSS?

VSZ включает всю виртуальную память процесса (зарезервированную, разделяемые библиотеки, memory-mapped файлы), а RSS - только страницы в физической памяти. VSZ > RSS, потому что не вся зарезервированная память используется.

### 2. Где находятся разные типы памяти в адресном пространстве?

* Текст (код): низкие адреса
* Данные/Heap: после кода, растёт вверх
* Stack: высокие адреса, растёт вниз
* Библиотеки: средние адреса
* mmap-регионы: случайные адреса (ASLR)

### 3. Как изменился RSS при выделении 1 MB через malloc vs mmap?

При первом выделении оба метода увеличивают RSS только при реальном обращении к памяти (page faults). При активном использовании оба приводят к полному увеличению RSS на выделенный объем. Разница в механизмах управления, а не в потреблении памяти.

### **Виртуальная память:**

**Что такое виртуальная память и зачем она нужна?**
- Виртуальная память — это абстракция, которая предоставляет каждому процессу собственное изолированное адресное пространство, не зависящее от физической памяти. Она создаёт иллюзию, что процесс обладает всей доступной памятью системы.
- Основные цели:
* Изоляция процессов: Процессы не могут вмешиваться в память друг друга
* Расширение памяти: Возможность использовать больше памяти, чем есть физически (за счёт swap-раздела на диске)
* Упрощение управления памятью: Программа работает с линейным адресным пространством
* Безопасность: Разграничение прав доступа к различным областям памяти
**Чем отличаются VSZ, RSS, PSS, USS? Какая метрика наиболее точно показывает потребление памяти процессом?**
- **VSZ (Virtual Set Size)**: Вся виртуальная память, запрошенная процессом.
- **RSS (Resident Set Size)**: Физическая память, занятая процессом в данный момент (включая разделяемые библиотеки).
- **PSS (Proportional Set Size)**: RSS, но разделяемая память делится пропорционально количеству процессов, её использующих. Более точная метрика для оценки нагрузки на память.
- **USS (Unique Set Size)**: Память, уникальная для данного процесса (не разделяемая). Наиболее точно показывает реальное потребление памяти процессом.
- **Наиболее точная метрика**: **USS** показывает реальную эксклюзивную память процесса, а **PSS** лучше подходит для оценки общего влияния на систему, так как честно учитывает разделяемую память.

**Что такое страница, кадр, таблица страниц?**
- **Страница (Page)**: Фиксированный по размеру блок виртуальной памяти.
- **Кадр (Page Frame)**: Фиксированный по размеру блок физической памяти, в который может быть помещена страница.
- **Таблица страниц (Page Table)**: Структура данных в ядре, которая хранит mapping (соответствие) виртуальных страниц процесса физическим кадрам памяти или местам на диске (swap).

**Как работает MMU и TLB? Что происходит при промахе TLB?**
- **MMU (Memory Management Unit)**: Аппаратный компонент CPU, который преобразует виртуальные адреса в физические, используя таблицу страниц.
- **TLB (Translation Lookaside Buffer)**: Кеш внутри CPU для быстрого доступа к недавно использованным преобразованиям виртуальных адресов в физические.
- **При промахе TLB (TLB Miss)**: Процессору приходится выполнять "прогулку по таблице страниц" (page walk) — обращаться к таблице страниц в оперативной памяти, чтобы найти нужное соответствие. Это операция значительно медленнее.

**Что такое Copy-on-Write и где он применяется?**
- **Copy-on-Write (CoW, Копирование при записи)**: Механизм, при котором память, разделяемая между процессами (например, после `fork()`), не копируется физически до тех пор, пока один из процессов не попытается её изменить. В момент записи создаётся отдельная копия страницы для модифицирующего процесса.
- **Применение**: Системный вызов `fork()` для создания процессов, `mmap()` с флагом `MAP_PRIVATE` для отображения файлов.

### **Page Faults:**

**Чем отличается minor page fault от major page fault?**
- **Minor Page Fault (Малый сбой страницы)**: Происходит, когда запрошенная страница уже находится в оперативной памяти (например, в page cache), но ещё не привязана в таблице страниц текущего процесса. Обработка быстрая.
- **Major Page Fault (Большой сбой страницы)**: Происходит, когда запрошенной страницы нет в оперативной памяти, и её необходимо загрузить с диска (из swap или файла). Обработка очень медленная.

**Почему при первом обращении к malloc()-памяти происходит page fault?**
- `malloc()` выделяет виртуальную память (расширяет heap), но не выделяет физическую память сразу (ленивое выделение — demand paging). При первом обращении к выделенной области возникает page fault (чаще minor, если память обнуляется, то может быть major из-за необходимости выделить чистую страницу), и только тогда ядро выделяет физический кадр.

**Как уменьшить количество page faults?**
- Увеличить объем оперативной памяти.
- Использовать `mlock()` для закрепления критических страниц в памяти (предотвращает вытеснение в swap).
- Оптимизировать локальность данных (cache-friendly код).
- Предзагружать данные (`madvise()` с `MADV_WILLNEED`).

**Что такое demand paging и page replacement?**
- **Demand Paging (Подкачка по требованию)**: Стратегия, при которой страницы загружаются в физическую память только в момент первого обращения к ним (при page fault).
- **Page Replacement (Замена страниц)**: Алгоритм, который решает, какую страницу вытеснить из физической памяти, когда она заполнена и требуется место для новой страницы (например, LRU - Least Recently Used).

### **Memory Mapping:**

**Чем mmap() отличается от read()/write()? Когда mmap эффективнее?**
- **`read()/write()`**: Системные вызовы, которые копируют данные между буфером в пользовательском пространстве и кешем страниц (page cache) в ядре.
- **`mmap()`**: Отображает файл (или область файла) непосредственно в виртуальное адресное пространство процесса. Обращения к памяти автоматически становятся операциями с файлом.
- **`mmap` эффективнее** когда:
    - Производится много случайных чтений из большого файла.
    - Необходимо разделять данные между процессами.
    - В сценариях, где можно избежать лишнего копирования данных между пользовательским пространством и ядром.

**Что такое MAP_PRIVATE и MAP_SHARED? В чём разница?**
- **`MAP_SHARED`**: Изменения в отображённой памяти видны другим процессам, отобразившим тот же файл, и записываются обратно в файл.
- **`MAP_PRIVATE`**: Создаётся приватная копия при записи (Copy-on-Write). Изменения не видны другим процессам и не записываются в файл.

**Что произойдёт, если обратиться к памяти за пределами отображённого файла?**
- Возникнет **SIGSEGV (Segmentation Fault)**, так как попытка доступа к неотображённой виртуальной памяти является нарушением.

**Как работает page cache и зачем он нужен?**
- **Page Cache (Кеш страниц)**: Механизм в ядре, который кеширует страницы из файлов и блочных устройств в оперативной памяти.
- **Зачем нужен**: Для ускорения доступа к данным. Последующие чтения из файла, которые уже находятся в кеше, выполняются из памяти (без обращения к диску), что значительно быстрее. Запись также часто буферизируется в кеше.

### **Файловый I/O:**

**Зачем нужна буферизация? Какие уровни буферизации существуют?**
- **Зачем**: Чтобы сгладить разницу в скорости между быстрым CPU и медленным I/O, уменьшить количество системных вызовов и обращений к диску.
- **Уровни буферизации**:
    1. **Буферизация в пользовательском пространстве** (например, буфер стандартной библиотеки `stdio`).
    2. **Буферизация в ядре (Page Cache)**.

**Почему маленький размер буфера замедляет I/O?**
- Маленький буфер приводит к большому количеству системных вызовов (`read`/`write`) и переключений контекста между пользовательским режимом и ядром. Каждый системный вызов имеет накладные расходы.

**Что такое O_DIRECT и O_SYNC? Когда их использовать?**
- **`O_DIRECT`**: I/O обходит кеш страниц ядра. Данные передаются напрямую между пользовательским буфером и устройством. Используется для приложений, которые реализуют собственный кеш (например, СУБД).
- **`O_SYNC`**: Каждая операция записи блокирует процесс до тех пор, пока данные не будут физически записаны на диск. Обеспечивает целостность данных после возврата из `write()`, но очень медленный.
- **Использовать**: `O_DIRECT` — когда свой кеш эффективнее; `O_SYNC` — когда критична гарантия записи (журналирование, метаданные).

**Чем отличается fwrite() от write()?**
- **`write()`**: Системный вызов. Записывает данные из буфера в файловый дескриптор. Может буферизироваться на уровне ядра (в page cache), но не в пользовательском пространстве.
- **`fwrite()`**: Функция стандартной библиотеки C (`stdio`). Работает с указателем `FILE*`. Использует буфер в пользовательском пространстве, что уменьшает количество системных вызовов `write()`. Данные могут быть не записаны сразу, пока буфер не заполнится или не будет вызвана `fflush()`.

### **Файловая система:**

**Что такое inode и что в нём хранится?**
- **Inode (index node)** — это структура данных в файловой системе, которая хранит метаданные о файле (всё, кроме имени и собственно данных).
- **Хранится в inode**: Права доступа, владелец (UID/GID), размер файла, временные метки (atime, ctime, mtime), ссылки на блоки данных, на диске, где хранятся данные файла.

**Почему имя файла не хранится в inode?**
- Потому что одно и то же имя файла (жесткая ссылка) может быть связано с одним inode, и один inode может иметь несколько имён. Имена файлов хранятся в записях каталогов (directories), которые сами являются файлами, сопоставляющими имена файлов с номерами inode.

**Чем жёсткая ссылка отличается от символьной?**
- **Жёсткая ссылка (Hard Link)**: Дополнительное имя (запись в каталоге) для того же самого inode. Все жёсткие ссылки равнозначны. Нельзя создать для директории и на другую файловую систему. Удаление одной ссылки не затрагивает другие, пока есть хотя бы одна.
- **Символическая ссылка (Soft/Symbolic Link)**: Отдельный файл, который содержит путь к другому файлу. Имеет собственный inode. Может ссылаться на директории и файлы на других ФС. Если целевой файл удалён, симлинк становится "битым".

**Как в ext4 хранятся большие файлы (indirect pointers)?**
- Inode содержит 12 прямых указателей на блоки данных.
- Для больших файлов используются косвенные указатели:
    - **Одинарный косвенный указатель (1 indirect)**: Указывает на блок, который сам содержит указатели на блоки данных.
    - **Двойной косвенный указатель (2 indirect)**: Указывает на блок, содержащий указатели на блоки с одинарными косвенными указателями.
    - **Тройной косвенный указатель (3 indirect)**: Указывает на блок, содержащий указатели на блоки с двойными косвенными указателями.
- Эта многоуровневая схема позволяет адресовать очень большие файлы.

### **Дисковое планирование:**

**Зачем нужны I/O schedulers?**
- Чтобы упорядочить и оптимизировать запросы на ввод-вывод к диску. Они уменьшают время позиционирования головок HDD (объединяя соседние запросы и сортируя их) и обеспечивают справедливость между процессами.

**Чем отличаются FCFS, SSTF, SCAN?**
- **FCFS (First-Come, First-Served)**: Запросы обрабатываются в порядке поступления. Просто, но неэффективно для HDD.
- **SSTF (Shortest Seek Time First)**: Выбирается запрос, ближайший к текущему положению головки. Может приводить к "голоданию" запросов на краях диска.
- **SCAN ("Лифт")**: Головка движется от одного края диска к другому, обслуживая запросы по пути, затем разворачивается и движется обратно. Устраняет голодание.

**Какие I/O schedulers используются в современном Linux?**
- **BFQ (Budget Fair Queueing)**: Ориентирован на десктопы и интерактивные системы, обеспечивает справедливость и низкие задержки.
- **mq-deadline**: Простой и предсказуемый, хорошо подходит для SSD и систем, требующих детерминизма.
- **Kyber**: Разработан для быстрых устройств (SSD, NVMe), регулирует глубину очереди для управления задержками.
- **None (Noop)**: Простая FIFO-очередь, используется в основном для SSD, где механическое позиционирование не требуется.

**Почему для SSD планирование менее критично, чем для HDD?**
- У SSD нет механических движущихся частей. Время доступа ко всем ячейкам памяти практически одинаково (в отличие от времени позиционирования головки HDD). Поэтому сложные алгоритмы планирования, оптимизирующие перемещения, для SSD менее эффективны. Основная задача для SSD — равномерный износ (wear leveling) и управление параллелизмом, чем занимается собственный контроллер SSD.

### **Производительность:**

**Что такое фрагментация памяти? Внутренняя vs внешняя.**
- **Фрагментация** — ситуация, когда свободная память существует, но она разбита на маленькие несмежные куски, и её нельзя использовать для выделения большого блока.
- **Внутренняя фрагментация**: Происходит, когда процессу выделен блок памяти больше, чем ему нужно. Неиспользуемая память находится *внутри* выделенного блока. Характерна для систем с фиксированными размерами страниц.
- **Внешняя фрагментация**: Происходит, когда свободная память разбита на множество маленьких разрозненных участков между занятыми блоками. Характерна для систем с переменными размерами сегментов.

**Как swap влияет на производительность?**
- **Позитивно**: Позволяет системе работать, когда физической памяти не хватает, предотвращая аварийное завершение процессов.
- **Негативно**: При активном использовании swap (swapping) происходит интенсивный дисковый ввод-вывод, что сильно замедляет всю систему, так как доступ к диску на порядки медленнее, чем к RAM.

**Что такое thrashing и как его избежать?**
- **Thrashing (Пробуксовка)**: Ситуация, когда система тратит больше времени на подкачку страниц (page faults, swapping), чем на выполнение полезной работы. Происходит, когда сумма рабочего набора процессов значительно превышает доступную физическую память.
- **Как избежать**:
    - Увеличить объем оперативной памяти.
    - Уменьшить количество одновременно работающих процессов.
    - Использовать приоритеты и "вытеснять" менее важные процессы (через OOM killer или ручное управление).
    - Использовать `mlock()` для критических процессов.

**Почему последовательный доступ к памяти быстрее случайного?**
- Из-за **локальности ссылок** и аппаратных оптимизаций:
    - **Кеш процессора**: Последовательный доступ эффективно использует предварительную выборку (prefetching) данных в кеш.
    - **Страничная память**: Последовательный доступ к виртуальной памяти уменьшает количество TLB-промахов.
    - **Диски (HDD)**: Последовательное чтение/запись не требует механического перемещения головки, в отличие от случайных прыжков по диску.

**Что такое cache-friendly код?**
- Это код, написанный с учётом принципов локальности данных, чтобы максимально эффективно использовать кеш процессора.
- **Основные принципы**:
    - **Последовательный доступ**: Обработка данных в том порядке, в котором они расположены в памяти.
    - **Локальность по пространству**: Использование данных, находящихся близко друг к другу в памяти.
    - **Локальность по времени**: Повторное использование одних и тех же данных в короткий промежуток времени.
    - **Компактные структуры данных**: Уменьшение размера структур для помещения большего их количества в кеш.
