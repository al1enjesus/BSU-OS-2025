## Теоретическая часть

### Виртуальная память в Linux

**Виртуальная память** - это абстракция, которая предоставляет каждому процессу изолированное адресное пространство, не зависящее от физической памяти.

**Ключевые концепции:**

- **Страничная организация памяти** - память делится на страницы фиксированного размера (обычно 4 KB)
- **Таблица страниц** - структура данных для отображения виртуальных адресов в физические
- **MMU (Memory Management Unit)** - аппаратный блок для трансляции адресов
- **TLB (Translation Lookaside Buffer)** - кеш трансляций адресов

### Метрики памяти процесса

| Метрика | Описание | Особенности |
|---------|----------|-------------|
| **VSZ** | Virtual Size - полный размер виртуального адресного пространства | Включает все сегменты, даже неиспользуемые |
| **RSS** | Resident Set Size - память в физической RAM | Считает shared pages полностью для каждого процесса |
| **PSS** | Proportional Set Size - пропорциональная память | Делит shared pages между процессами |
| **USS** | Unique Set Size - уникальная память | Память, используемая только данным процессом |

### Страничные ошибки (Page Faults)

- **Minor Page Fault**: Страница находится в RAM, но не отображена в таблице страниц процесса
- **Major Page Fault**: Страницы нет в RAM, требуется загрузка с диска

### Буферизация I/O

**Уровни буферизации:**
1. **User-space буферы** (stdio) - буферизация на уровне библиотеки C
2. **Kernel page cache** - кеш страниц в ядре
3. **Disk cache** - кеш на уровне контроллера диска

## Практическая реализация

### 1. Memory Info Utility (`memory_info.c`)

```c
// Пример реализации различных типов памяти
void demonstrate_memory_types() {
    // Стек
    char stack_var[1024];
    memset(stack_var, 'S', sizeof(stack_var));
    
    // Куча (heap)
    char *heap_var = malloc(10 * 1024 * 1024);
    for (size_t i = 0; i < 10 * 1024 * 1024; i += 4096) {
        heap_var[i] = 'H';  // Вызов page faults
    }
    
    // Anonymous mmap
    void *mmap_var = mmap(NULL, 50 * 1024 * 1024, 
                         PROT_READ | PROT_WRITE,
                         MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    
    // File-backed mmap
    int fd = open("test_file.bin", O_RDWR | O_CREAT, 0644);
    ftruncate(fd, 5 * 1024 * 1024);
    void *file_mmap = mmap(NULL, 5 * 1024 * 1024, 
                          PROT_READ | PROT_WRITE, 
                          MAP_SHARED, fd, 0);
}
```

**Функциональность:**
- Чтение метрик из `/proc/[PID]/status`
- Парсинг карты памяти из `/proc/[PID]/maps`
- Визуализация различных регионов памяти
- Сравнение разных методов выделения памяти

### 2. I/O Benchmark Utility (`io_benchmark.c`)

```c
// Сравнение методов записи
double benchmark_fwrite(const char *filename, size_t size, size_t buffer_size) {
    FILE *f = fopen(filename, "wb");
    char *buffer = malloc(buffer_size);
    memset(buffer, 'A', buffer_size);
    
    double start = get_time();
    for (size_t written = 0; written < size; written += buffer_size) {
        size_t to_write = min(buffer_size, size - written);
        fwrite(buffer, 1, to_write, f);
    }
    double end = get_time();
    
    fclose(f);
    free(buffer);
    return end - start;
}
```

**Тестируемые методы:**
- `fwrite()` - буферизованный I/O через stdio
- `write()` - системные вызовы с разными размерами буфера
- `write()` с `O_SYNC` - синхронная запись
- `mmap()` - memory-mapped I/O

## Анализ и выводы

### Ключевые наблюдения

1. **Виртуальная vs Физическая память**
   - VSZ показывает зарезервированное виртуальное пространство, которое может значительно превышать реально используемую память (RSS)
   - PSS является наиболее точной метрикой для оценки реального потребления памяти системой
   - USS показывает, сколько памяти освободится при завершении процесса

2. **Эффективность буферизации**
   - Маленькие буферы (512B) крайне неэффективны из-за большого количества системных вызовов
   - Оптимальный размер буфера находится в диапазоне 64KB-1MB
   - Дальнейшее увеличение буфера не дает значительного прироста производительности
   - `fwrite()` с буферизацией на уровне stdio показывает сравнимую производительность с оптимально настроенным `write()`

3. **Влияние I/O планировщиков**
   - Для SSD планировщик `none` показывает наилучшие результаты
   - `mq-deadline` обеспечивает баланс между производительностью и fairness
   - `bfq` больше подходит для интерактивных workloads

4. **Практические рекомендации**
   - Для последовательного доступа использовать `write()` с буфером 64KB-1MB
   - Для случайного доступа к большим файлам предпочтительнее `mmap()`
   - Для интерактивных приложений использовать планировщик `bfq`
   - Для серверных нагрузок на SSD использовать `none` или `mq-deadline`

## Ответы на контрольные вопросы

### Виртуальная память

**1. Что такое виртуальная память и зачем она нужна?**

Виртуальная память - это абстракция, предоставляющая каждому процессу изолированное адресное пространство, независимое от физической памяти. Она нужна для:
- **Изоляции процессов** - процессы не могут мешать друг другу
- **Упрощения программирования** - программист работает с линейным адресным пространством
- **Эффективного использования RAM** - в памяти находятся только активные страницы
- **Поддержки разделяемой памяти** - несколько процессов могут использовать одни физические страницы

**2. Чем отличаются VSZ, RSS, PSS, USS?**

- **VSZ (Virtual Size)** - полный размер виртуального адресного пространства процесса
- **RSS (Resident Set Size)** - память, находящаяся в физической RAM в данный момент
- **PSS (Proportional Set Size)** - RSS с учетом разделяемых страниц (делится между процессами)
- **USS (Unique Set Size)** - память, используемая только данным процессом

**Наиболее точная метрика - PSS**, так как она учитывает разделение памяти между процессами.

**3. Что такое страница, кадр, таблица страниц?**

- **Страница (Page)** - блок виртуальной памяти фиксированного размера (обычно 4 KB)
- **Кадр (Frame)** - блок физической памяти того же размера, что и страница
- **Таблица страниц (Page Table)** - структура данных, отображающая виртуальные страницы на физические кадры

**4. Как работает MMU и TLB?**

- **MMU (Memory Management Unit)** - аппаратный блок процессора, выполняющий трансляцию виртуальных адресов в физические с использованием таблицы страниц
- **TLB (Translation Lookaside Buffer)** - кеш последних трансляций адресов, значительно ускоряющий доступ к памяти

При промахе TLB происходит обращение к таблице страниц, что требует дополнительных обращений к памяти.

**5. Что такое Copy-on-Write и где он применяется?**

**Copy-on-Write (CoW)** - оптимизационная техника, при которой копирование данных откладывается до момента фактической записи. Применяется:
- При вызове `fork()` - родитель и ребенок изначально используют одни страницы
- В `mmap()` с флагом `MAP_PRIVATE` - запись вызывает копирование страницы

### Page Faults

**6. Чем отличается minor page fault от major page fault?**

- **Minor Page Fault**: Страница находится в физической памяти, но не отображена в таблице страниц процесса. Быстрое разрешение (микросекунды)
- **Major Page Fault**: Страницы нет в физической памяти, требуется загрузка с диска. Медленное разрешение (миллисекунды)

**7. Почему при первом обращении к `malloc()`-памяти происходит page fault?**

`malloc()` выделяет виртуальную память, но физические страницы не выделяются до первого обращения (ленивое выделение). При первом доступе происходит minor page fault, и ядро выделяет физическую страницу.

**8. Как уменьшить количество page faults?**

- Использовать `calloc()` вместо `malloc()` + `memset()` (может использовать zero pages)
- Предварительное чтение данных (prefetching)
- Правильная работа с памятью (последовательный доступ вместо случайного)
- Использование больших страниц (hugepages)

**9. Что такое demand paging и page replacement?**

- **Demand Paging** - страницы загружаются в память только при обращении к ним
- **Page Replacement** - алгоритмы выбора страниц для вытеснения при нехватке памяти (LRU, Clock и др.)

### Memory Mapping

**10. Чем `mmap()` отличается от `read()`/`write()`?**

- `read()/write()`: копирование данных между kernel space и user space
- `mmap()`: прямое отображение файла в виртуальную память, работа с данными как с массивом

`mmap()` эффективнее для:
- Больших файлов
- Случайного доступа
- Разделяемой памяти между процессами

**11. Что такое MAP_PRIVATE и MAP_SHARED?**

- **MAP_PRIVATE**: Изменения видны только текущему процессу (Copy-on-Write)
- **MAP_SHARED**: Изменения видны всем процессам, отображающим файл, и записываются в файл

**12. Что произойдёт, если обратиться к памяти за пределами отображённого файла?**

Произойдет ошибка Segmentation Fault (SIGSEGV) или Bus Error (SIGBUS), в зависимости от ситуации.

**13. Как работает page cache и зачем он нужен?**

Page cache - кеш страниц в ядре для ускорения доступа к файлам. При чтении файла данные кешируются в памяти, последующие чтения выполняются из кеша.

### Файловый I/O

**14. Зачем нужна буферизация?**

Буферизация уменьшает количество системных вызовов и оптимизирует доступ к диску. Уровни буферизации:
- User-space буферы (stdio)
- Kernel page cache  
- Disk controller cache

**15. Почему маленький размер буфера замедляет I/O?**

Маленькие буферы приводят к большому количеству системных вызовов, что создает значительные накладные расходы.

**16. Что такое O_DIRECT и O_SYNC?**

- **O_DIRECT**: Прямой I/O, минуя page cache ядра
- **O_SYNC**: Синхронная запись - данные записываются на диск перед возвратом из write()

Используются в базах данных и приложениях, требующих гарантий записи.

**17. Чем отличается `fwrite()` от `write()`?**

- `fwrite()`: буферизованный I/O на уровне библиотеки C
- `write()`: непосредственный системный вызов

`fwrite()` может быть быстрее для маленьких записей благодаря буферизации.

### Файловая система

**18. Что такое inode и что в нём хранится?**

Inode (index node) - структура данных, содержащая метаданные файла:
- Тип файла и права доступа
- Владелец и группа
- Размер файла
- Временные метки (atime, mtime, ctime)
- Указатели на блоки данных

**19. Почему имя файла не хранится в inode?**

Имя файла хранится в директории, что позволяет:
- Поддержку жестких ссылок (несколько имен для одного inode)
- Эффективный поиск файлов в директориях

**20. Чем жёсткая ссылка отличается от символьной?**

- **Жесткая ссылка**: Дополнительное имя для существующего inode
- **Символьная ссылка**: Отдельный файл, содержащий путь к целевому файлу

**21. Как в ext4 хранятся большие файлы?**

В ext4 используется многоуровневая система указателей:
- 12 прямых указателей
- 1 косвенный указатель
- 1 двойной косвенный указатель  
- 1 тройной косвенный указатель

### Дисковое планирование

**22. Зачем нужны I/O schedulers?**

I/O schedulers оптимизируют порядок обработки запросов к диску для:
- Увеличения пропускной способности
- Уменьшения времени ожидания
- Справедливого распределения ресурсов

**23. Чем отличаются FCFS, SSTF, SCAN?**

- **FCFS (First Come First Served)**: В порядке поступления
- **SSTF (Shortest Seek Time First)**: Ближайший запрос к текущей позиции
- **SCAN (Elevator)**: Движение в одном направлении с обслуживанием всех запросов на пути

**24. Какие I/O schedulers используются в современном Linux?**

- **mq-deadline**: Deadline-based для гарантированного времени обслуживания
- **bfq**: Budget Fair Queueing для интерактивных workloads
- **kyber**: Для NVMe SSD
- **none**: Без планирования для быстрых устройств

**25. Почему для SSD планирование менее критично, чем для HDD?**

SSD не имеют механических частей, поэтому:
- Нет задержек на позиционирование головки
- Параллельный доступ к нескольким ячейкам
- Более равномерное время доступа

### Производительность

**26. Что такое фрагментация памяти?**

- **Внутренняя фрагментация**: Неиспользуемая память внутри выделенного блока
- **Внешняя фрагментация**: Свободная память разбита на маленькие несмежные блоки

**27. Как swap влияет на производительность?**

Swap позволяет работать с большими объемами данных, но при активном использовании (swapping) приводит к значительному замедлению из-за дисковых операций.

**28. Что такое thrashing и как его избежать?**

Thrashing - ситуация, когда система тратит больше времени на подкачку страниц, чем на полезную работу. Способы избежания:
- Увеличение объема RAM
- Оптимизация алгоритмов работы с памятью
- Использование mlock() для критических страниц

**29. Почему последовательный доступ к памяти быстрее случайного?**

- **Кеширование**: Последовательный доступ эффективнее использует кеш-память
- **Prefetching**: Процессор может предсказать последовательный доступ
- **Локальность ссылок**: Улучшает использование TLB и кешей

**30. Что такое cache-friendly код?**

Код, эффективно использующий иерархию памяти:
- Последовательный доступ к данным
- Локализация данных в памяти
- Минимизация указателей и случайных доступов
- Правильное выравнивание данных
