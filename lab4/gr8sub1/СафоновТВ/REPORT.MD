### Описание

**Memory Profiler** - это утилита для детального анализа использования памяти процессами в Linux. Программа предоставляет подробную информацию о виртуальной и физической памяти, page faults, карте памяти и позволяет мониторить изменения в реальном времени. Memory Profiler представляет собой многофункциональную утилиту для глубокого анализа использования памяти процессами в операционной системе Linux. Одной из её ключевых возможностей является комплексный анализ метрик памяти, включая отслеживание виртуального размера процесса (VSZ), резидентного набора памяти (RSS), пропорционального размера с учётом разделяемой памяти (PSS) и уникального размера процесса (USS), что обеспечивает полную картину использования системных ресурсов. Программа предоставляет детальную статистику с классификацией памяти на разделяемую и приватную, а также на чистую и изменённую, позволяя выявлять структурные особенности распределения памяти. Важной функцией является мониторинг page faults, отслеживающий как незначительные нарушения, возникающие при отсутствии страницы в таблице страниц процесса, так и основные, требующие загрузки данных с диска. Утилита также включает визуализацию карты памяти, отображающую распределение сегментов по различным областям - куче, стеку, библиотекам и анонимной памяти, что помогает анализировать структуру адресного пространства. Режим динамического мониторинга позволяет отслеживать изменения использования памяти в реальном времени, а функция сравнения процессов даёт возможность проводить сравнительный анализ двух процессов для выявления различий в их поведении и потреблении ресурсов.

    ./bin/memory_profiler <PID> [options]

Options:
  --watch [interval]     Monitor process continuously (default: 1 sec)
  --compare <PID2>       Compare two processes
  --map                  Show detailed memory map

## Ответы на вопросы
## Виртуальная память

1. Что такое виртуальная память и зачем она нужна?
Это абстракция, которая предоставляет каждому процессу его собственное изолированное адресное пространство (обычно 4 ГБ на 32-битных системах), не зависящее от физической памяти.

    Зачем нужна:

        Изоляция процессов: Процесс не может повредить память другого процесса.

        Безопасность: Контроль доступа к памяти (read/write/execute).

        Упрощение программирования: Программа "видит" непрерывное адресное пространство, даже если физическая память фрагментирована.

        Расширение памяти: Возможность использовать часть диска (swap) для хранения неиспользуемых страниц, что позволяет запускать программы, требующие больше памяти, чем есть физически.

2. Чем отличаются VSZ, RSS, PSS, USS? Какая метрика наиболее точно показывает потребление памяти процессом?

    VSZ (Virtual Set Size): Вся виртуальная память, которую запросил процесс (библиотеки, отображённые файлы, стек, куча). Сильно завышает оценку.

    RSS (Resident Set Size): Физическая память (RAM), которая реально выделена процессу в данный момент. Недостаток: общая память (например, библиотеки) считается для каждого процесса, что ведёт к двойному счёту.

    PSS (Proportional Set Size): Исправляет недостаток RSS. Память, разделяемая между процессами (библиотеки), делится на количество процессов, которые её используют. Лучшая метрика для оценки "грузности" процесса в системе.

    USS (Unique Set Size): Память, уникальная для данного процесса (его куча, стек). Наиболее точная метрика для определения, сколько памяти освободится, если процесс убить.

3. Что такое страница, кадр, таблица страниц?

    Страница (Page): Фиксированный по размеру блок виртуальной памяти (обычно 4 КБ).

    Кадр (Page Frame): Фиксированный по размеру блок физической памяти, куда может быть помещена страница. Размер кадра равен размеру страницы.

    Таблица страниц (Page Table): Структура данных в ядре, которая преобразует виртуальные адреса в физические. Каждая запись (PTE - Page Table Entry) содержит флаги (доступна, только для чтения, etc.) и номер кадра физической памяти.

4. Как работает MMU и TLB? Что происходит при промахе TLB?

    MMU (Memory Management Unit): Аппаратный блок внутри CPU, который занимается преобразованием виртуальных адресов в физические, используя таблицы страниц, подготовленные ядром.

    TLB (Translation Lookaside Buffer): Кеш внутри MMU для результатов трансляции адресов (виртуальный адрес -> физический адрес). Обращение к TLB происходит очень быстро.

    Промах TLB (TLB Miss): Когда MMU не находит трансляции для виртуального адреса в TLB.

        MMU генерирует исключение (page fault исключение, но не связанное с отсутствием страницы в памяти).

        Управление передаётся обработчику в ядре.

        Ядро "проходит" по таблице страниц и находит нужную запись (Page Walk).

        Найденная трансляция заносится в TLB.

        Выполнение инструкции возобновляется.
        Это дорогая, но не катастрофическая операция.

5. Что такое Copy-on-Write и где он применяется?

    Copy-on-Write (CoW): Оптимизационная стратегия, при которой несколько процессов-потомков изначально разделяют одни и те же страницы памяти родителя. Реальное копирование страницы происходит только тогда, когда один из процессов пытается её изменить.

    Применение: Системный вызов fork(). При вызове fork() не происходит копирования всей памяти, что делает его очень быстрым. Копирование происходит только при записи, экономя память и время.

## Page Faults

1. Чем отличается minor page fault от major page fault?

    Minor Page Fault: Запрошенная страница уже находится в оперативной памяти (например, в Page Cache), но отсутствует в таблице страниц текущего процесса. Это быстрое исправление (просто добавить запись в таблицу страниц).

    Major Page Fault: Запрошенной страницы нет в оперативной памяти. Требуется загрузить её с диска (из swap или файла). Это очень медленная операция.

2. Почему при первом обращении к malloc()-памяти происходит page fault?
malloc() выделяет память виртуально (меняет кучу процесса), но не выделяет физические страницы. Физическая страница выделяется ядром только при первом обращении (чтении или записи) по этому адресу. Это и вызывает minor page fault.

3. Как уменьшить количество page faults?

    Увеличить объем оперативной памяти.

    Использовать mlock() для фиксации критических страниц в памяти (запрет вытеснения в swap).

    Оптимизировать алгоритмы для улучшения локальности данных (locality of reference).

    Использовать большие страницы (HugePages).

4. Что такое demand paging и page replacement?

    Demand Paging (Подкачка по требованию): Стратегия, при которой страницы загружаются в физическую память только при первом обращении к ним (при page fault), а не все сразу при запуске программы.

    Page Replacement (Алгоритмы замещения страниц): Когда физическая память заполнена, а нужно загрузить новую страницу, ядро должно выбрать "жертву" — страницу для вытеснения. Примеры алгоритмов: LRU (Least Recently Used), Clock.

## Memory Mapping

1. Чем mmap() отличается от read()/write()? Когда mmap эффективнее?

    read()/write(): Системные вызовы, требующие явного копирования данных между буфером в пользовательском пространстве и кешем страниц (Page Cache) в ядре.

    mmap(): Отображает файл (или его часть) прямо в виртуальное адресное пространство процесса. Обращение к данным происходит напрямую, как к памяти, а подкачка данных из файла осуществляется ядром прозрачно через Page Faults.

    mmap эффективнее, когда:

        Производится много случайных доступов к файлу.

        Необходимо разделять данные между процессами.

        mmap избегает лишнего копирования данных из ядра в пользовательское пространство.

2. Что такое MAP_PRIVATE и MAP_SHARED? В чём разница?

    MAP_SHARED: Изменения в отображённой памяти видны другим процессам, отобразившим тот же файл, и записываются обратно в файл.

    MAP_PRIVATE: Создаётся приватная копия при записи (Copy-on-Write). Изменения не видны другим процессам и не записываются в файл. Идеально для загрузки исполняемых файлов и библиотек.

3. Что произойдёт, если обратиться к памяти за пределами отображённого файла?
Произойдёт segmentation fault (SIGSEGV), так как виртуальный адрес валиден, но ему не соответствует никакая физическая страница (или файл на задёре).

4. Как работает page cache и зачем он нужен?
Page Cache — это кеш в оперативной памяти для данных с диска (файлов, блоков). При чтении из файла данные кешируются в Page Cache. Последующие чтения (из любого процесса) будут обслуживаться из RAM, что многократно быстрее. Запись в файл также часто буферизуется в Page Cache перед отложенной записью на диск.

## Файловый I/O

1. Зачем нужна буферизация? Какие уровни буферизации существуют?

    Зачем: Сгладить разницу в скорости между быстрым CPU и медленным I/O, уменьшить количество системных вызовов и обращений к диску.

    Уровни:

        Буфер в пользовательском пространстве: (например, буфер стандартной библиотеки C stdio).

        Page Cache (Кеш страниц ядра): Общий кеш для файловых операций.

        Буферы контроллера диска (Hardware cache).

2. Почему маленький размер буфера замедляет I/O?
Увеличивает количество системных вызовов (read/write) и операций позиционирования (seek) на диске. Каждый системной вызов — это переключение контекста (user->kernel->user), что дорого.

3. Что такое O_DIRECT и O_SYNC? Когда их использовать?

    O_DIRECT: I/O обходит Page Cache ядра. Данные передаются напрямую между буфером пользователя и диском. Используется СУБД (например, PostgreSQL, MySQL), которые сами управляют кешированием.

    O_SYNC: Каждая операция записи write() блокирует процесс до тех пор, пока данные не будут физически записаны на диск. Гарантирует сохранность данных, но очень медленно.

4. Чем отличается fwrite() от write()?

    write(): Системный вызов. Низкоуровневый, записывает данные из буфера в дескриптор файла. Может быть небуферизированным или буферизированным на уровне ядра (Page Cache).

    fwrite(): Функция стандартной библиотеки C (stdio). Работает с FILE*. Обычно буферизируется в пользовательском пространстве. Несколько мелких fwrite() могут быть объединены в один системный вызов write(), что эффективнее.

## Файловая система

1. Что такое inode и что в нём хранится?
inode (index node) — это структура данных на диске, описывающая файл (кроме его имени). Хранит:

    Тип файла (регулярный, каталог, символьная ссылка...)

    Права доступа (permissions)

    ID владельца и группы

    Размер файла

    Временные метки (atime, ctime, mtime)

    Ссылки на блоки данных, где хранится содержимое файла.

2. Почему имя файла не хранится в inode?
Чтобы реализовать жёсткие ссылки (hard links). Одно и то же содержимое (один inode) может иметь несколько имён в разных (или одном) каталогах. Имена файлов хранятся в записях каталогов, которые представляют собой таблицы "имя файла -> inode".

3. Чем жёсткая ссылка отличается от символьной?

    Жёсткая ссылка (Hard Link): Ещё одна запись в каталоге, указывающая на тот же inode. Неотличима от "оригинального" файла. Работает только в пределах одной файловой системы. Удаление "оригинала" не влияет на жёсткую ссылку.

    Символьная (Мягкая) ссылка (Symbolic / Soft Link): Отдельный файл специального типа, который содержит путь к целевому файлу. Аналогична ярлыку в Windows. Работает между ФС. При удалении целевого файла становится "битой".

4. Как в ext4 хранятся большие файлы (indirect pointers)?
Используется древовидная структура:

    Прямые блоки (Direct Blocks): В inode хранятся прямые указатели на первые ~12 блоков данных.

    Одинарный косвенный блок (Single Indirect Block): Указатель на блок, который сам содержит указатели на блоки данных.

    Двойной косвенный блок (Double Indirect Block): Указатель на блок, указывающий на блоки с одинарными косвенными указателями.

    Тройной косвенный блок (Triple Indirect Block): И так далее. Это позволяет адресовать огромные файлы.

Дисковое планирование

1. Зачем нужны I/O schedulers?
Чтобы упорядочить запросы на I/O, приходящие от процессов, в последовательность, оптимальную для работы накопителя (в первую очередь, для HDD), минимизируя время позиционирования головок.

2. Чем отличаются FCFS, SSTF, SCAN?

    FCFS (First-Come, First-Served): В порядке поступления. Просто, но неэффективно (сильная фрагментация доступа).

    SSTF (Shortest Seek Time First): Выбирает запрос, ближайший к текущему положению головки. Может привести к "голоданию" запросов на краях диска.

    SCAN ("Лифт"): Головка движется от одного края диска к другому, обслуживая запросы по пути, затем разворачивается и движется обратно. Справедливее SSTF.

3. Какие I/O schedulers используются в современном Linux?

    Для HDD (mq-deadline, bfq):

        mq-deadline: Гарантирует, что запрос не будет ждать дольше заданного времени, балансируя между пропускной способностью и задержкой.

        BFQ (Budget Fair Queuing): Продвинутый планировщик, обеспечивающий справедливое распределение пропускной способности между процессами. Хорош для интерактивных систем и десктопов.

    Для SSD (чаще none или kyber):

        none: Отключает планировщик, так как для SSD нет механического задержка на позиционирование.

        kyber: Легковесный планировщик, который в основном следит за задержками (latency).

4. Почему для SSD планирование менее критично, чем для HDD?
У SSD нет движущихся частей. Время доступа к любой ячейке памяти примерно одинаково (хотя есть нюансы с параллелизмом и выравниванием износа). Поэтому сложные алгоритмы, оптимизирующие перемещение головки, для SSD не нужны и даже могут быть вредны из-за лишней задержки на логику планировщика.
Производительность

1. Что такое фрагментация памяти? Внутренняя vs внешняя.

    Фрагментация: Невозможность использовать свободную память из-за её раздробленности на маленькие кусочки.

    Внутренняя фрагментация: Когда процессу выделен блок памяти больше, чем он запросил. Разница пропадает впустую внутри выделенного блока. (Пример: выделение памяти страницами по 4КБ).

    Внешняя фрагментация: Свободная память разбита на множество маленьких разрозненных блоков, и хотя общий объём свободной памяти достаточен, нельзя удовлетворить запрос на один большой непрерывный блок.

2. Как swap влияет на производительность?

    Позитивно: Позволяет системе работать, когда физической памяти не хватает, выгружая неактивные страницы на диск.

    Негативно (сильно!): Если системе постоянно не хватает RAM ("memory pressure"), она тратит почти всё время на обмен страницами с диском (swapping). Это приводит к лавинообразному падению производительности (см. Thrashing). Доступ к диску на порядки медленнее RAM.

3. Что такое thrashing и как его избежать?

    Thrashing (Пробуксовка): Ситуация, когда система тратит больше времени на подкачку страниц (swapping/paging), чем на выполнение полезной работы. Происходит, когда слишком много активных процессов конкурируют за недостаточный объём физической памяти.

    Как избежать:

        Увеличить объем RAM.

        Уменьшить количество одновременно работающих процессов.

        Использовать более агрессивные алгоритмы убийства процессов (OOM Killer).

        Настроить параметры swappiness (vm.swappiness).

4. Почему последовательный доступ к памяти быстрее случайного?
Из-за принципов работы подсистемы памяти:

    Предвыборка (Prefetcher): Предсказывает последовательный доступ и заранее подгружает следующие кэш-линии в кеш CPU.

    Локальность (Locality): Последовательный доступ эффективно использует кеш.

    Аппаратная архитектура: Чтение из RAM происходит блоками (cache lines, обычно 64 байта). При последовательном доступе следующий элемент, скорее всего, уже в кеше.

5. Что такое cache-friendly код?
Это код, написанный так, чтобы максимально эффективно использовать кеш процессора.

    Принципы:

        Последовательный доступ: Обход массивов по порядку.

        Локальность данных: Расположение часто используемых данных близко друг к другу в памяти (например, в одном классе/структуре).

        Компактность структур: Уменьшение размера структур данных для помещения большего их количества в кеш.

        Избегание "разрывов" ссылок (pointer chasing): Когда для доступа к данным нужно пройти по цепочке указателей в разных участках памяти, что приводит к промахам кеша.
