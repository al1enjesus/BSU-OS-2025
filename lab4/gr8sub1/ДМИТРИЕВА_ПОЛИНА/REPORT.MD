## Ответы на теоретические вопросы

### Виртуальная память

**1. Что такое виртуальная память и зачем она нужна?**
Виртуальная память - это абстракция, позволяющая каждому процессу иметь изолированное адресное пространство. Преимущества:
- **Изоляция процессов** - процессы не могут вмешиваться в память друг друга
- **Упрощение программирования** - линейное адресное пространство
- **Эффективное использование RAM** - demand paging
- **Разделяемая память** - библиотеки, Copy-on-Write

**2. Чем отличаются VSZ, RSS, PSS, USS?**
- **VSZ (Virtual Size):** Полный размер виртуального адресного пространства
- **RSS (Resident Set Size):** Физическая память в RAM (включает разделяемую)
- **PSS (Proportional Set Size):** RSS с учётом доли разделяемой памяти
- **USS (Unique Set Size):** Уникальная (приватная) память процесса

**Наиболее точная метрика:** PSS, так как корректно учитывает разделяемую память.

**3. Что такое страница, кадр, таблица страниц?**
- **Страница:** Единица виртуальной памяти фиксированного размера (обычно 4 KB)
- **Кадр:** Единица физической памяти того же размера
- **Таблица страниц:** Структура данных, хранящая соответствие виртуальных страниц физическим кадрам

**4. Как работает MMU и TLB?**
- **MMU (Memory Management Unit):** Аппаратный блок процессора, выполняющий трансляцию виртуальных адресов в физические
- **TLB (Translation Lookaside Buffer):** Кеш трансляций для ускорения доступа к памяти
- **При промахе TLB:** Происходит поиск в таблице страниц, что требует дополнительных обращений к памяти

**5. Что такое Copy-on-Write?**
Механизм, при котором после fork() родитель и потомок изначально используют одни физические страницы, а копирование происходит только при попытке записи. Экономит память и ускоряет создание процессов.

### Page Faults

**6. Чем отличается minor page fault от major page fault?**
- **Minor:** Страница есть в RAM, но не в таблице страниц процесса (быстрое разрешение)
- **Major:** Страницы нет в RAM, нужно загружать с диска (медленно)

**7. Почему при первом обращении к malloc()-памяти происходит page fault?**
`malloc()` выделяет виртуальную память, но физические страницы выделяются только при первом обращении (demand paging).

**8. Как уменьшить количество page faults?**
- Использовать большие страницы (hugepages)
- Предварительная загрузка данных (prefetching)
- Оптимизация паттернов доступа (локальность)
- Использование madvise() для подсказок ядру

**9. Что такое demand paging и page replacement?**
- **Demand paging:** Страницы загружаются в память только при обращении
- **Page replacement:** Алгоритмы вытеснения страниц при нехватке памяти (LRU, Clock)

### Memory Mapping

**10. Чем mmap() отличается от read()/write()?**
- `mmap()`: Отображает файл в память, позволяет работать с данными как с массивом
- `read()/write()`: Традиционные системные вызовы с буферизацией

**mmap эффективнее для:**
- Больших файлов
- Случайного доступа
- Когда несколько процессов работают с одним файлом

**11. MAP_PRIVATE vs MAP_SHARED**
- **MAP_PRIVATE:** Изменения видны только текущему процессу (Copy-on-Write)
- **MAP_SHARED:** Изменения видны всем процессам и записываются в файл

**12. Что произойдёт, если обратиться к памяти за пределами отображённого файла?**
Вызывает сигнал SIGSEGV (segmentation fault).

### Файловый I/O

**13. Как работает page cache?**
Кеш страниц в ядре для ускорения дискового I/O. При чтении данные сначала загружаются в page cache, при записи данные сначала попадают в cache (dirty pages).

**14. Зачем нужна буферизация?**
- Уменьшение количества системных вызовов
- Оптимизация доступа к диску
- Выравнивание операций записи

**Уровни буферизации:**
- User-space (stdio)
- Kernel page cache
- Disk controller cache

**15. Почему маленький размер буфера замедляет I/O?**
Увеличивает количество системных вызовов и накладные расходы на переключение контекста.

4. **Page faults** являются неотъемлемой частью работы виртуальной памяти, и их количество зависит от паттернов доступа и размера рабочего набора.
