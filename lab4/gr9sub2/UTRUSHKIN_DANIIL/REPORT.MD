### Ответы на вопросы

**Почему VSZ намного больше RSS?**
VSZ включает всю виртуальную память процесса (код, данные, библиотеки, зарезервированные области), тогда как RSS показывает только ту часть, которая реально находится в физической памяти.

**Где находятся разные типы памяти?**
- **Код программы**: в сегментах с правами r-xp (read, execute)
- **Данные**: в сегментах с правами rw-p (read, write)  
- **Куча (heap)**: в области `[heap]` с правами rw-p
- **mmap**: в анонимных областях с правами rw-p
- **Стек**: обычно в высоких адресах (не показан в первых 20 строках)

**Как изменился RSS при выделении 1 MB через malloc vs mmap?**
Оба способа увеличили RSS примерно одинаково, так как при первом доступе к памяти происходят page faults и физические страницы выделяются в RAM.

## Задание B: Memory Mapping vs Read/Write

### Цель
Сравнить производительность mmap() и read().

### Результаты выполнения

#### Первый запуск (холодный кеш):

read(): 0.008 секунд
mmap(): 0.011 секунд
text


#### Второй запуск (теплый кеш):

read(): 0.014 секунд
mmap(): 0.010 секунд
text


#### Анализ:
- При холодном кеше **read() быстрее** на 27%
- При теплом кеше **mmap() быстрее** на 29%
- Оба метода дают одинаковый результат (суммы байтов совпадают)
- **mmap() эффективнее** при повторном доступе благодаря прямому отображению в page cache

### Вывод
mmap() показывает лучшую производительность при работе с файлами в условиях теплого кеша, что делает его предпочтительным для приложений, многократно работающих с одними и теми же файлами.

### Анализ:

- **Последовательный доступ**: вызвал 5 minor faults (обращение к новым страницам)
- **Случайный доступ**: вызвал 1 minor fault (обращение к ранее неиспользуемым страницам)
- **Повторный доступ**: не вызвал faults (все страницы уже в памяти)
- **Major faults**: 0 (не было обращения к swap)

### Ответы на вопросы

**Почему при последовательном доступе больше page faults?**
Последовательный доступ затрагивает все страницы выделенной памяти, тогда как случайный доступ затрагивает только часть страниц.

**Почему major faults отсутствуют?**
Программа работает в пределах доступной физической памяти, все данные помещаются в RAM без необходимости использования swap.

**Как изменится поведение при повторном запуске?**
Количество faults уменьшится, так как страницы могут остаться в page cache.

Ответы на теоретические вопросы
Виртуальная память:

Что такое виртуальная память и зачем она нужна?
Виртуальная память - это абстракция, позволяющая каждому процессу иметь собственное изолированное адресное пространство. Нужна для изоляции процессов, упрощения программирования и эффективного использования RAM.

Чем отличаются VSZ, RSS, PSS, USS?

    VSZ - весь виртуальный размер

    RSS - физическая память в RAM (может включать дублирование)

    PSS - пропорциональная память (разделяемая делится между процессами)

    USS - уникальная память процесса

Page Faults:

Чем отличается minor page fault от major page fault?

    Minor fault - страница есть в RAM, но не в таблице страниц процесса (быстро)

    Major fault - страницы нет в RAM, нужно загружать с диска (медленно)

Почему при первом обращении к malloc()-памяти происходит page fault?
Потому что физические страницы выделяются лениво (demand paging) - только при первом обращении.
Memory Mapping:

Чем mmap() отличается от read()/write()?
mmap() отображает файл прямо в адресное пространство процесса, избегая копирования между kernel и user space.

Когда mmap эффективнее?
При работе с большими файлами, особенно при случайном доступе или многократном использовании.
Файловый I/O:

Зачем нужна буферизация?
Для уменьшения количества системных вызовов и оптимизации работы с диском.

Что такое O_DIRECT?
Прямой I/O, обходящий page cache ядра. Используется когда приложение само управляет кешированием.
