## Ответы на вопросы задания A

### 1. Почему VSZ намного больше RSS?

**VSZ (Virtual Size)** — это весь объём виртуальной памяти, который процесс зарезервировал для себя. Сюда входят:
- Код программы
- Данные (инициализированные и неинициализированные)
- Куча (heap)
- Стек (stack) 
- Разделяемые библиотеки
- Memory-mapped файлы
- Неиспользуемые зарезервированные области

**RSS (Resident Set Size)** — это только те страницы, которые в данный момент находятся в физической памяти.

**Причины различия:**
- Не все зарезервированные страницы находятся в физической памяти
- Многие страницы могут быть еще не затронуты (не инициализированы)
- Часть страниц может быть вытеснена в swap
- Ленивое выделение памяти (demand paging)

**Пример из эксперимента:**
После malloc(1MB): 
- VSZ: 2680 kB → 3708 kB (+1028 kB) // Виртуальная память зарезервирована
- RSS: 1564 kB → 1564 kB (+0 kB) // Физическая память не выделена

## 3. Как изменился RSS при выделении 1 MB через malloc vs mmap?

### Сравнительная таблица:

| Метод выделения | Изменение VSZ | Изменение RSS | Причина |
|-----------------|---------------|---------------|---------|
| **malloc(1MB)** | +1028 kB | +0 kB | Ленивое выделение памяти |
| **mmap(1MB) + полная инициализация** | +1024 kB | +1024 kB | Немедленное выделение |

### Детальный анализ:

#### malloc(1MB)
```
Исходное состояние: RSS = 1564 kB
После malloc(1MB): RSS = 1564 kB
Изменение: +0 kB
```
**Причина:** `malloc()` только резервирует виртуальную память. Физическая память выделяется "лениво" при первом обращении к страницам.

```c
char* ptr = malloc(1024 * 1024);  // RSS не меняется
ptr[0] = 'A';                     // Теперь RSS +4KB (одна страница)
```
#### mmap(1MB) + полная инициализация
```
Исходное состояние: RSS = 1564 kB  
После mmap + инициализация: RSS = 2588 kB
Изменение: +1024 kB
```
**Причина**: При полной инициализации mmap-памяти система сразу выделяет физические страницы для всего объёма.
```c
char* ptr = mmap(..., 1024 * 1024, ...);
for (int i = 0; i < 1024 * 1024; i++) {
    ptr[i] = 'B';  // Инициализируем ВСЕ страницы
}
// RSS увеличивается на весь 1MB
```

## Memory Profiler

### Цель работы
Разработка утилиты для комплексного анализа памяти процессов в операционной системе Linux, обеспечивающей мониторинг метрик памяти, визуализацию карты памяти и динамическое отслеживание изменений.

### Выполненные требования

#### Минимальные требования

**1. Метрики памяти:**
- VSZ (Virtual Size) - виртуальный размер памяти
- RSS (Resident Set Size) - резидентный набор страниц
- PSS (Proportional Set Size) - пропорциональный размер памяти
- USS (Unique Set Size) - уникальная память процесса
- Shared vs Private память - разделяемая и приватная память
- Page faults (minor/major) - мягкие и жесткие ошибки страниц

**2. Карта памяти:**
- Визуализация сегментов из `/proc/[PID]/maps`
- Группировка регионов: heap, stack, libraries, anonymous
- Классификация типов памяти с подсчетом суммарных размеров

# Ответы на вопросы

## Виртуальная память

### 1. Что такое виртуальная память и зачем она нужна?
**Виртуальная память** - это механизм управления памятью, который предоставляет каждому процессу собственное изолированное адресное пространство, не зависящее от физической памяти.

**Зачем нужна:**
- **Изоляция процессов** - процессы не могут вмешиваться в память друг друга
- **Упрощение программирования** - программист работает с линейным адресным пространством
- **Эффективное использование RAM** - только активные страницы находятся в физической памяти
- **Разделяемая память** - возможность совместного использования библиотек и данных
- **Overcommit** - выделение больше виртуальной памяти, чем есть физической

### 2. Чем отличаются VSZ, RSS, PSS, USS? Какая метрика наиболее точно показывает потребление памяти процессом?

| Метрика | Описание | Что включает |
|---------|----------|--------------|
| **VSZ** | Virtual Size | Всю виртуальную память процесса (код, данные, библиотеки, mmap) |
| **RSS** | Resident Set Size | Физическую память в RAM (может дублировать разделяемую память) |
| **PSS** | Proportional Set Size | RSS с делением разделяемой памяти между процессами |
| **USS** | Unique Set Size | Только приватную (уникальную) память процесса |

**Наиболее точная метрика: PSS** - она учитывает разделяемую память и показывает реальную "стоимость" процесса в системе.

### 3. Что такое страница, кадр, таблица страниц?

- **Страница (Page)** - блок виртуальной памяти фиксированного размера (обычно 4 KB)
- **Кадр (Frame)** - блок физической памяти того же размера, что и страница
- **Таблица страниц (Page Table)** - структура данных, отображающая виртуальные страницы на физические кадры + флаги доступа

### 4. Как работает MMU и TLB? Что происходит при промахе TLB?

**MMU (Memory Management Unit)** - аппаратный блок процессора, выполняющий трансляцию виртуальных адресов в физические с использованием таблицы страниц.

**TLB (Translation Lookaside Buffer)** - кеш трансляций адресов внутри процессора.

**При промахе TLB:**
1. MMU обращается к таблице страниц в оперативной памяти
2. Находит соответствие виртуальной страницы физическому кадру
3. Обновляет TLB новой трансляцией
4. Выполняется запрошенная операция с памятью

### 5. Что такое Copy-on-Write и где он применяется?

**Copy-on-Write (CoW)** - оптимизационная техника, при которой копирование данных откладывается до момента фактической модификации.

**Применение:**
- При вызове `fork()` - родитель и ребенок изначально используют одни страницы
- При записи в разделяемую память с флагом MAP_PRIVATE
- В файловых системах при создании снапшотов

## Page Faults

### 6. Чем отличается minor page fault от major page fault?

| Тип | Причина | Время разрешения |
|-----|---------|------------------|
| **Minor** | Страница есть в RAM, но не в таблице страниц процесса | Микросекунды |
| **Major** | Страницы нет в RAM, нужно загружать с диска | Миллисекунды |

### 7. Почему при первом обращении к malloc()-памяти происходит page fault?

`malloc()` только резервирует виртуальную память. Физические страницы выделяются "лениво" при первом обращении (demand paging). При первой записи происходит minor page fault, и ядро выделяет физический кадр.

### 8. Как уменьшить количество page faults?

- Использовать `mlock()` для фиксации критичных страниц в RAM
- Предварительная инициализация данных (`memset()` после `malloc()`)
- Оптимизация паттернов доступа к памяти (последовательный vs случайный)
- Увеличение размера рабочего набора процесса

### 9. Что такое demand paging и page replacement?

**Demand Paging** - стратегия, при которой страницы загружаются в память только при обращении к ним.

**Page Replacement** - алгоритмы вытеснения страниц из RAM при нехватке памяти (LRU, FIFO, Clock).

## Memory Mapping

### 10. Чем mmap() отличается от read()/write()? Когда mmap эффективнее?

**Отличия:**
- `mmap()`: прямое отображение файла в память, работа через указатели
- `read()/write()`: системные вызовы с копированием данных через буфер ядра

**mmap эффективнее когда:**
- Большие файлы (> 64 MB)
- Случайный доступ к данным
- Несколько процессов читают один файл
- Частые мелкие чтения/записи

### 11. Что такое MAP_PRIVATE и MAP_SHARED? В чём разница?

- **MAP_PRIVATE**: изменения видны только текущему процессу (Copy-on-Write)
- **MAP_SHARED**: изменения видны всем процессам и записываются в файл

### 12. Что произойдёт, если обратиться к памяти за пределами отображённого файла?

Произойдет ошибка **SIGBUS** (bus error), если:
- Файл был усечен после отображения
- Обращение к странице за пределами файла
- Для анонимных отображений - segmentation fault (SIGSEGV)

### 13. Как работает page cache и зачем он нужен?

**Page Cache** - кеш страниц в ядре Linux для ускорения доступа к файлам.

**Принцип работы:**
- При чтении файла данные кешируются в RAM
- Повторные чтения берутся из кеша
- Запись сначала попадает в кеш (dirty pages)
- Периодически или при `fsync()` данные сбрасываются на диск

## Файловый I/O

### 14. Зачем нужна буферизация? Какие уровни буферизации существуют?

**Зачем:** уменьшение количества системных вызовов и оптимизация работы с диском.

**Уровни буферизации:**
1. **User-space** (stdio) - буфер в пространстве пользователя
2. **Kernel page cache** - кеш страниц ядра
3. **Disk controller cache** - кеш контроллера диска

### 15. Почему маленький размер буфера замедляет I/O?

- Увеличивается количество системных вызовов
- Растут накладные расходы на переключение контекста
- Неэффективное использование кешей процессора
- Увеличивается время ожидания операций ввода-вывода

### 16. Что такое O_DIRECT и O_SYNC? Когда их использовать?

- **O_DIRECT**: обход page cache, прямое чтение/запись на диск
- **O_SYNC**: синхронная запись, данные сбрасываются на диск перед возвратом из write()

**Использовать:**
- **O_DIRECT**: базы данных (у них свой кеш), потоковые данные
- **O_SYNC**: критичные к сохранности данные (журналирование)

### 17. Чем отличается fwrite() от write()?

| Аспект | fwrite() | write() |
|--------|----------|---------|
| **Уровень** | Библиотека C (stdio) | Системный вызов |
| **Буферизация** | Есть (user-space) | Нет (или kernel cache) |
| **Производительность** | Выше для мелких операций | Выше для больших блоков |
| **Контроль** | Автоматический | Ручной |

## Файловая система

### 18. Что такое inode и что в нём хранится?

**Inode (index node)** - структура данных, содержащая метаданные файла.

**Хранится:**
- Тип файла и права доступа
- Владелец и группа
- Размер файла и временные метки
- Количество жестких ссылок
- Указатели на блоки данных

### 19. Почему имя файла не хранится в inode?

Имя файла хранится в директории, что позволяет:
- Одному файлу иметь несколько имен (жесткие ссылки)
- Эффективно организовывать иерархическую структуру
- Переименовывать файлы без изменения inode

### 20. Чем жёсткая ссылка отличается от символьной?

| Характеристика | Жесткая ссылка | Символьная ссылка |
|----------------|----------------|-------------------|
| **Inode** | Тот же | Разный |
| **Файловая система** | Только в пределах | Может пересекать |
| **Удаление оригинала** | Файл остается | Ссылка ломается |
| **Размер** | Занимает место в директории | Длина имени файла |

### 21. Как в ext4 хранятся большие файлы (indirect pointers)?

1. **Прямые указатели** (12 штук) - для файлов до ~48 KB
2. **Одинарная косвенность** - указатель на блок с 1024 указателями (~4 MB)
3. **Двойная косвенность** - указатель на блок указателей на блоки указателей (~4 GB)
4. **Тройная косвенность** - для файлов до ~4 TB

## Дисковое планирование

### 22. Зачем нужны I/O schedulers?

**Для оптимизации:**
- Уменьшения времени поиска на HDD
- Справедливого распределения пропускной способности
- Гарантии времени отклика для интерактивных приложений
- Объединения смежных операций

### 23. Чем отличаются FCFS, SSTF, SCAN?

- **FCFS** (First Come First Served): в порядке поступления (простой, но неэффективный)
- **SSTF** (Shortest Seek Time First): ближайшая к головке операция (риск starvation)
- **SCAN** (Elevator): движение в одном направлении с разворотом (честный, предсказуемый)

### 24. Какие I/O schedulers используются в современном Linux?

- **mq-deadline** - гарантированное время отклика
- **bfq** (Budget Fair Queueing) - честное распределение между процессами
- **kyber** - для быстрых устройств (NVMe)
- **none** - без планирования (для SSD)

### 25. Почему для SSD планирование менее критично, чем для HDD?

- **Нет механических частей** - не нужно оптимизировать перемещение головки
- **Параллельный доступ** - множество операций одновременно
- **Одинаковая скорость** случайного и последовательного доступа
- **Износ ячеек** - важнее равномерное распределение записи

## Производительность

### 26. Что такое фрагментация памяти? Внутренняя vs внешняя.

**Фрагментация** - неэффективное использование памяти из-за разбросанности свободных блоков.

- **Внутренняя**: неиспользуемая память внутри выделенного блока
- **Внешняя**: свободная память разбита на мелкие несмежные блоки

### 27. Как swap влияет на производительность?

**Положительно:**
- Позволяет работать при нехватке RAM
- Вытесняет неактивные страницы

**Отрицательно:**
- Сильное замедление при активном использовании (thrashing)
- Износ SSD при частой записи
- Увеличение времени отклика

### 28. Что такое thrashing и как его избежать?

**Thrashing** - ситуация, когда система тратит больше времени на своппинг, чем на полезную работу.

**Как избежать:**
- Увеличить объем RAM
- Оптимизировать рабочие наборы процессов
- Использовать `mlock()` для критичных страниц
- Настроить политику swappiness

### 29. Почему последовательный доступ к памяти быстрее случайного?

- **Кеширование** - предвыборка следующих данных
- **TLB** - меньше промахов при последовательном доступе
- **Аппаратная оптимизация** - burst режимы памяти
- **Дисковые операции** - меньше перемещений головки

### 30. Что такое cache-friendly код?

Код, оптимизированный для эффективного использования кешей процессора.

**Принципы:**
- Локализация данных (работа с близкими адресами)
- Последовательный доступ к памяти
- Компактные структуры данных
- Выравнивание по границам кеш-линий
- Минимизация указателей в структурах
