### Вопросы для анализа

1. **VSZ намного больше RSS**, так как он включает всю виртуальную память, а RSS показывает только страницы в физической памяти.

2. **Разные типы памяти в адресном пространстве находятся таким образом:**

   **АДРЕСНОЕ ПРОСТРАНСТВО (от низких к высоким адресам):**

   **НИЗКИЕ АДРЕСА (0x0000...)**
   `0x62efb8e31000` : КОД ПРОГРАММЫ (24 KB) – `r-xp`
   `0x62efee811000` : [HEAP] системный (132 KB) – `rw-p`

   **СРЕДНИЕ АДРЕСА (0x7000...)**
   `0x7be73a900000` : FILE-BACKED MMAP (5 MB) – `rw-s`
   `0x7be73ae00000` : ANONYMOUS MMAP (50 MB) – `rw-p`
   `0x7be73e1ff000` : HEAP наш (10 MB) – `rw-p`
   `0x7be73ec00000` : БИБЛИОТЕКИ (~2 MB) – `r-xp`

   **ВЫСОКИЕ АДРЕСА (0x7ffe...)**
   `0x7ffc24e6e000` : [STACK] (132 KB) – `rw-p`

3. **При заполнении памяти (`memset`)** RSS увеличивается одинаково (в данном случае на 1 МВ) для `malloc` и `mmap`. Без `memset` разница была бы значительной.

4. **Что означают разные права доступа?**

   - `r-xp`:
     - `r` — разрешено чтение
     - `-` — запрещена запись
     - `x` — разрешено исполнение
     - `p` — приватная область памяти

   - `rw-p`:
     - `r` — разрешено чтение
     - `w` — разрешена запись
     - `-` — запрещено исполнение
     - `p` — приватная область памяти

## Ответы на вопросы для отчёта из скелета **memory_profiler**:
1. **VSZ > RSS** - **VSZ** включает всю виртуальную память, **RSS** только страницы в **RAM**.
2. **PSS** лучше **RSS** - **PSS** учитывает разделение библиотек между процессами, **RSS** нет.
3. Показывает уникальную память процесса, освобождаемую при его завершении.
4. **Shared_dirty** растёт при изменении разделяемой памяти.
5. Права доступа:
- `r-x` - код
- `rw-` - данные
- `r--` - read-only данные
6. **Heap** растёт вверх от данных, **Stack** растёт вниз от конца адресного пространства.
7. **Minor faults** растут при первом доступе к страницам, уже загруженным в **RAM**.
8. **Major faults** возникают при загрузке страниц с диска.
9. Используется одна копия в **RAM** для многих процессов.
10. Память скопируется при записи, изначально общая.

## Общие вопросы для отчёта

1. Виртуальная память (Virtual Memory) — абстракция, позволяющая каждому процессу иметь собственное изолированное адресное пространство, независимое от физической памяти. Нужна для:
   - Изоляции процессов
   - Упрощения программирования
   - Эффективного использования RAM
   - Разделяемой памяти

2. VSZ / VIRT (Virtual Size) — полный размер виртуального адресного пространства процесса. Включает код программы, данные, стек, кучу, разделяемые библиотеки, memory-mapped файлы, неиспользуемые зарезервированные области.
   RSS (Resident Set Size) — размер физической памяти (RAM), которую процесс реально занимает в данный момент.
   PSS (Proportional Set Size) — более точная метрика, которая делит разделяемую память пропорционально между процессами.
   USS (Unique Set Size) — память, используемая только этим процессом (приватные страницы). USS показывает, сколько памяти освободится, если завершить этот процесс.
   PSS — лучшая метрика для понимания реального вклада процесса в потребление памяти системы, так как она учитывает разделяемую память пропорционально.

3. Страница — единица виртуальной памяти фиксированного размера (обычно 4 KB). Виртуальная память делится на страницы.
   Кадр (Frame / Page Frame) — единица физической памяти того же размера, что и страница. Физическая память делится на кадры.
   Таблица страниц (Page Table) — структура данных ядра, хранящая соответствие: виртуальная страница → физический кадр + флаги

4. MMU (Memory Management Unit) — аппаратный блок процессора, который переводит виртуальные адреса в физические используя таблицу страниц.
   TLB (Translation Lookaside Buffer) — аппаратный кеш последних трансляций адресов. При промахе TLB процессору приходится обращаться к таблице страниц в памяти для получения трансляции, что занимает значительно больше времени.

5. Copy-on-Write (COW) — механизм, при котором после fork() родитель и ребёнок изначально используют одни и те же физические страницы, а копирование происходит только при попытке записи в эти страницы. Применяется:
   - При системном вызове fork() для создания новых процессов
   - В mmap() с флагом MAP_PRIVATE
   - Для эффективного использования памяти при создании копий данных

6. Minor Page Fault (мягкая ошибка страницы) — происходит когда страница есть в RAM, но не отмечена как присутствующая в таблице страниц процесса.
   Major Page Fault (жёсткая ошибка страницы) — происходит когда страницы нет в RAM, нужно загружать с диска.

7. При первом обращении к выделенной памяти происходит minor page fault, так как страница есть в виртуальном адресном пространстве, но не имеет соответствующего физического кадра.

8. Уменьшить количество page faults так:
   - Использовать большие страницы
   - Оптимизировать доступ к памяти
   - Увеличить объем RAM для уменьшения использования swap
   - Использовать mlock() для фиксации критических страниц в памяти

9. Demand paging — стратегия, при которой страницы загружаются в физическую память только при первом обращении к ним, а не заранее.
   Page replacement — алгоритмы, которые решают, какие страницы вытеснить из физической памяти при нехватке свободных кадров.

10. Традиционный подход (read/write): данные копируются из kernel buffer в user buffer, что приводит к лишнему копированию.
    Memory mapping (mmap): файл отображается прямо в адресное пространство процесса, копирования нет, работа идёт напрямую с данными.
    mmap эффективнее когда:
    - Работа с большими файлами
    - Необходим случайный доступ к данным
    - Несколько процессов работают с одним файлом (разделяемая память)

11. MAP_PRIVATE — изменения видны только текущему процессу, не записываются в файл. Подходит для чтения файлов или когда изменения не нужно сохранять.
    MAP_SHARED — изменения видны всем процессам, отображающим этот файл, записываются обратно в файл. Подходит для разделяемой памяти между процессами.

12. Если файл короче, чем отображённая область, обращение к "пустой" части вызовет SIGBUS. Это происходит потому, что ядро не может обеспечить валидные данные для этой области памяти.

13. Page Cache — кеш страниц в оперативной памяти, используемый ядром для ускорения дискового I/O.
    Принцип работы:
    - При чтении файла данные сначала загружаются в page cache
    - Повторные чтения берутся из кеша
    - При записи данные сначала попадают в page cache (dirty pages)
    - Периодически или при fsync() dirty pages сбрасываются на диск
    Зачем нужен: значительно ускоряет операции чтения/записи за счёт кеширования, уменьшает количество обращений к диску.

14. Буферизация нужна для:
    - Уменьшения количества системных вызовов
    - Оптимизации доступа к медленным устройствам (дискам)
    - Сглаживания пиков нагрузки
    Уровни буферизации:
    - User-space buffer (stdio) — буфер библиотеки C (обычно 8 KB)
    - Kernel buffer (page cache) — кеш страниц ядра
    - Disk controller cache — кеш на уровне контроллера диска

15. Маленький размер буфера приводит к:
    - Увеличению количества системных вызовов
    - Росту накладных расходов на каждый вызов
    - Неэффективному использованию кешей процессора
    - Увеличению времени ожидания для дисковых операций

16. O_DIRECT — обход page cache, чтение/запись идут напрямую с диска. Использовать: для баз данных, потокового видео.
    O_SYNC — каждая операция записи ждёт физической записи на диск. Использовать: когда критически важна сохранность данных, для журналируемых операций.

17. fwrite() — функция стандартной библиотеки C, работает с FILE*, использует буферизацию на уровне пользователя. Данные могут накапливаться в буфере перед фактической записью.
    write() — системный вызов, работает с файловым дескриптором, данные обычно сразу передаются в ядро.

18. Inode — структура данных файловой системы, содержащая метаданные о файле.
    Что хранится в inode:
    - Тип файла
    - Права доступа
    - Владелец (UID) и группа (GID)
    - Размер файла в байтах
    - Временные метки
    - Указатели на блоки данных

19. Имя файла не хранится в inode, потому что один файл (один inode) может иметь несколько имён (жёстких ссылок). Имена файлов хранятся в директориях, которые представляют собой таблицы соответствия "имя файла → номер inode".

20. Жёсткая ссылка — создаётся новая запись в директории, указывающая на тот же inode. Оба имени равноправны, ссылка существует пока есть хотя бы одна жёсткая ссылка на файл. Нельзя создавать для директорий и между разными файловыми системами.
    Символьная ссылка — создаётся новый файл (новый inode), содержащий путь к оригиналу. Это отдельный файл, который может указывать на несуществующий объект, можно создавать для директорий и между разными файловыми системами

21. В ext4 для хранения больших файлов используется многоуровневая система указателей:
    - Прямые указатели (direct pointers): Inode содержит 12-15 прямых указателей на блоки данных. Каждый блок обычно 4 KB
    - Косвенные указатели (indirect pointers):
      - Indirect
      - Double Indirect
      - Triple Indirect

22. I/O schedulers нужны для оптимизации порядка обработки запросов к диску, особенно при случайных чтениях. Они решают, в каком порядке обрабатывать запросы, чтобы минимизировать перемещение головок диска и maximize пропускную способность.

23. FCFS (First Come, First Served) — обрабатываем запросы в порядке поступления.
    SSTF (Shortest Seek Time First) — обрабатываем запрос, ближайший к текущей позиции головки.
    SCAN (Elevator Algorithm) — головка двигается в одном направлении, обслуживая все запросы на пути, потом разворачивается.

24. Современный Linux использует:
    - mq-deadline
    - bfq (Budget Fair Queueing)
    - kyber
    - none

25. Для SSD планирование менее критично, потому что:
    - SSD не имеют механических движущихся частей
    - Время доступа ко всем ячейкам памяти примерно одинаково
    - Нет задержек на позиционирование головки
    - SSD сами имеют сложные внутренние контроллеры для управления распределением данных

26. Фрагментация памяти — ситуация, когда свободная память разбита на множество маленьких несмежных блоков.
    Внутренняя фрагментация — происходит когда выделено больше памяти, чем фактически используется.
    Внешняя фрагментация — происходит когда свободная память разбита на множество маленьких блоков, и хотя общий объём свободной памяти достаточен, нельзя выделить большой непрерывный блок.

27. Swap влияет на производительность:
    - Положительно: позволяет системе работать при нехватке физической памяти, предотвращает аварийное завершение процессов.
    - Отрицательно: при активном использовании swap происходят частые операции чтения/записи на медленный диск, что значительно замедляет работу системы.

28. Thrashing — ситуация, когда система тратит больше времени на подкачку страниц, чем на полезную работу. Происходит когда физической памяти недостаточно для рабочего набора процессов.
    Как избежать:
    - Увеличить объем физической памяти
    - Уменьшить количество одновременно работающих процессов
    - Использовать mlock() для критических страниц
    - Использовать оптимизированные алгоритмы замены страниц

29. Последовательный доступ быстрее случайного потому что:
    - Используется spatial locality — данные, расположенные рядом, с большей вероятностью понадобятся вместе
    - Процессорные кеши оптимизированы для последовательного доступа

30. Cache-friendly код — код, написанный с учётом принципов работы кешей процессора.
