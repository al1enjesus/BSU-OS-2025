## Задание A: Анализ виртуальной памяти процесса

### Цель
Исследовать распределение виртуальной памяти процесса при различных способах выделения (стек, куча, mmap) и проанализировать метрики памяти.

### Реализация
Программа на Python выполняет:
1. Выделение памяти в стеке (1 KB)
2. Выделение памяти в куче через malloc (1 MB)
3. Попытку выделения через mmap (1 MB)
4. Чтение и анализ `/proc/self/maps`, `/proc/self/status`

### Результаты эксперимента

**ДО выделения памяти:**
- VSZ (VmSize): 23,232 KB
- RSS (VmRSS): 12,276 KB

**ПОСЛЕ выделения памяти:**
- VSZ (VmSize): 25,280 KB  
- RSS (VmRSS): 13,300 KB

**Изменения:**
- ΔVSZ: +2,048 KB
- ΔRSS: +1,024 KB

### Карта памяти (/proc/self/maps)

2a768000-2a980000 rw-p 00000000 00:00 0 [heap]
7ffce5368000-7ffce5389000 rw-p 00000000 00:00 0 [stack]


### Анализ
1. **VSZ vs RSS**: VSZ значительно больше RSS, так как VSZ включает всю виртуальную память (зарезервированную, но не обязательно загруженную в физическую память), тогда как RSS отражает только фактически используемые страницы в RAM.

2. **Размещение сегментов**:
   - **Куча (heap)**: `2a768000-2a980000` - динамическое выделение через malloc
   - **Стек (stack)**: `7ffce5368000-7ffce5389000` - локальные переменные функции

3. **Проблема с mmap**: Возникла ошибка "mmap can't specify both access and flags, prot", что указывает на некорректное использование флагов в вызове mmap.

## Задание B: Буферизованный vs Небуферизованный I/O

### Цель

### Методы тестирования
1. Стандартная библиотека C (буферизованный)
2. Системные вызовы с разными размерами буфера: 512B, 1KB, 4KB, 8KB, 16KB, 32KB, 64KB

|-------|---------------|-------------|-------------------|------------------|
| stdio_buffered | - | 7.59 | 13.2 | - |
| syscall | 512 B | 1.56 | 63.9 | ~204,800 |
| syscall | 1 KB | 0.82 | 121.3 | ~102,400 |
| syscall | 4 KB | 0.36 | 281.1 | ~25,600 |
| syscall | 8 KB | 0.29 | 340.1 | ~12,800 |
| syscall | 16 KB | 0.44 | 225.4 | ~6,400 |
| syscall | 32 KB | 0.31 | 320.7 | ~3,200 |
| syscall | 64 KB | 0.28 | 356.1 | ~1,600 |

### Анализ strace
```bash
% time    seconds  usecs/call    calls    errors syscall
---
```

1. Оптимальный размер буфера: 64 KB показал наилучшую производительность (0.28 сек)

2. Влияние количества системных вызовов: Уменьшение количества syscall напрямую влияет на производительность

3. Буферизация stdio: Стандартная библиотека значительно медленнее из-за дополнительных уровней буферизации

4. Неравномерность производительности: Размер буфера 16 KB показал аномально низкую производительность, что может быть связано с выравниванием или кэшированием

## Ответы на вопросы

1. Абстракция, дающая каждому процессу своё изолированное адресное пространство. Нужна для изоляции процессов, безопасности и использования памяти большего объёма, чем ОЗУ (через swap).

2. VSZ — виртуальный размер процесса; RSS — резидентная память в ОЗУ; PSS — RSS, поделённая между процессами; USS — эксклюзивная память процесса. USS точнее показывает реальное потребление.

3. Страница — блок виртуальной памяти; кадр — блок физической памяти; таблица страниц — структура, отображающая виртуальные страницы на физические кадры.

4. MMU — модуль управления памятью, преобразует виртуальные адреса в физические. TLB — буфер быстрого преобразования адресов. При промахе TLB обращение идёт к таблице страниц (медленнее).

5. Copy-on-Write — механизм, при котором копирование данных откладывается до момента записи. Используется при fork(), mmap(MAP_PRIVATE).

6. Minor page fault — страница есть в памяти, но не в таблице процесса; Major page fault — страницы нет в ОЗУ, требуется загрузка с диска.

7. malloc() выделяет виртуальную память; при первом обращении к ней происходит page fault, чтобы подключить физическую страницу.

8. Увеличить размер ОЗУ, оптимизировать алгоритмы, использовать mlock() для фиксации страниц.

9. Demand paging — загрузка страниц по требованию; page replacement — замена страниц при нехватке памяти

10. mmap() отображает файл в память, read()/write() — системные вызовы для чтения/записи. mmap эффективнее при частом случайном доступа.

11. MAP_PRIVATE — изменения не видны другим и не записываются в файл; MAP_SHARED — изменения общие и синхронизируются с файлом.

12. SIGSEGV (segmentation fault) — обращение к неотображённой памяти.

13. Page cache — кеш в ОЗУ для файловых данных и метаданных. Ускоряет доступ к часто используемым данным.

14. Буферизация уменьшает количество системных вызовов и дисковых операций. Уровни: в приложении, в stdio, в ядре (page cache).

15. Маленький буфер → больше системных вызовов → накладные расходы.

16. O_DIRECT — обход page cache (для СУБД); O_SYNC — синхронная запись на диск (для надёжности).

17. fwrite() — буферизуемая библиотечная функция; write() — небуферизуемый системный вызов.

18. Inode — структура, хранящая метаданные файла (права, размер, ссылки, указатели на данные), но не имя.

19. Имя файла хранится в директории для поддержки нескольких жёстких ссылок на один inode.

20. Жёсткая ссылка — дополнительное имя для того же inode; символическая ссылка — отдельный файл, содержащий путь к другому файлу.

21. В ext4 для больших файлов используются: прямые, косвенные, двойные и тройные косвенные блоки указателей.

22. I/O schedulers упорядочивают запросы для уменьшения времени позиционирования головок HDD
 
23. FCFS — в порядке поступления; SSIT — кратчайшее время поиска сначала; SCAN — движение головки от края к краю.

24. В Linux: mq-deadline, BFQ, Kyber (для SSD/NVMe).

25. У SSD нет механических головок, поэтому планирование менее критично.

26. Фрагментация — разбиение памяти на несмежные блоки. Внутренняя — неиспользуемая память внутри выделенного блока; внешняя — свободные блоки слишком малы для новых запросов.

27. Swap использует дисковое пространство как расширение ОЗУ, но замедляет работу из-за дисковых операций.

28. Thrashing — система тратит больше времени на подкачку страниц, чем на работу. Лечение: уменьшить нагрузку, добавить ОЗУ.

29. Последовательный доступ эффективнее из-за предварительной выборки (prefetching) и кеширования

30. Cache-friendly код — использование локальности данных, последовательный доступ, компактные структуры.
