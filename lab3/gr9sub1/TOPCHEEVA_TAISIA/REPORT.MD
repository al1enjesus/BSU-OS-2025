### 6. Ответы на вопросы
1. **Чем поток отличается от процесса? Где увидеть поток в /proc и ps?**
   - **Отличие**: Процесс — независимая единица с собственным адресным пространством и ресурсами. Поток — легковесная единица внутри процесса, разделяющая адресное пространство, но имеющая собственный стек и регистры.
   - **Где увидеть**: В `ps -L -p <pid>` потоки отображаются как LWP с TID. В `/proc/<pid>/status` поле `Threads` показывает количество потоков. Каталог `/proc/<pid>/task` содержит подкаталоги с TID каждого потока.

2. **Что такое race condition и почему volatile не решает проблему корректности?**
   - **Race condition**: Ситуация, когда результат зависит от порядка выполнения потоков, работающих с общими данными без синхронизации (например, одновременный инкремент счётчика).
   - **Почему volatile не помогает**: `volatile` предотвращает оптимизации компилятора, но не обеспечивает атомарность или синхронизацию. Нужны мьютексы или атомики.

3. **Когда выбирать mutex/condvar, когда semaphore, когда атомики?**
   - **Mutex/condvar**: Для сложной синхронизации, например, защиты критических секций (mutex) или ожидания событий (condvar). Подходят для продюсер-потребитель.
   - **Semaphore**: Для управления доступом к ограниченным ресурсам (например, слоты в буфере). Удобны для bounded buffer.
   - **Атомики**: Для простых операций (например, инкремент счётчика) без блокировок. Быстрее мьютексов.

4. **Почему синхронизация замедляет выполнение и как уменьшать contention?**
   - **Замедление**: Мьютексы и семафоры вызывают блокировки и переключение контекста. Атомики менее затратны, но требуют координации.
   - **Уменьшение contention**:
     - Минимизировать критические секции.
     - Использовать атомики для простых операций.
     - Разделять данные между потоками.
     - Применять `memory_order_relaxed` для атомиков, если строгая синхронизация не нужна.

5. **Что такое ложное совместное использование (false sharing) и как его избежать?**
   - **False sharing**: Когда потоки обращаются к разным переменным в одной кэш-линии процессора, вызывая ненужную синхронизацию кэша.
   - **Как избежать**:
     - Выравнивать данные по кэш-линиям (`alignas(64)`).
     - Использовать локальные переменные для промежуточных вычислений.
     - Группировать данные, используемые одним потоком, вместе.
