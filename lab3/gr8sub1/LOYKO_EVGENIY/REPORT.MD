# Отчет по лабораторной работе #3
## Потоки, синхронизация и гонки данных

### Цель работы
Изучение многопоточности в Linux, воспроизведение гонок данных и их устранение с помощью примитивов синхронизации.

### Задачи
1. Реализовать программу с гонкой данных и устранить её
2. Реализовать bounded buffer (producer-consumer) 
3. Исследовать потоки в системе

### Шаги выполнения

#### A) Гонка данных и устранение

**Реализация:**
- `thread_race.c` - программа с тремя режимами синхронизации
- Режим `unsync`: без синхронизации (демонстрация гонки)
- Режим `mutex`: с использованием `pthread_mutex_t`
- Режим `atomic`: с использованием атомарных операций

**Команды запуска:**
```bash
./thread_race 4 1000000 unsync
./thread_race 4 1000000 mutex  
./thread_race 4 1000000 atomic

B) Producer-Consumer (bounded buffer)
Реализация:prodcons.c - кольцевой буфер с синхронизацией

Использование pthread_mutex_t + pthread_cond_t

Корректное завершение потоков

Команды запуска:
./prodcons -P 2 -C 2 -N 100000 -B 64

C) Потоки в системе
Команды для исследования:
ps -L -p <PID> -o pid,tid,psr,pcpu,stat,comm
cat /proc/<PID>/status | grep Threads
ls -l /proc/<PID>/task

Выводы

Гонка данных: При тестировании гонка не проявилась даже при 8 потоках и 40M операций. Возможные причины:

Особенности ARM архитектуры

Оптимизации компилятора

Быстрое выполнение на современном процессоре

Производительность синхронизации:

Unsync: 2ms (экстремально быстро, но потенциально небезопасно)

Atomic: 22-345ms (в 11-170 раз медленнее unsync)

Mutex: 109-1113ms (в 54-556 раз медленнее unsync)

Mutex значительно медленнее atomic из-за блокировок

Producer-Consumer: Работает корректно - все элементы произведены и потреблены, сумма значений совпадает для различных конфигураций.



Ответы на вопросы

Чем поток отличается от процесса? Где увидеть поток в /proc и ps?
Поток разделяет память с процессом, процесс имеет отдельное адресное пространство. Потоки видны в /proc/<PID>/task/ и ps -L -p <PID>.

Что такое race condition и почему volatile не решает проблему корректности?
Race condition - когда результат зависит от порядка выполнения потоков. volatile гарантирует чтение из памяти, но не атомарность операций.

Когда выбирать mutex/condvar, когда semaphore, когда атомики?

Mutex+condvar: сложная синхронизация (очереди, ожидание условий)

Semaphore: счетчики ресурсов

Атомики: простые операции (инкремент, CAS)

Почему синхронизация замедляет выполнение и как уменьшать contention?
Замедление из-за блокировок и ожидания. Уменьшать contention: finer-grained locking, lock-free структуры.

Что такое ложное совместное использование (false sharing) и как его избежать?
Когда разные ядра кэшируют одну cache-line с разными данными. Избегать: выравнивание данных, padding.
