A) Гонка данных и устранение (mutex vs atomic)
Необходимо было изменить файл thread_race.c из папки samples.
Реализованы три режима:
mutex — инкремент через мьютекс (pthread_mutex_t).
atomic — атомарный инкремент через atomic_fetch_add_explicit.
Создается массив аргументов потоков для корректного распределения M инкрементов между N потоками.
Перед запуском каждого режима обнуляются счётчики: counter = 0 и atomic_store(&atomic_counter, 0). Происходит измерение времени выполнения с помощью gettimeofday().
Тогда при запуске кода мы получаем:
Mode: mutex
Threads: 4, Total increments: 1000000
Expected: 1000000, Actual: 1000000
Time: 0.031087 sec
Mode: atomic
Threads: 4, Total increments: 1000000
Expected: 1000000, Actual: 1000000
Time: 0.010459 sec
Оба способа синхронизации дают точный результат (Actual = Expected).
Потоковой гонки нет. Атомики выполняются быстрее мьютекса (0.010 s против 0.031 s). Мьютекс создаёт накладные расходы на блокировку и ожидание потоков. Программа не использует sudo. Количество потоков N и итераций M задаётся пользователем через аргументы командной строки. Все созданные потоки присоединяются через pthread_join. Мьютекс корректно уничтожается вызовом pthread_mutex_destroy(&mutex). Память, выделенная для массивов потоков и аргументов, освобождается через free.

B) Producer–Consumer (bounded buffer, семафоры)
Реализован кольцевой буфер с параметрами:
-P — количество производителей,
-C — количество потребителей,
-N — общее количество элементов,
-B — размер буфера.
Синхронизация: два семафора (empty и full), mutex для доступа к буферу. Корректное завершение: после завершения всех производителей потребители завершаются без busy-wait.
Тогда при запуске ./prodcons -P 1 -C 1 -N 1000 -B 16
получаем
[prodcons: sem] P=1 C=1 N=1000 B=16 produced=1000 consumed=1000 sum=1000499500 expected_sum=1000499500 time=0.001702s
sum и expected_sum совпадают, значит гонки данных нет.

Ответы на вопросы
Чем поток отличается от процесса? Где увидеть поток в /proc и ps?
Потоки делят общую память и ресурсы процесса (код, данные, дескрипторы файлов), а процессы — полностью изолированы.

Что такое race condition и почему volatile не решает проблему корректности? Race condition возникает, когда несколько потоков одновременно обращаются к общим данным без синхронизации. volatile лишь запрещает оптимизацию компилятором, но не делает операции атомарными.

Когда выбирать mutex/condvar, когда semaphore, когда атомики?
mutex/condvar — когда нужно синхронизировать доступ к сложным структурам данных.
semaphore — для подсчёта доступных ресурсов (например, ячеек буфера).
atomic — для простых счётчиков и флагов без необходимости блокировки.

Почему синхронизация замедляет выполнение и как уменьшать contention?
Из-за блокировок и ожидания между потоками

Что такое ложное совместное использование (false sharing) и как его избежать?
Когда разные потоки модифицируют переменные, лежащие в одном кэше-линии, и кэш постоянно инвалидируется. Избегают этого, выравнивая данные по границам кэш-линий или разделяя структуры.
