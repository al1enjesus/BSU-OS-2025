## Ответы на вопросы
### 1
**Поток (thread)** - это легковесная единица выполнения внутри процесса, которая разделяет с ним память, файловые дескрипторы и другие ресурсы. Все потоки процесса выполняются в одном адресном пространстве. **Процесс** - это изолированная единица выполнения с собственным адресным пространством, ресурсами и состоянием.
### 2 
**Race condition (гонка данных)** возникает, когда несколько потоков одновременно обращаются к общим данным, и хотя бы один поток изменяет эти данные, при этом порядок доступа не детерминирован. 
`volatile` гарантирует только чтение из основной памяти, а не из кэша процессора 
**НЕ гарантирует атомарность** составных операций. 
**НЕ предотвращает** переупорядочивание инструкций компилятором.
**НЕ обеспечивает** взаимное исключение
### 3
**`mutex/condvar`** (мьютекс + условные переменные):
- **Когда использовать**: Сложные условия синхронизации, ожидание событий
- **Примеры**: Producer-Consumer, читатели-писатели, барьеры
- **Преимущества**: Гибкость, точный контроль
- **Недостатки**: Сложнее в использовании
**`semaphore`** (семафоры):
- **Когда использовать**: Ограничение доступа к ресурсам, подсчёт
- **Примеры**: Ограничение соединений, пулы ресурсов
- **Преимущества**: Проще для подсчёта ресурсов
- **Недостатки**: Меньше гибкости чем mutex/condvar
**Атомики** (`stdatomic.h`):
- **Когда использовать**: Простые операции (инкремент, декремент, CAS)
- **Примеры**: Счётчики, флаги, простые структуры данных
- **Преимущества**: Высокая производительность, lock-free
- **Недостатки**: Ограниченный набор операций
### 4
Причины:
1. **Блокировки**: Потоки ожидают доступа к критическим секциям
2. **Контекстные переключения**: При ожидании mutex/semaphore
3. **Когерентность кэшей**: Синхронизация кэшей между ядрами процессора
4. **Memory barriers**: Ограничения переупорядочивания инструкций
**Методы уменьшения contention:**
    **Уменьшение времени в критических секциях**
    **Использование lock-free структур данных**
    **Локализация данных по потокам**
    **Иерархические блокировки**
    **Оптимистичные блокировки**
### 5
**False sharing** возникает, когда несвязанные данные, часто используемые разными потоками, попадают в одну кэш-линию. При изменении одного элемента процессор вынужден синхронизировать всю кэш-линию.
**Симптомы:**
- Необъяснимое падение производительности
- Высокая нагрузка на системную шину
- Потоки "мешают" друг другу без видимой причины
**Способы избежания:**

1. **Выравнивание данных**
2. **Размещение в разных кэш-линиях**
3. **Thread-local storage**
4. **Массивы с padding**
5. **Использование специализированных структур**
