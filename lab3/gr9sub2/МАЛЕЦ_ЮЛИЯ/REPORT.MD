4. Все потоки одного процесса разделяют общие ресурсы (память, файловые дескрипторы), но планируются независимо на разных ядрах процессора.

Ответы на вопросы для отчёта

1. Чем поток отличается от процесса? Где увидеть поток в /proc и ps?

Отличия:

* Процесс - изолированная единица выполнения с собственным адресным пространством
* Поток - часть процесса, разделяет память и ресурсы с другими потоками того же процесса

Где увидеть:

* В /proc:
  ```
  /proc/<PID>/task/                  # директории для каждого потока
  /proc/<PID>/status | grep Threads  # общее количество потоков
  ```
* В ps:
  ```
  ps -L -p <PID>             # показать все потоки процесса
  ps -eLf                    # показать все потоки системы
  ```

2. Что такое race condition и почему volatile не решает проблему корректности?

Race condition - состояние гонки, когда результат выполнения программы зависит от порядка выполнения потоков.

Volatile не решает проблему, потому что:

* volatile гарантирует только чтение из памяти, а не из регистров
* Не обеспечивает атомарность составных операций (инкремент = read-modify-write)
* Не предотвращает переупорядочивание операций компилятором/процессором
* Не обеспечивает взаимное исключение доступа к критической секции

3. Когда выбирать mutex/condvar, когда semaphore, когда атомики?

Mutex + Condvar:

* Сложная логика ожидания (producer-consumer)
* Условные ожидания (wait/notify)
* Защита критических секций с ожиданием условий

Semaphore:

* Ограничение доступа к ресурсам с фиксированной ёмкостью
* Синхронизация между процессами (именованные семафоры)
* Счётчики доступных ресурсов

Атомики:

* Простые операции (инкремент, compare-and-swap)
* Высокая производительность для простых операций
* Lock-free алгоритмы

4. Почему синхронизация замедляет выполнение и как уменьшать contention?

Причины замедления:

* Блокировки потоков (ожидание мьютексов)
* Переключения контекста
* Инвалидация кэшей процессора
* Serialization операций

Способы уменьшения contention:

* Fine-grained locking (мелкозернистые блокировки)
* Lock-free структуры данных
* Уменьшение времени удержания блокировок
* Thread-local storage где возможно
* Read-write locks для read-heavy workload

5. Что такое ложное совместное использование (false sharing) и как его избежать?

False sharing - ситуация, когда несвязанные данные разных потоков попадают в одну кэш-линию, вызывая постоянную инвалидацию кэша.

Как избежать:

* Выравнивание данных по размеру кэш-линии (обычно 64 байта)
* Размещение часто изменяемых данных разных потоков в разных кэш-линиях
* Использование padding между переменными
* Локальное копирование данных в стек потока
