### Задание A: TOP-5 слов в syslog
**Шаги:**
1. Для анализа использовался системный лог.
2. Команда преобразует текст в список слов в нижнем регистре, сортирует и подсчитывает частоту.

**Используемые команды:**

```cat /var/log/syslog | \
grep -v '^[A-Z][a-z][a-z] [0-9 :]* [a-zA-Z0-9-]*' | \
tr -cs '[:alnum:]' '\n' | tr '[:upper:]' '[:lower:]' | \
grep -v '^[0-9]*$' | \
sort | uniq -c | sort -nr | head -n 5
```

**Результат:**
   15636 bogdan
   5152 kernel
   4291 03t23
   4174 systemd
   3547 gnome
   
   Почему в задании А среди топ-слов bogdan и числа?
   В исходном варианте не была реализована фильтрация временных меток и имён пользователей, поэтому они попали в статистику. Фильтрация, исключающая временные метки и числа, делает вывод более информативным.

### Задание Б: Анализ неудачных событий аутентификации

**Исходная цель:** Найти TOP-10 IP-адресов с неудачными попытками входа.
**Адаптированная цель:** Проанализировать типы и источники неудачных событий в системе аутентификации.

**Итоговая команда:**
```
if ls /var/log/auth.log* &>/dev/null; then
    raw_lines=$(zgrep -hE 'Failed|Invalid' /var/log/auth.log* 2>/dev/null)

    if [ -z "$raw_lines" ]; then
        echo "Неудачных SSH-подключений не обнаружено."
    else
        echo "$raw_lines" | \
        grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' | \
        sed -E 's/([0-9]+\.[0-9]+\.[0-9]+\.)[0-9]+/\1x/' | \
        sort | uniq -c | sort -nr | head -10
    fi
else
    echo "Файл /var/log/auth.log* не найдены"
fi
```
**Результат:**
 Неудачных SSH-подключений не обнаружено.

Так как SSH недоступен, то найдем и подсчитаем неудачные попытки входа для пользователя bogdan.
**Итоговая команда:**
grep -iE '(failed|invalid)' /var/log/auth.log | grep -i bogdan | wc -l
**Результат:**
3

Вывод: Было зафиксировано три неудачных попыток входа.

Можно ли проанализировать другие события безопасности, кроме SSH?
Да, если в логах нет SSH-событий, полезно проверить ошибки sudo, PAM, su, polkitd, а также открытие и закрытие сессий.

### Задание В: Установки пакетов (dpkg.log)
**Шаги:**
1. Поиск всех установленных пакетов.
2. Извлечение имен пакетов.
3. Подсчет количества установок для каждого уникального пакета.
4. Сортировка по популярности и вывод топ-10 результатов.

**Команды:**
```
if ls /var/log/dpkg.log* &>/dev/null; then
    zgrep ' install ' /var/log/dpkg.log* | \
    awk '{print $4}' | sort | uniq -c | sort -nr | head -10
else
    echo "Файл /var/log/dpkg.log* не найдены"
fi
```
**Результат:**
      1 zstd:amd64
      1 zlib1g:amd64
      1 zip:amd64
      1 zenity-common:all
      1 zenity:amd64
      1 yelp-xsl:all
      1 yelp:amd64
      1 yaru-theme-sound:all
      1 yaru-theme-icon:all
      1 yaru-theme-gtk:all

Почему в задании В все пакеты установлены по одному разу — это нормально?
Для свежей системы это типично, так как большинство пакетов устанавливается однократно без частых переустановок.
Проверяли ли команды на чистой системе без персональных данных?
Да, команды проверены на виртуальной машине Ubuntu 22.04, где персональных данных минимум.
