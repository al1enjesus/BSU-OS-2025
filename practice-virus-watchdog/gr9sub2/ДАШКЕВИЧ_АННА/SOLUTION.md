## Часть 1: Обнаружение процесса
1) Kак получить список всех запущенных процессов в Linux?
- Прочитать каталог /proc и парсить файлы /proc//comm, /proc//cmdline, /proc//status.
Использовать утилиты ps/pgrep/pidof (ручной запуск или через subprocess).
В Python опционально использовать 
библиотеку psutil: psutil.process_iter().

2) Как отфильтровать процессы по имени (например, найти "telegram")?
- Использовать pgrep telegram или pgrep -f telegram.
В Python — проверять содержимое /proc//comm или cmdline на наличие подстроки "telegram".

3) Какая информация нужна о процессе для его завершения?
- PID процесса (обязателен).

4) Как часто нужно проверять список процессов, чтобы не нагружать систему?
- Практически 0.5–1.0 сек.

## Часть 2: Завершение процесса
1) Какие сигналы можно отправить процессу в Linux для его завершения?
- SIGTERM (15) — корректное завершение.
SIGINT (2) — прерывание (аналог Ctrl+C).
SIGKILL (9) — принудительное немедленное завершение.

2) В чём разница между SIGTERM и SIGKILL?
- SIGTERM перехватываем и позволяет приложению завершиться корректно.
SIGKILL не перехватывается и мгновенно убивает процесс без очистки.

3) Как отправить сигнал процессу из Python/C?
- Python: os.kill(pid, signal.SIGTERM) и os.kill(pid, signal.SIGKILL); либо subprocess.run(['kill','-TERM',str(pid)]).
C: kill(pid, SIGTERM) из <signal.h>.

4) Нужны ли специальные права (root) для завершения чужого процесса?
- Да. Обычно можно послать сигнал только процессам своего пользователя;
для чужих - нужны повышенные права (root/capabilities).

## Часть 3: GUI уведомление (опционально)
1) Как показать message box (всплывающее окно) в Linux?
- notify-send "Заголовок" "Текст" (система уведомлений).
zenity --info/--error --text="..." (диалоговое окно).
Через Python GUI (Tkinter, Gtk, Qt) — создать и показать окно.

2) Какие инструменты/библиотеки можно использовать для GUI в Python?
- Tkinter (встроено), PyGObject/GTK, PyQt/PySide, wxPython.
Для нативных уведомлений — notify2/dbus или запуск notify-send/zenity.

3) Как сделать, чтобы окно появлялось поверх всех окон?
- Tkinter: root.attributes('-topmost', True).
PyQt/PySide: setWindowFlag(Qt.WindowStaysOnTopHint).
Внешние утилиты не всегда гарантируют top-most, зависит от WM.

## Часть 4: Архитектура решения
1) Как организовать бесконечный цикл мониторинга?
- while True: проверка процессов → реакция → time.sleep(interval).
Обработка KeyboardInterrupt для корректного выхода.

2) Kак обеспечить, чтобы скрипт запускался автоматически при старте системы?
- systemd user unit (~/.config/systemd/user/*.service) + enable.
Desktop Autostart (~/.config/autostart/*.desktop).

3) Как сделать скрипт незаметным для пользователя?
- Запуск в фоне (nohup, systemd user service).
Без лишнего вывода; логирование в файл. Этические аспекты учитывать.

## Часть 5: Защита и обнаружение
1) Как обычный пользователь может обнаружить такой "вирус" на своей системе?
- ps aux | grep python, pgrep -af python, htop.
Проверка автозапуска: systemctl --user list-unit-files, ~/.config/autostart, crontab -l.
lsof/ss для сетей и открытых файлов.

2) Как защититься от подобного скрипта?
- Регулярно ревизировать автозапуск и пользовательские сервисы.
Ограничить права, использовать IDS/мониторинг (auditd, psacct).

3) Какие системные механизмы Linux могут помешать работе такого скрипта?
- Контроль доступа (SELinux/AppArmor), cgroups, namespaces.
Отсутствие прав на отправку сигналов чужим процессам.
Политики окружения (Wayland/DE) для всплывающих окон/уведомлений.
Мини‑разбор реализации
Мониторинг через pgrep — простой и быстрый способ получить PID по имени.
Реакция через отправку сигналов (в учебном коде используется SIGKILL).
GUI предупреждение через zenity/notify-send.
Запуск в фоне через nohup.
Остановка — Ctrl+Z (при интерактивном запуске) или kill по PID.

## Ответы на вопросы:
1) Как ваш код поведёт себя, если одновременно запущено несколько процессов firefox?
- В исправленном варианте каждый PID обрабатывается по отдельности (по строкам pgrep). Всем отправляется SIGKILL.
2) Что произойдёт, если pgrep firefox не найдёт ни одного процесса?
- Пустой вывод/ошибка pgrep игнорируются; скрипт делает sleep(0.5) и продолжает.
3) Почему выбрали SIGKILL вместо более "мягкого" SIGTERM для завершения?
- Для гарантированного мгновенного завершения в учебных целях. В реале лучше сначала SIGTERM, затем при необходимости SIGKILL.
4) Рассматривали ли добавление логирования для отслеживания срабатываний?
- Да. Полезно добавить logging/print для фиксации срабатываний, но в минимальном варианте опущено.
5) Как можно безопасно остановить watchdog кроме kill по PID?
- Послать SIGTERM/SIGINT (kill -TERM ); в интерактиве можно Ctrl+Z и затем завершить job.
6) Что произойдёт, если zenity не установлен в системе?
- Окно не появится, но скрипт не упадёт (исключение перехватывается). Установите zenity или используйте notify-send.
