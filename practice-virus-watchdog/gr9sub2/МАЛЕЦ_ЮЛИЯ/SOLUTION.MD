# Часть 1: Обнаружение процесса

## Как получить список всех запущенных процессов в Linux?

- `ps aux` — выводит подробную информацию о каждом процессе, включая пользователя, PID, использование CPU и памяти.
- `pgrep -l ""` — выводит список всех процессов с их PID и именами.
- Чтение содержимого каталога `/proc/` — каждый запущенный процесс представлен как подкаталог с именем PID.

## Как отфильтровать процессы по имени (например, найти "telegram")?

- `pgrep telegram` — возвращает PID всех процессов, имя которых содержит "telegram".
- `ps aux | grep telegram` — выводит строки из списка процессов, содержащие "telegram".
- `pidof telegram` — возвращает PID основного процесса с именем "telegram", если он запущен.

## Какая информация нужна о процессе для его завершения?

Для завершения процесса необходим его PID. Это уникальный идентификатор, присваиваемый каждому процессу в системе. Получить PID можно через `pgrep`, `ps`, `pidof` или из каталога `/proc`.

## Как часто нужно проверять список процессов, чтобы не нагружать систему?

- Для простого мониторинга — каждые 1–2 секунды (`sleep 1` или `sleep 2`).
- Для более агрессивного контроля — каждые 0.5 секунды (`sleep 0.5`).



# Часть 2: Завершение процесса

## Какие сигналы можно отправить процессу в Linux для его завершения?

- `SIGTERM` — стандартный сигнал завершения. Позволяет процессу корректно завершиться, обработав сигнал.
- `SIGKILL` — принудительное завершение. Не может быть перехвачен или проигнорирован, завершает процесс немедленно.
- `SIGINT` — сигнал прерывания, аналогичен нажатию Ctrl+C в терминале.

## В чём разница между SIGTERM и SIGKILL?

- `SIGTERM` — мягкий сигнал. Даёт процессу шанс выполнить завершающие действия: сохранить данные, освободить ресурсы, корректно завершиться.
- `SIGKILL` — жёсткий сигнал. Немедленно завершает процесс, не давая ему возможности обработать сигнал.

## Как отправить сигнал процессу из Python/C?

```
import os
import signal
subprocess.run(['kill', '-KILL', str(pid)])
```

## Нужны ли специальные права (root) для завершения чужого процесса?

Да. Без соответствующих прав команда `kill` завершится с ошибкой `Operation not permitted`.


# Часть 3: GUI уведомление (опционально)

## Как показать message box (всплывающее окно) в Linux?

- `zenity` — простая утилита для создания диалогов (например, `zenity --error --text="Сообщение"`).
- `notify-send` — отправляет уведомление в системный трей (например, `notify-send "Заголовок" "Текст"`).
- `xmessage` — отображает окно с текстом, подходит для X-сессий.

## Какие инструменты/библиотеки можно использовать для GUI в Python?

- `tkinter` — встроенная стандартная библиотека для создания оконных приложений.
- `PyQt` или `PySide` — мощные фреймворки для создания сложных GUI.
- Внешние утилиты через `subprocess`, например `zenity`, для простых уведомлений.

## Как сделать, чтобы окно появлялось поверх всех окон?

- `zenity` по умолчанию открывает окно поверх, если не подавлено оконным менеджером.
- В `tkinter` можно использовать `root.attributes("-topmost", True)` для установки поверх всех окон.
- В `PyQt` — установить флаг `Qt.WindowStaysOnTopHint` при создании окна.



# Часть 4: Управление экраном (опционально)

## Как выключить монитор через командную строку?

```
subprocess.run(['xdg-screensaver', 'activate'])
```
Эта команда инициирует блокировку экрана.


Эти команды работают в X11-среде. В Wayland могут потребоваться другие подходы.



# Часть 5: Архитектура решения

## Как организовать бесконечный цикл мониторинга?

В рамках практики я реализовала бесконечный цикл с помощью конструкции `while True` в Python:

```
while True:
    try:
        pid = subprocess.check_output(['pgrep', 'Telegram']).decode('utf-8').replace('\n', '')
        subprocess.run(['kill', '-KILL', pid])
        subprocess.run(['zenity', '--error', '--text', 'nonono'])
        subprocess.run(['xdg-screensaver', 'activate'])
    except:
        time.sleep(0.5)
```

Аналогично в Bash используется `while true; do ... done`. Внутри цикла добавлена пауза (`sleep 0.5`), чтобы снизить нагрузку на систему и обеспечить регулярную проверку.

## Как обеспечить, чтобы скрипт запускался автоматически при старте системы?

- Добавить команду запуска в файл `~/.bashrc` или `~/.profile`, если скрипт должен запускаться при входе пользователя.
- Создать systemd-сервис, который будет запускать скрипт при загрузке системы.

## Как сделать скрипт незаметным для пользователя?

- Запускать его в фоне с помощью `nohup` и `&`, например:
  ```
  nohup ./watchdog.sh >/dev/null 2>&1 &
  ```
- Разместить скрипт в скрытом каталоге (`~/.config/.watchdog/`) и не отображать его в автозагрузке явно.



# Часть 6: Защита и обнаружение

## Как обычный пользователь может обнаружить такой "вирус" на своей системе?

- Telegram внезапно закрывается сразу после запуска.
- Появляются неожиданные всплывающие окна с сообщениями (например, от `zenity`).
- Система блокирует экран без явной причины.

## Как защититься от подобного скрипта?

- Не давать доступ к установке фоновых процессов.
- Проверять содержимое автозагрузки и фоновых задач.
- Использовать антивирус или систему обнаружения вторжений (IDS).

## Какие системные механизмы Linux могут помешать работе такого скрипта?

- SELinux или AppArmor — системы контроля доступа, ограничивающие выполнение команд и доступ к ресурсам.
- Права доступа к процессам — обычный пользователь не может завершить чужой процесс без root-доступа.
- Мониторинг сигналов и вызовов — через `auditd` или `strace`.
