- Выбор метода зависит от размера файла, паттерна доступа и операций

## Ответы на вопросы для отчёта

### Виртуальная память

**Что такое виртуальная память и зачем она нужна?**
Виртуальная память - это абстракция, позволяющая каждому процессу иметь собственное изолированное адресное пространство. Нужна для:
- Изоляции процессов друг от друга
- Упрощения программирования (линейное адресное пространство)
- Эффективного использования RAM (demand paging)
- Разделяемой памяти между процессами

**Чем отличаются VSZ, RSS, PSS, USS? Какая метрика наиболее точно показывает потребление памяти процессом?**
- **VSZ**: Полный размер виртуального адресного пространства
- **RSS**: Физическая память в RAM (включая разделяемую)
- **PSS**: RSS с учетом разделения (shared_size / num_processes)
- **USS**: Только уникальная (неразделяемая) память

**Наиболее точная метрика**: PSS, так как она учитывает реальную долю разделяемой памяти.

**Что такое страница, кадр, таблица страниц?**
- **Страница**: Единица виртуальной памяти фиксированного размера (обычно 4KB)
- **Кадр**: Единица физической памяти того же размера, что и страница
- **Таблица страниц**: Структура данных, хранящая соответствие виртуальных страниц физическим кадрам

**Как работает MMU и TLB? Что происходит при промахе TLB?**
- **MMU (Memory Management Unit)**: Аппаратный блок процессора для трансляции виртуальных адресов в физические
- **TLB (Translation Lookaside Buffer)**: Кеш последних трансляций адресов

**При промахе TLB**: MMU обращается к таблице страниц в памяти, что требует дополнительных обращений к RAM (penalty).

**Что такое Copy-on-Write и где он применяется?**
**Copy-on-Write**: Механизм, при котором копирование страницы откладывается до момента записи. Применяется:
- После `fork()` - родитель и ребенок изначально используют одни страницы
- При создании приватных копий разделяемых библиотек

### Page Faults

**Чем отличается minor page fault от major page fault?**
- **Minor fault**: Страница есть в RAM, но не отмечена в таблице страниц (быстро)
- **Major fault**: Страницы нет в RAM, нужно загружать с диска (медленно)

**Почему при первом обращении к malloc()-памяти происходит page fault?**
`malloc()` выделяет только виртуальную память. При первом обращении к странице возникает minor fault для выделения физического кадра и его обнуления.

**Как уменьшить количество page faults?**
- Использовать `calloc()` вместо `malloc()` + memset()
- Предварительно инициализировать память
- Использовать большие страницы (hugepages)
- Оптимизировать паттерны доступа к памяти

**Что такое demand paging и page replacement?**
- **Demand paging**: Страницы загружаются в RAM только при первом обращении
- **Page replacement**: Алгоритмы вытеснения страниц из RAM при нехватке памяти (LRU, Clock и др.)

### Memory Mapping

**Чем mmap() отличается от read()/write()? Когда mmap эффективнее?**
- **read()/write()**: Копирование данных между user-space и kernel-space
- **mmap()**: Прямой доступ к данным файла через память

**mmap эффективнее для**:
- Больших файлов (>100MB)
- Случайного доступа
- Нескольких процессов, работающих с одним файлом
- Интенсивной записи

**Что такое MAP_PRIVATE и MAP_SHARED? В чём разница?**
- **MAP_PRIVATE**: Изменения видны только текущему процессу (Copy-on-Write)
- **MAP_SHARED**: Изменения видны всем процессам и записываются в файл

**Что произойдёт, если обратиться к памяти за пределами отображённого файла?**
Возникнет сигнал `SIGBUS` (bus error) - доступ к несуществующей памяти.

**Как работает page cache и зачем он нужен?**
**Page cache** - кеш страниц в RAM для ускорения дискового I/O:
- При чтении файла данные кешируются в RAM
- Повторные чтения берутся из кеша
- Запись сначала идет в кеш, потом асинхронно на диск

### Файловый I/O

**Зачем нужна буферизация? Какие уровни буферизации существуют?**
**Буферизация нужна для**:
- Уменьшения количества системных вызовов
- Оптимизации дискового доступа
- Сглаживания пиковой нагрузки

**Уровни буферизации**:
1. User-space буфер (stdio)
2. Kernel page cache
3. Disk controller cache

**Почему маленький размер буфера замедляет I/O?**
- Увеличивает количество системных вызовов
- Неэффективное использование диска (много мелких операций)
- Большие накладные расходы

**Что такое O_DIRECT и O_SYNC? Когда их использовать?**
- **O_DIRECT**: Прямой I/O минуя page cache (для СУБД)
- **O_SYNC**: Синхронная запись - данные сразу на диск (для критичных данных)

**Чем отличается fwrite() от write()?**
- **fwrite()**: Библиотечная функция с буферизацией в user-space
- **write()**: Системный вызов, данные сразу в kernel (но все равно буферизуются в page cache)

### Файловая система

**Что такое inode и что в нём хранится?**
**inode** - структура с метаданными файла:
- Тип файла, права доступа
- Владелец, группа
- Размер, временные метки
- Количество ссылок
- Указатели на блоки данных

**Почему имя файла не хранится в inode?**
Имя файла хранится в директории (таблица имя→inode). Это позволяет:
- Одному файлу иметь несколько имен (hard links)
- Эффективно организовывать директории

**Чем жёсткая ссылка отличается от символьной?**
- **Жёсткая ссылка**: Дополнительная запись в директории, указывающая на тот же inode
- **Символьная ссылка**: Отдельный файл (свой inode), содержащий путь к целевому файлу

**Как в ext4 хранятся большие файлы (indirect pointers)?**
1. **12 прямых указателей** - для маленьких файлов
2. **Одинарный косвенный** - указатель на блок указателей
3. **Двойной косвенный** - указатель на блок указателей на блоки указателей
4. **Тройной косвенный** - для очень больших файлов

### Дисковое планирование

**Зачем нужны I/O schedulers?**
Для оптимизации порядка обработки запросов к диску:
- Уменьшение времени поиска (seek time)
- Предотвращение starvation
- Улучшение пропускной способности

**Чем отличаются FCFS, SSTF, SCAN?**
- **FCFS**: В порядке поступления (просто, но неэффективно)
- **SSTF**: Ближайший запрос к текущей позиции (риск starvation)
- **SCAN**: "Лифт" - в одном направлении до конца, потом обратно

**Какие I/O schedulers используются в современном Linux?**
- **mq-deadline**: Deadline-based с гарантиями
- **bfq**: Budget Fair Queueing - справедливое распределение
- **kyber**: Для NVMe SSD
- **none**: Без планировщика для очень быстрых устройств

**Почему для SSD планирование менее критично, чем для HDD?**
SSD не имеют механических частей:
- Нет времени поиска (seek time)
- Параллельный доступ к ячейкам
- Более равномерное время доступа

### Производительность

**Что такое фрагментация памяти? Внутренняя vs внешняя.**
- **Внутренняя фрагментация**: Неиспользуемая память внутри выделенного блока
- **Внешняя фрагментация**: Свободная память разбита на мелкие несмежные блоки

**Как swap влияет на производительность?**
- **Положительно**: Позволяет работать с большими наборами данных
- **Отрицательно**: Major faults очень медленные (дисковый I/O)

**Что такое thrashing и как его избежать?**
**Thrashing**: Система тратит больше времени на подкачку страниц, чем на полезную работу.

**Как избежать**:
- Увеличить RAM
- Оптимизировать working set
- Использовать mlock() для критичных страниц

**Почему последовательный доступ к памяти быстрее случайного?**
- **Кеш-память**: Предсказуемый доступ позволяет prefetch
- **TLB**: Локальность ссылок уменьшает промахи
- **Аппаратные оптимизации**: Burst mode, pipelining

**Что такое cache-friendly код?**
Код, учитывающий принципы локальности:
- **Пространственная локальность**: Обращение к соседним данным
- **Временная локальность**: Повторное использование данных
- Пример: Обход массивов по строкам, а не по столбцам
