### 3. Изучение /proc

**PID текущей оболочки:** 83196

**Исследование файлов /proc для PID 83196:**

**1. Командная строка:**
```bash

```
**Вывод:** `bash`

**Анализ:** Процесс представляет собой оболочку bash.

**2. Статус процесса:**
```bash
head -n 20 /proc/83196/status
```
**Ключевые поля:**
- **Name:** bash - имя процесса
- **State:** S (sleeping) - процесс находится в состоянии ожидания
- **Pid:** 83196 - идентификатор процесса
- **PPid:** 83186 - идентификатор родительского процесса (gnome-terminal)
- **Uid:** 1000 1000 1000 1000 - пользователь grant3d
- **Gid:** 1000 1000 1000 1000 - основная группа пользователя
- **VmSize:** 11280 kB - объем виртуальной памяти

**3. Открытые файловые дескрипторы:**
```bash
ls -l /proc/83196/fd
```
**Вывод:**
```
0 -> /dev/pts/0  # стандартный ввод (stdin)
1 -> /dev/pts/0  # стандартный вывод (stdout)  
2 -> /dev/pts/0  # стандартный вывод ошибок (stderr)
255 -> /dev/pts/0 # дополнительный дескриптор bash
```

**Анализ:** Все стандартные потоки ввода/вывода связаны с псевдо-терминалом `/dev/pts/0`.

**Выводы по исследованию /proc:**
- Процесс bash работает в фоновом режиме (состояние Sleeping)
- Имеет корректную связь с родительским процессом gnome-terminal
- Все файловые дескрипторы связаны с терминалом, что типично для интерактивной оболочки
- Процесс принадлежит пользователю grant3d (UID 1000)

## Ответы на вопросы для отчёта

1. **Чем процесс отличается от программы?**  
   Программа - это статичный исполняемый файл, а процесс - это выполняющийся экземпляр программы с собственным контекстом выполнения (PID, память, дескрипторы, состояние).

2. **Что будет, если вызвать fork() без wait()?**  
   Дочерний процесс станет "зомби" после завершения, пока родитель не вызовет wait() или не завершится сам. В моей системе наблюдается 0 zombie процессов.

3. **Как система хранит информацию о процессах?**  
   В таблице процессов ядра и через виртуальную файловую систему /proc, где каждый процесс имеет свою папку с файлами статуса, дескрипторов, памяти.

4. **Что делает exec() и зачем он нужен?**  
   Заменяет текущий образ процесса новым исполняемым файлом, сохраняя PID. Нужен для запуска новых программ в том же процессе.

5. **Почему в /proc нет «настоящих» файлов?**  
   Это виртуальная файловая система, которая предоставляет интерфейс для доступа к данным ядра в виде файлов.

6. **Как интерпретировать поля top: %CPU, %MEM, VIRT, RES, SHR, TIME+?**  
   - `%CPU`: Discord 127.3% - использует более одного ядра
   - `%MEM`: Firefox 13.2% - использует 13.2% доступной памяти
   - `VIRT`: виртуальная память процесса
   - `RES`: физическая память процесса
   - `SHR`: разделяемая память
   - `TIME+`: общее время CPU (Discord: 36 минут)

7. **Почему сумма %CPU может быть больше 100%?**  
   На многоядерных системах каждый процесс может использовать до 100% одного ядра. Discord показывает 127% - использует более одного ядра.

8. **Чем отличается мгновенное %CPU от load average?**  
   `%CPU` - текущая нагрузка конкретного процесса, `load average` - среднее количество процессов в очереди выполнения за 1, 5, 15 минут.

9. **Чем IO-нагрузка отличается от CPU-нагрузки?**  
   CPU-нагрузка - вычисления (Discord 137%), IO-нагрузка - операции с диском (Firefox 203 КБ/сек). Видно по разным инструментам мониторинга.

10. **Что такое nice/приоритеты процессов?**  
    Значение nice влияет на приоритет планировщика процессов. В выводах видно разные классы: `be/4` (best effort), `rt/4` (real-time).

11. **Чем поток отличается от процесса?**  
    Потоки разделяют адресное пространство процесса, процессы изолированы. В pidstat видно разные процессы с общим родителем.

12. **Что такое зомби и сироты, как они возникают?**  
    Зомби - завершенные процессы, ожидающие wait(); сироты - процессы, чей родитель завершился. В системе 0 zombie процессов.
