# Отчёт по лабораторной работе №2 — Процессы и файловая система /proc

---

## Цель работы

Изучить модель процессов Linux, понять, как создаются и завершаются процессы, а также научиться работать с виртуальной файловой системой `/proc`, отображающей состояние ядра и процессов.

---

## 1. Создание процессов

Была реализована программа `fork_example.py`, в которой родительский процесс порождает двух дочерних.  
Каждый дочерний выводит свой PID и PID родителя, затем завершает выполнение.  
Родитель после этого ожидает завершения обоих процессов с помощью `waitpid()` и печатает коды их выхода.

**Запуск программы:**
```bash
./run.sh
```

**Пример вывода:**
```
Parent: My PID is 2315
child_A: PID = 2316, PPID = 2315
child_B: PID = 2317, PPID = 2315
Parent: Child A (PID=2316) finished with status 0
Parent: Child B (PID=2317) finished with status 0
Parent: All children have finished
```

**Пример дерева процессов:**
```
parent(2315)
├─ child_A(2316)
└─ child_B(2317)
```

## 2. Исследование дерева процессов

Для исследования дерева процессов использовались команды:

```bash
ps -ef --forest | head -n 30 | cat
pstree -p | head -n 50 | cat
```

Обе команды показывают иерархию процессов.  
`ps --forest` отображает древовидную структуру в текстовом виде,  
а `pstree` визуализирует дерево в более наглядной форме с указанием PID.

---

## 3. Изучение /proc

С помощью PID текущего процесса (`echo $$`) были исследованы файлы каталога `/proc`.

- **/proc/<pid>/cmdline** — показывает командную строку, с которой был запущен процесс.  
  Пример вывода: `bash`

- **/proc/<pid>/status** — содержит информацию о состоянии процесса: PID, PPID, UID, приоритет, использование памяти и т.д.

- **/proc/<pid>/fd** — каталог с открытыми файловыми дескрипторами процесса.

Эти данные отражают текущее состояние процесса и формируются ядром динамически.

## 5. Ответы на вопросы

**1. Чем процесс отличается от программы?**  
Программа — статический файл с кодом; процесс — выполняющаяся копия программы с PID и контекстом.

**2. Что будет, если вызвать fork() без wait()?**  
Родитель не дождётся завершения потомка; при этом дочерний может стать зомби, пока не будет вызван `wait()`.

**3. Как система хранит информацию о процессах?**  
В ядре — структура `task_struct`; в пользовательском пространстве — виртуальные файлы `/proc/<pid>/`.

**4. Что делает exec() и зачем он нужен?**  
`exec()` заменяет текущий процесс новым образом программы, сохраняя PID.

**5. Почему в /proc нет настоящих файлов?**  
Это виртуальная файловая система, данные создаются ядром динамически при обращении.

**6. Как интерпретировать поля top (%CPU, %MEM, VIRT, RES, SHR, TIME+)?**  
- `%CPU` — использование CPU  
- `%MEM` — использование памяти  
- `VIRT` — виртуальная память  
- `RES` — физическая память  
- `SHR` — разделяемая память  
- `TIME+` — накопленное CPU-время  

**7. Почему сумма %CPU может быть больше 100%?**  
Каждое ядро — 100%; на 4-ядерной системе максимум 400%.

**8. Чем отличается %CPU от load average и что значит Cpu(s) в top?**  
`%CPU` — мгновенное использование; `load average` — среднее число активных процессов.  
`Cpu(s)` показывает распределение времени CPU (us, sy, ni, id, wa, hi, si, st).

**9. Чем IO-нагрузка отличается от CPU-нагрузки и как её увидеть?**  
IO — операции чтения/записи, CPU — вычисления.  
Смотреть через `pidstat -d`, `iotop`, `/proc/<pid>/io`.

**10. Что такое nice и приоритет процессов?**  
`nice` определяет приоритет планирования (-20…19).  
Чем меньше значение — тем чаще процесс получает процессорное время.

**11. Чем поток отличается от процесса и как их увидеть?**  
Потоки разделяют память внутри одного процесса.  
Команды: `ps -eLf`, `ps -T`, в `top` — клавиша `H`.

**12. Что такое зомби и сироты?**  
Зомби — завершившиеся, но не собранные процессы.  
Сироты — процессы без родителя, усыновляются `init`.
