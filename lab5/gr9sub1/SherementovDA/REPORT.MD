### Задание A: Hello World модуль 

**Код:** `hello_module.c`

**Функциональность:**
- Модуль успешно загружается и выгружается
- Поддерживает параметр `message` для кастомного сообщения
- Выводит сообщения в kernel log через `printk(KERN_INFO)`

**Тестирование:**

```bash
# Загрузка без параметра
sudo insmod hello_module.ko
# Вывод: Hello from Daniil module!

# Загрузка с параметром
sudo insmod hello_module.ko message="Custom_greeting_from_test"
# Вывод: Custom_greeting_from_test

# Выгрузка
sudo rmmod hello_module
# Вывод: Goodbye from Daniil module!
```

### Задание B: /proc файл с записью 

**Код:** `proc_module.c`

**Функциональность:**
- Создает файл `/proc/my_config` с правами 0666
- Реализованы операции чтения и записи
- Максимальная длина данных: 256 символов
- По умолчанию содержит "default"

**Тестирование:**

```bash
# Чтение начального значения
cat /proc/my_config
# Вывод: default

# Запись нового значения
echo "new test value" | sudo tee /proc/my_config
# Вывод: new test value

# Проверка записи
cat /proc/my_config
# Вывод: new test value
```

## Ответы на контрольные вопросы

### Базовые понятия:

#### 1. Что такое модуль ядра и зачем он нужен?

Модуль ядра - это фрагмент кода, который может быть динамически загружен и выгружен из ядра Linux во время работы системы. Нужен для добавления функциональности без перекомпиляции ядра (драйверы устройств, файловые системы, сетевые протоколы).

#### 2. Чем отличается kernel-space от user-space?

| Kernel-space | User-space |
|--------------|------------|
| Привилегированный режим | Непривилегированный режим |
| Полный доступ к аппаратуре | Ограниченный доступ |
| Крах приводит к kernel panic | Крах только одной программы |
| Нет стандартной библиотеки C | Есть стандартная библиотека C |

#### 3. Что произойдёт, если в модуле обратиться к NULL указателю?

Произойдет kernel panic - аварийное завершение работы ядра с последующей перезагрузкой системы.

#### 4. Почему нельзя использовать printf() в модуле ядра?

В kernel-space нет стандартной библиотеки C. Вместо `printf()` используется `printk()` для вывода в kernel log buffer.

#### 5. Что такое kernel panic и как его избежать?

Kernel panic - критическая ошибка ядра, приводящая к остановке системы. Чтобы избежать: проверять указатели, выделенную память, возвращаемые значения функций.

---

### Жизненный цикл модуля:

#### 6. Какие функции вызываются при insmod и rmmod?

- При `insmod` вызывается функция, зарегистрированная через `module_init()`
- При `rmmod` вызывается функция, зарегистрированная через `module_exit()`

#### 7. Что должна делать функция module_exit()?

Освобождать все ресурсы, выделенные в `module_init()`: память, регистрации устройств, /proc файлы и т.д.

#### 8. Что происходит, если module_init() возвращает ошибку?

Модуль не загружается, при этом `module_exit()` НЕ вызывается.

#### 9. Можно ли выгрузить модуль, если он используется?

Нет, появится ошибка "Module is in use". Нужно сначала закрыть все процессы, использующие модуль.

---

### Логирование и отладка:

#### 10. Чем printk() отличается от printf()?

| printk() | printf() |
|----------|----------|
| Вывод в kernel log | Вывод в stdout |
| Имеет уровни важности | Нет уровней важности |
| Не может блокироваться | Может блокироваться |
| Используется в ядре | Используется в user-space |

#### 11. Какие уровни логирования существуют в ядре?

- `KERN_EMERG (0)` - Аварийная ситуация
- `KERN_ALERT (1)` - Требует немедленных действий
- `KERN_CRIT (2)` - Критическая ошибка
- `KERN_ERR (3)` - Ошибка
- `KERN_WARNING (4)` - Предупреждение
- `KERN_NOTICE (5)` - Заметка
- `KERN_INFO (6)` - Информация
- `KERN_DEBUG (7)` - Отладка

#### 12. Как посмотреть логи модуля?

```bash
dmesg | tail -20
dmesg | grep "module_name"
journalctl -k
tail -f /var/log/kern.log
```

#### 13. Что означает "tainted kernel"?

Ядро помечено как "испорченное" из-за загрузки проприетарного модуля или модуля без правильной лицензии.

---

### Память:

#### 14. Чем kmalloc() отличается от malloc()?

| kmalloc() | malloc() |
|-----------|----------|
| Выделяет в kernel-space | Выделяет в user-space |
| Физически непрерывная память | Виртуальная память |
| Не может использовать swap | Может использовать swap |
| Флаги GFP_KERNEL/GFP_ATOMIC | Без специальных флагов |

#### 15. Что такое флаги GFP и зачем они нужны?

Флаги Get Free Pages определяют условия выделения памяти:
- `GFP_KERNEL` - обычное выделение (может спать)
- `GFP_ATOMIC` - атомарное выделение (для прерываний, не может спать)
- `GFP_USER` - для user-space данных

#### 16. Что произойдёт, если не освободить память в module_exit()?

Произойдет утечка памяти - память будет потеряна до перезагрузки системы.

#### 17. Почему нельзя использовать user-space указатели напрямую в ядре?

User-space указатели могут быть невалидными в контексте ядра. Нужно использовать `copy_to_user()` и `copy_from_user()` для безопасного копирования.

---

### Взаимодействие с user-space:

#### 18. Что такое /proc и для чего он используется?

Виртуальная файловая система для экспорта информации из ядра в user-space. Используется для чтения системной информации и конфигурации.

#### 19. Что такое /sys (sysfs) и чем отличается от procfs?

**ProcFS:**
- Историческая система
- Разные форматы данных
- Используется для различной системной информации

**SysFS:**
- Современная система
- Один файл = одно значение
- Используется для конфигурации устройств

#### 20. Зачем нужны функции copy_to_user() и copy_from_user()?

Для безопасного копирования данных между kernel-space и user-space с проверкой прав доступа и валидности указателей.

#### 21. Что такое character device и как он работает?

Устройство, с которым можно работать как с файлом (`/dev/...`). Реализует операции open, close, read, write через структуру `file_operations`.

### Параметры и метаданные:

#### 22. Как передать параметры модулю при загрузке?

```bash
sudo insmod module.ko param_name=value
```

#### 23. Зачем нужен MODULE_LICENSE()?

Для указания лицензии модуля. Без GPL лицензии ядро помечается как tainted, некоторые API недоступны.

#### 24. Что произойдёт, если не указать лицензию?

Модуль будет работать, но ядро пометится как "tainted", некоторые функции ядра будут недоступны.

---

### Безопасность:

#### 25. Какие основные правила безопасного кода в ядре?

- Всегда проверять возвращаемые значения
- Освобождать все ресурсы в exit
- Использовать `copy_to/from_user()`
- Проверять границы массивов
- Не использовать стандартную библиотеку C
- Не использовать числа с плавающей точкой
- Не делать бесконечные циклы
- Не обращаться к user-space указателям напрямую

#### 26. Можно ли использовать бесконечный цикл в модуле?

Нет, это может заблокировать систему, особенно в обработчике прерываний.

#### 27. Почему в ядре нет FPU операций?

FPU (Floating Point Unit) операции требуют сохранения состояния и медленные. В ядре используют целочисленные вычисления для эффективности.

#### 28. Что делать, если модуль вызвал kernel panic?

1. Перезагрузить систему
2. Проанализировать код
3. Найти ошибку (обращение к NULL, утечка и т.д.)
4. Исправить и повторить тест
