## Обязательные вопросы для отчёта:

1. **Модуль ядра (Kernel Module)** — фрагмент кода, который может быть динамически загружен и выгружен из ядра Linux во время работы системы без перезагрузки. Нужен для добавления драйверов устройств, файловых систем, сетевых протоколов.

2. **Kernel Space** — привилегированное пространство ядра с полным доступом к аппаратуре, крах приводит к kernel panic. **User Space** — непривилегированное пространство пользовательских программ с ограниченным доступом, крах только одной программы.

3. При обращении к NULL указателю в модуле произойдёт **kernel panic** — аварийное завершение работы ядра.

4. Нельзя использовать **printf()** в модуле ядра, потому что в kernel-space нет стандартной библиотеки C. Вместо этого используется **printk()** для вывода в kernel log buffer.

5. **Kernel panic** — аварийное завершение ядра при критической ошибке. Чтобы избежать: проверять указатели, выделенную память, возвращаемые значения функций.

6. При **insmod** вызывается **module_init()**, при **rmmod** — **module_exit()**.

7. **module_exit()** должна освобождать все ресурсы, выделенные в module_init() (память, регистрации устройств, /proc файлы).

8. Если **module_init()** возвращает ошибку (не 0), модуль не загружается и **module_exit()** не вызывается.

9. Нельзя выгрузить модуль, если он используется (заняты устройства, открыты файлы). Нужно сначала закрыть все использующие процессы.

10. **printk()** выводит в kernel log buffer, просмотр через dmesg; **printf()** — в stdout. printk имеет уровни важности (KERN_INFO, KERN_ERR).

11. Уровни логирования: KERN_EMERG, KERN_ALERT, KERN_CRIT, KERN_ERR, KERN_WARNING, KERN_NOTICE, KERN_INFO, KERN_DEBUG.

12. Логи модуля смотрят через **dmesg**, /var/log/kern.log, journalctl -k.

13. **"Tainted kernel"** — ядро "испорчено" загрузкой проприетарного модуля или модуля без правильной лицензии.

14. **kmalloc()** выделяет физическую память в kernel-space, **malloc()** — виртуальную в user-space.

15. **Флаги GFP** (Get Free Pages): GFP_KERNEL — обычное выделение (может спать), GFP_ATOMIC — атомарное (для прерываний, не спит).

16. Если не освободить память в module_exit(), произойдёт **утечка памяти** — потеря памяти до перезагрузки.

17. Нельзя использовать user-space указатели напрямую в ядре — это вызовет kernel panic. Нужно использовать **copy_from_user()** и **copy_to_user()**.

18. **/proc** — виртуальная ФС для экспорта информации из ядра в user-space (например, /proc/cpuinfo).

19. **/sys (sysfs)** — современный способ экспорта атрибутов устройств и параметров (один файл = одно значение). **procfs** — более общий, для различной информации.

20. **copy_to_user()** и **copy_from_user()** нужны для безопасного копирования данных между kernel-space и user-space.

21. **Character device** — устройство, с которым можно работать как с файлом (/dev/null, /dev/random). Регистрируется через alloc_chrdev_region(), cdev_init(), cdev_add().

22. Параметры передаются при загрузке: `insmod module.ko param=value`. Объявляются через module_param().

23. **MODULE_LICENSE()** обязателен для указания лицензии. Без этого ядро будет "tainted", некоторые функции ядра недоступны.

24. Без лицензии модуль будет работать, но ядро пометится как "tainted", некоторые API будут недоступны.

25. Основные правила: проверять возвращаемые значения, освобождать ресурсы в exit, использовать copy_to/from_user(), проверять границы, не использовать стандартную библиотеку C.

26. **Нельзя** делать бесконечные циклы в модуле — это может заблокировать систему.

27. В ядре **нет FPU** (floating point unit) операций, потому что FPU операции не атомарны и могут быть прерваны, что сложно обрабатывать в kernel-space, большинство операций ядра используют целочисленную арифметику, нет необходимости в операциях с плавающей точкой в kernel-space.

28. Если модуль вызвал kernel panic: перезагрузить VM (модуль не загрузится автоматически), проверить код, исправить ошибку, попробовать снова.

29. Загруженные модули можно посмотреть через **lsmod**, /proc/modules.

30. Информацию о модуле можно получить через **modinfo module.ko**, параметры — в /sys/module/module_name/parameters/.
