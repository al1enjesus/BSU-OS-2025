# Лабораторная работа №5
## Разработка модулей ядра Linux (LKM): параметры, procfs, символьные устройства

# 1. Цель работы и выполненные задания

Цель лабораторной работы — изучить разработку модулей ядра Linux и механизмов взаимодействия ядра с пользовательским пространством. В рамках работы были выполнены следующие задачи:

- Подготовка окружения для сборки LKM.
- Разработка трёх модулей ядра:
  1. *hello_module* — модуль с параметром `message`.
  2. *proc_module* — создание виртуального файла `/proc/student_info`.
  3. *chardev_module* — создание символьного устройства `/dev/mychardev`.
- Сборка модулей с использованием Makefile и системной подсистемы сборки ядра.
- Тестирование загрузки/выгрузки модулей (`insmod`, `rmmod`).
- Анализ логов ядра с помощью `dmesg`.
- Проверка чтения/записи в `/proc`.
- Создание символьного устройства `mknod`, тестирование read/write.
- Документирование результатов.

## 2.3 Реализация hello_module
- Объявлен параметр:
```
module_param(message, charp, 0644);
```
- Если параметр не передан — выводятся ФИО, группа.
- Если передан — выводится пользовательское сообщение.
- В вывод используются сообщения `printk(KERN_INFO, ...)`.

Команды тестирования:
```
sudo insmod hello_module.ko
sudo insmod hello_module.ko message=RozhdaevEV\ says\ hi
sudo rmmod hello_module
sudo dmesg | tail
```

## 2.4 Реализация proc_module
Модуль создаёт файл `/proc/student_info`.  
При каждом чтении увеличивается счётчик обращений.

Используемые функции ядра:
- `proc_create`
- `single_open`
- `seq_printf`
- `remove_proc_entry`

Тестирование:
```
sudo insmod proc_module.ko
cat /proc/student_info
cat /proc/student_info
sudo rmmod proc_module
```

## 2.5 Реализация chardev_module
Реализовано символьное устройство:
- выделение динамического major-номера (`alloc_chrdev_region`)
- регистрация `cdev` (`cdev_init`, `cdev_add`)
- буфер внутри драйвера (1024 байта)
- операции `read` и `write`

Тестирование:
```
sudo insmod chardev_module.ko
sudo mknod /dev/mychardev c <major> 0
sudo chmod 666 /dev/mychardev
echo "Hello" > /dev/mychardev
cat /dev/mychardev
sudo rm /dev/mychardev
sudo rmmod chardev_module
```

# 3. Ответы на 30 вопросы

**1. Что такое модуль ядра?**  
Динамически загружаемый компонент ядра, расширяющий его функциональность.

**2. Можно ли загружать модули без перезагрузки ядра?**  
Да, с помощью `insmod`, `modprobe`.

**3. Чем отличается монолитное ядро от модульного?**  
Монолитное включает всё в себя, модульное позволяет подгружать части.

**4. Что делает insmod?**  
Загружает модуль в ядро без разрешения зависимостей.

**5. Что делает rmmod?**  
Удаляет модуль из ядра.

**6. Что делает modprobe?**  
Загружает модуль с учётом зависимостей.

**7. Что такое syscall?**  
Механизм взаимодействия пользователя и ядра.

**8. Что такое printk?**  
Функция вывода сообщений из ядра.

**9. Куда выводится printk?**  
В буфер ядра, читаемый через `dmesg`.

**10. Что такое dmesg?**  
Утилита просмотра сообщений ядра.

**11. Что такое /proc?**  
Виртуальная файловая система состояния ядра.

**12. Как создать файл в /proc?**  
С помощью `proc_create()`.

**13. Как удалить файл из /proc?**  
Через `remove_proc_entry()`.

**14. Что такое seq_file?**  
API ядра для вывода данных в /proc.

**15. Что такое символьное устройство?**  
Устройство с последовательным доступом (read/write).

**16. Что такое major/minor?**  
Major — тип драйвера; minor — конкретный экземпляр.

**17. Как создать символьное устройство?**  
Через `mknod /dev/name c major minor`.

**18. Что делает copy_to_user?**  
Копирует данные из ядра в user space.

**19. Что делает copy_from_user?**  
Копирует данные из user space в ядро.

**20. Почему нельзя обращаться напрямую в память пользователя?**  
Из-за защиты памяти и сегментации.

**21. Что такое cdev?**  
Структура ядра для описания символьного устройства.

**22. Как зарегистрировать cdev?**  
`cdev_init(); cdev_add();`

**23. Что делает alloc_chrdev_region?**  
Выделяет диапазон устройств и major-номер.

**24. Что такое sysfs?**  
Файловая система для атрибутов устройств.

**25. Когда вызывается init-функция модуля?**  
При загрузке (insmod).

**26. Когда вызывается exit-функция модуля?**  
При выгрузке (rmmod).

**27. Можно ли модулю использовать printf?**  
Нет, только printk.

**28. Можно ли использовать malloc в ядре?**  
Нет, нужно использовать `kmalloc/kfree`.

**29. Что такое license в модуле?**  
Определяет лицензию (GPL), влияет на экспорт символов.

**30. Что произойдёт при загрузке модуля без GPL лицензии?**  
Некоторые функции ядра станут недоступны.
