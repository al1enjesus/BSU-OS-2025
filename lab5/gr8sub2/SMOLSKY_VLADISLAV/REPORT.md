# Лабораторная 5 — Модули ядра Linux
Практика по разработке модулей ядра Linux: изучим архитектуру ядра, напишем простые модули, научимся взаимодействовать с user-space через `/proc` и `/sys`, создадим базовый character device.
#### Окружение
	VirtualBox с Ubuntu 22.04
#### Использование
```bash
make # сборка
sudo insmod src/<module_name>.ko # загрузка модуля
sudo rmmod <module_name> # выгрузка
```
## Задание A: Модуль «Hello World» с параметром
#### Цель задания  
Создать простой загружаемый модуль ядра Linux, который при загрузке выводит приветственное сообщение, при выгрузке — прощальное, а также может принимть параметр message и использовать его вместо стандартного текста.
#### Решение и результаты  
Модуль реализован в файле `hello_module.c`.  
Код использует:  
- module_param(message, charp, 0644)  
- printk(KERN_INFO ...) в функциях init и exit  
- проверку, задан ли параметр 

Результаты выполнения команд:
```bash
$ sudo insmod src/hello_module.ko
$ lsmod | grep hello_module
hello_module           12288  0

$ sudo rmmod hello_module

$ sudo insmod src/hello_module.ko message=Custom_greeting
$ sudo rmmod hello_module

$ sudo dmesg | tail -4
[ 4571.795534] hello_module: Hello from Vladislav module!
[ 4759.436115] hello_module: Goodbye from Vladislav module!
[ 4762.808725] hello_module: Custom_greeting
[ 4768.909888] hello_module: Goodbye from Vladislav module!
```
#### Как проверяли  
1. Загрузка без параметра → приветствие по умолчанию  
2. Проверка наличия модуля через lsmod  
3. Выгрузка  
4. Загрузка с параметром message=Custom_greeting → вывод переданного текста  
5. Выгрузка и проверка dmesg
#### Ключевые выводы  
- Механизм module_param позволяет передавать строки в модуль при загрузке  
- Сообщения printk с уровнем KERN_INFO корректно попадают в журнал ядра  
- Модуль регистрируется в системе и отображается в lsmod  
- При наличии параметра он полностью заменяет стандартное сообщение
## Задание B: /proc файл с возможностью записи
#### Цель задания
Создать модуль ядра, который создаёт файл `/proc/my_config` со следующими свойствами:
- По умолчанию содержит строку "default"
- Поддерживает запись (через `echo ... > /proc/my_config`)
- После записи при чтении возвращает новое значение
- Максимальная длина строки — 256 символов
- Права доступа 0666, реализация через `proc_create()` и собственные `proc_read`/`proc_write`
- Использование `copy_from_user()` при записи
#### Решение и результаты
Модуль реализован в файле `proc_module.c`.  
Ключевые элементы:
- Глобальный буфер `config_data[MAX_LEN]` и переменная длины
- Автоматическое удаление `\n` в конце при записи через `echo`
- Обрезка при превышении 255 символов (возврат `-EINVAL`)
- Сообщения о создании/удалении файла через `printk`

Результаты выполнения команд:
```bash
$ sudo insmod src/proc_module.ko

$ cat /proc/my_config
default

$ echo "new value" > /proc/my_config

$ cat /proc/my_config
new value

$ sudo rmmod proc_module

$ sudo dmesg | tail -2
[ 2122.417175] my_config: /proc/my_config created successfully
[ 2658.695221] my_config: /proc/my_config removed
```
#### Как проверяли
1. Загрузка модуля и проверка начального содержимого  
2. Запись нового значения через перенаправление  
3. Повторное чтение — значение успешно изменилось  
4. Выгрузка модуля, проверка сообщений в dmesg 
#### Ключевые выводы
- Интерфейс `/proc` позволяет легко реализовать пользовательские файлы с чтением/записью
- `copy_from_user()` — безопасный способ получения данных из пользовательского пространства  
- Использование прав 0666 даёт возможность записи любому пользователю 
## Задание C: /proc файл со статистикой системы
#### Цель задания  
Создать модуль ядра, который создаёт файл `/proc/sys_stats`, при чтении выводящий в читаемом виде актуальную информацию о системе:  
- количество запущенных процессов  
- объём используемой оперативной памяти (в МБ)  
- время работы системы (uptime) в секундах  
#### Решение и результаты  
Модуль реализован в файле `sys_stat_module.c` с использованием `simple_read_from_buffer()`

Ключевые особенности реализации:  
- Данные собираются каждый раз при чтении файла (функция `update_stats()`)  
- Количество процессов — цикл `for_each_process()`  
- Память — `si_meminfo()` + расчёт "используемой" памяти  
- Uptime — `get_jiffies_64()` → `jiffies_to_msecs()`  
- Вывод формируется в статический буфер, затем отдаётся пользователю через `simple_read_from_buffer()`  
- Файл создаётся с правами 0444 (только чтение)  

Результаты выполнения команд:
```bash
$ sudo insmod src/sys_stat_module.ko

$ cat /proc/sys_stats
Processes:      234
Memory Used:    1724 MB
System Uptime:  4294777 seconds

$ cat /proc/sys_stats
Processes:      234
Memory Used:    1721 MB
System Uptime:  4294780 seconds

$ cat /proc/sys_stats
Processes:      234
Memory Used:    1722 MB
System Uptime:  4294782 seconds

$ ps aux | wc -l
236

$ sudo rmmod sys_stat_module

$ sudo dmesg | tail -2
[ 3041.232977] sys_stats: /proc/sys_stats created (simple version)
[ 3106.491907] sys_stats: module unloaded
```
#### Как проверяли  
1. Загрузка модуля  
2. Многократный `cat /proc/sys_stats` — проверка динамического обновления uptime и памяти  
3. Сравнение количества процессов с выводом `ps aux | wc -l`. В проверке показывает на два процесса больше, т.к. в это время выполняются команды самой проверки (`ps`, `wc`).
4. Выгрузка модуля и проверка сообщений в dmesg  
#### Ключевые выводы 
- Данные обновляются при каждом чтении, что обеспечивает актуальность статистики  
- `for_each_process()`, `si_meminfo()` и `jiffies` — стандартные и безопасные механизмы получения системной информации
## Вопросы для отчета
### Базовые понятия:
1. Это фрагмент кода, который может быть динамически загружен и выгружен из ядра Linux во время работы системы без необходимости перезагрузки. Нужен для упращения работы
2. kernel-sapce (пространство ядра) имеет полный доступ ко всему (память, процессор, устройства), ошибка вызывает kernel panic, в нем нельзя использовать стандартную библиотеку C
3. Произойдет kernel panic
4. `printf()` относится к стандартной бибилиотеке C
5. Это фатальная ошибка, которая приводит к краху всей системы
### Жизненный цикл модуля:
6. Функции зарегистрированные через `module_init()` и `module_exit()`
7. Регистрирует функцию, которая вызовется при выгрузке ядра.
8. Завершает работу (функция выгрузки \_\_exit не вызовется)
9. Нельзя
### Логирование и отладка:
10. `printk()` можно использовать в kernel-space
11. 0 - Аварийная, 1 - Требует действий, 2 - Критическая, 3 - Ошибка, 4 - Предупреждение, 5 - Заметка, 6 - Информация, 7 - Отладка
12. `dmesg`, файлы логов, `journalctl`
13. "испорченное" ядро
### Память:
14. kmalloc() выделяет физически непрерывную память в ядре, malloc() — виртуальную в user-space.
15. GFP — флаги, указывающие, как выделять память (можно ли спать, из какого пула). Например: GFP_KERNEL — можно спать, GFP_ATOMIC — нельзя спать.
16. Утечка памяти в ядре, останется занятой до перезагрузки.
17. Указатель может быть невалидным, в swap или недоступным — прямое обращение = kernel panic.
### Взаимодействие с user-space:
18. Виртуальная ФС, через которую ядро отдаёт информацию и принимает команды от user-space.
19. Современная ФС для атрибутов устройств и параметров ядра; «один файл = одно значение», более строгая и структурированная, чем /proc.
20. Безопасно копируют данные между kernel-space и user-space, проверяют валидность указателей.
21. Устройство, с которым работают как с обычным файлом (/dev/...); поддерживает open, read, write, close.
### Параметры и метаданные:
22. Через командную строку: insmod module.ko param="value" или через /sys/module/module/parameters/param.
23. Указывает лицензию модуля, даёт доступ к GPL-символам ядра.
24. Ядро помечается как tainted (испорченное), некоторые функции ядра становятся недоступны.
### Безопасность:
25. Проверять все возвращаемые значения, освобождать все ресурсы в exit, не использовать стандартную libc, всегда использовать copy_to/from_user, проверять границы.
26. Нельзя — заблокирует ядро или вызовет зависание системы.
27. В ядре отключён FPU для экономии контекста; операции с плавающей точкой запрещены.
28. Перезагрузить VM, исправить ошибку в коде (обычно NULL pointer или неверный user-space указатель), загрузить заново.
### Практические вопросы:
29. lsmod, cat /proc/modules.
30. modinfo имя_модуля.ko или modinfo имя_модуля (если уже загружен).
