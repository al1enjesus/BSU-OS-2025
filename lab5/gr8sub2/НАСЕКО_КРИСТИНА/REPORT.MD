# Лабораторная 4 — Модули ядря Linux
Практика по разработке модулей ядра Linux: изучение архитектуры ядра, написание простых модулей, научиться взаимодействовать с user-space через /proc и /sys.

## Цели
- Создание простого модуля "Hello World".
- Создание модуля, который регистрирует файл в /proc с возможностью чтения и записи.
- Создание модуля, который собирает и выводит статистику системы (память, процессы, uptime).

Ubuntu 24.04.3 на VirtualBox.

Вариант для лабораторной работы - 2.

## Задания

### A)  Hello World модуль
Цель: создать простой модуль, который: 1. при загрузке (insmod) выводит "Hello from [ВАШ_ИМЯ] module!"; 2. при выгрузке (rmmod) выводит "Goodbye from [ВАШ_ИМЯ] module!"; 3. принимает параметр message (строка); 4. если параметр задан, выводит его вместо дефолтного сообщения

Шаги/решения:
    - Реализовать модуль
    - Тестирование созданнового модуля.
    
Код:
    Представлен в файле hello_module.c - работа с файлом с помощью Makefile.

Команды:
~~~
    sudo insmod hello_module.ko
    sudo dmesg | tail -1
    sudo rmmod hello_module
    sudo dmesg | tail -1
~~~
  
Результат:
~~~
    [ 2212.585217] hello_module: Hello from Chris module!
    [ 2212.620622] hello_module: Goodbye from Chris module!
~~~

Команды:
~~~
    sudo rmmod hello_module message "Testing"
    sudo dmesg | tail -1
~~~

Результат:
~~~
    [ 2324.343656] hello_module: Custom message: Testing
~~~

Выводы:
  Модуль работает корректно - выводит базовое сообщение или кастомное, если оно указано. Если было указано кастомное сообщение при выгрузке - эта часть команды просто игнорируется и выполняется без ошибки. Если же загрузка была с кастомным сообщением, то при выгрузке напишется про это - "hello_module: Goodbye! Module was running in custom mode.\n".

## Ответы на вопросы
Базовые понятия:
1. Модуль ядра — это загружаемый фрагмент кода, расширяющий функциональность ядра без необходимости его перекомпиляции и перезагрузки.

2. Kernel-space работает с полными привилегиями и управляет оборудованием; ошибка там приводит к падению системы. User-space ограничен, ошибки затрагивают только процесс.

3. Произойдёт kernel panic.

4. Потому что стандартная библиотека C отсутствует в ядре.

5. Kernel panic — критическая ошибка ядра, приводящая к остановке системы.


Жизненный цикл модуля:
6. module_init() — при insmod, module_exit() — при rmmod.

7. Освобождать все ресурсы: память, /proc и /sys файлы, устройства, таймеры и т.д.

8. Модуль не загружается, а module_exit() не вызывается — нужно самостоятельно очистить уже выделенные ресурсы.

9. Нет, ядро вернёт ошибку «module is in use».


Логирование и отладка:
10. printk() пишет в буфер логов ядра и использует уровни важности; работает в kernel-space.

11. От KERN_EMERG (0) до KERN_DEBUG (7).

12. dmesg, journalctl -k, либо /var/log/kern.log.

13. Ядро считается «испорченным», если загружены непроверенные, проприетарные или некорректные модули.


Память:
14. kmalloc() выделяет физически непрерывную память в kernel-space и использует флаги GFP; malloc() работает в виртуальной памяти user-space.

15. Определяют условия выделения памяти: можно ли спать, тип памяти, контекст (обычный, прерывания, DMA и т.д.).

16. Возникнет утечка памяти, которая сохранится до перезагрузки.

17. Это опасно: пользователь мог передать невалидный адрес → kernel panic. Используются copy_to_user() и copy_from_user().


Взаимодействие с user-space:
18. Виртуальная ФС для экспорта состояния ядра и модулей, удобна для диагностики и информации. 

19. Sysfs — объектно-ориентированная ФС для устройств и параметров. Procfs — больше информационная и традиционная.

20. Для безопасного копирования данных между user-space и kernel-space.

21. Потоковое символьное устройство, доступное через файловые операции (open, read, write), представленное файлом в /dev.


Параметры и метаданные:
22. Через insmod module.ko param=value и объявление module_param() в коде.

23. Чтобы ядро понимало, что модуль совместим с GPL; это влияет на доступ к API и состояние tainted.

24. Ядро пометит себя как tainted, а часть GPL-only символов станет недоступной.


Безопасность:
25. Проверять указатели и возвраты, корректно освобождать ресурсы, не блокировать ядро, использовать безопасные функции доступа к памяти.

26. Нет, это заблокирует ядро и вызовет зависание или panic.

27. Сохранение и восстановление FPU контекста дорогое и сложное; ядро обычно работает без FPU.

28. Перезагрузить систему, исправить код, проверить логи и загрузочные параметры, попробовать снова в безопасной среде (VM).


Практические вопросы:
29. lsmod, cat /proc/modules

30. modinfo module.ko
