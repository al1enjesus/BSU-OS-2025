##  Задача А: Hello World модуль

Необходимо создать простой модуль, который выполняет вывод сообщений при загрузке (`insmod`) и выгрузке (`rmmod`).

### 1\. Сборка и загрузка

Сборка модуля осуществляется командой `make`.

**Загружаем модуль:**

```bash
sudo insmod hello_module.ko
```

**Просматриваем логи:**

```bash
sudo dmesg | tail
```

**Вывод лога:**

```text
[29027.720429] hello_module: Hello from Dashka module!
[29027.720436] hello_module: Module loaded successfully
```

### 2\. Выгрузка

**Выгружаем модуль:**

```bash
sudo rmmod hello_module.ko
```

**Логи после выгрузки:**

```text
[29009.014673] hello_module: Goodbye from Dashka module!
[29009.014679] hello_module: Module unloaded successfully
```

### 3\. Работа с параметрами

Проделаем операцию с параметрами.

**Логи:**

```text
[29009.014679] hello_module: CustomGreeting
[29027.720429] hello_module: Module loaded successfully
```

Посмотрим переменную через sysfs:

```bash
cat /sys/module/hello_module/parameters/message
```

**Вывод:** `CustomGreeting`

##  Задача C: Простой character device

Создаем символьное устройство.

**Инициализация:**

```bash
make
sudo insmod chardev_module.ko
```

**Логи загрузки:**

```text
[31762.599416] chardev: Initializing
[31762.599429] chardev: Registered with major number 240
[31762.599433] chardev: Create device with: mknod /dev/mychardev c 240 0
```

*О прелесть\!*

### Цепочка действий:

1.  **Создание узла устройства** (используем Major number 240 из логов):

    ```bash
    sudo mknod /dev/mychardev c 240 0
    ```

2.  **Выдача прав** (chmod 666):

    ```bash
    sudo chmod 666 /dev/mychardev
    ```

3.  **Запись в устройство:**

    ```bash
    echo "Hello" > /dev/mychardev
    ```

    *Логи ядра:*

    ```text
    [32223.563711] chardev: Device opened
    [32223.563740] chardev: Write request
    [32223.563747] chardev: Device closed
    ```

4.  **Чтение из устройства:**

    ```bash
    cat /dev/mychardev
    ```

    **Вывод:** `Hello`

5.  **Логи чтения:**

    ```text
    [32235.960378] chardev: Device opened
    [32235.960408] chardev: Read request
    [32235.960512] chardev: Read request
    [32235.960533] chardev: Device closed
    ```

6.  **Финальная выгрузка:**

    ```bash
    sudo rmmod chardev_module.ko
    ```

    *Лог:* `[32899.343503] chardev: Device unregistered`

#  Ответы на контрольные вопросы

## I. Базовые понятия

**1. Что такое модуль ядра и зачем он нужен?**
Модуль ядра (Loadable Kernel Module, LKM) — это объектный файл, содержащий код, который может быть **загружен в ядро** (или выгружен из него) во время работы системы без необходимости перезагрузки. Он нужен для **расширения функциональности ядра** (например, добавления драйверов устройств или файловых систем) по требованию, сохраняя размер основного образа ядра минимальным.

**2. Чем отличается kernel-space от user-space?**
Это два разных режима работы процессора, обеспечивающие защиту памяти и оборудования.

  * **User-space (Пространство пользователя):** Ограниченный режим (обычно Ring 3), где работают обычные приложения. У них нет прямого доступа к оборудованию и памяти ядра.
  * **Kernel-space (Пространство ядра):** **Привилегированный режим** (Ring 0), где работает ядро и модули. Здесь разрешен полный доступ ко всей памяти и всем инструкциям процессора. Сбой в этом пространстве может обрушить всю систему.

**3. Что произойдёт, если в модуле обратиться к NULL указателю?**
Произойдет **Kernel Oops** или **Kernel Panic**. В пространстве ядра отсутствует механизм `Segmentation Fault`, поэтому обращение по неверному адресу (0x0) приводит к **критической ошибке**, которая часто требует перезагрузки системы.

**4. Почему нельзя использовать `printf()` в модуле ядра?**
Функция `printf()` является частью **стандартной библиотеки C (glibc)**, которая доступна только в user-space. Ядро Linux не линкуется с пользовательскими библиотеками. Вместо этого используется функция ядра для логирования — `printk()`.

**5. Что такое kernel panic и как его избежать?**
**Kernel panic** — это фатальная ошибка, при которой ядро не может безопасно продолжить работу и **останавливает систему** во избежание повреждения данных.
*Как избежать:* Проверять указатели на NULL, корректно обрабатывать ошибки функций и правильно использовать блокировки.

## II. Жизненный цикл модуля

**6. Какие функции вызываются при `insmod` и `rmmod`?**

  * `insmod` (загрузка) -\> вызывает функцию с макросом **`module_init()`**.
  * `rmmod` (выгрузка) -\> вызывает функцию с макросом **`module_exit()`**.

**7. Что должна делать функция `module_exit()`?**
Она должна выполнить **полную очистку** ресурсов: освободить память (`kfree`), удалить устройства, отменить регистрацию прерываний и удалить записи в `/proc`/`/sys`.

**8. Что происходит, если `module_init()` возвращает ошибку?**
Модуль **не загружается**. Функция `module_exit()` **не вызывается**. Разработчик должен сам освободить ресурсы внутри `module_init()` перед возвратом ошибки.

**9. Можно ли выгрузить модуль, если он используется?**
По умолчанию — **нет**, если счетчик ссылок (reference count) больше нуля. Принудительная выгрузка (`rmmod -f`) возможна, но опасна.

-----

## III. Логирование и отладка

**10. Чем `printk()` отличается от `printf()`?**

  * **Место:** `printk` в ядре, `printf` в user-space.
  * **Вывод:** `printk` пишет в **кольцевой буфер ядра**, а не в stdout.
  * **Уровни:** `printk` поддерживает уровни важности (loglevels).

**11. Какие уровни логирования существуют в ядре?**
8 уровней: `KERN_EMERG` (система неработоспособна) ... до ... `KERN_DEBUG` (отладка).

**12. Как посмотреть логи модуля?**

  * Команда `dmesg`.
  * Файлы `/var/log/kern.log` или `/var/log/syslog`.
  * Команда `journalctl -k`.

**13. Что означает "tainted kernel"?**
Ядро помечено как "запятнанное" (находится в неподдерживаемом состоянии). Причины: загрузка проприетарного модуля, принудительная выгрузка, критическая ошибка.

-----

## IV. Память

**14. Чем `kmalloc()` отличается от `malloc()`?**

  * `kmalloc` — kernel-space, физически непрерывная память.
  * `malloc` — user-space, виртуальная память.

**15. Что такое флаги GFP?**
Флаги контекста выделения памяти:

  * `GFP_KERNEL`: Может спать (для процессов).
  * `GFP_ATOMIC`: Не может спать (для прерываний).

**16. Что произойдёт, если не освободить память в `module_exit()`?**
**Утечка памяти ядра**. Память останется занятой до перезагрузки ОС.

**17. Почему нельзя использовать user-space указатели напрямую?**
Из-за разной адресации и безопасности. Нужно использовать `copy_to_user()` / `copy_from_user()`.

-----

## V. Взаимодействие с user-space

**18. Что такое `/proc`?**
Виртуальная ФС для информации о процессах и состоянии ядра. Генерируется на лету.

**19. Что такое `/sys` (sysfs) и отличие от procfs?**
Структурированная виртуальная ФС для объектов ядра (драйверы, устройства). `/sys` более упорядочена (один файл — одно значение), чем `/proc`.

**20. Зачем нужны `copy_to_user()` и `copy_from_user()`?**
Для **безопасного** копирования данных между ядром и пользователем (проверка адресов, обработка ошибок).

**21. Что такое character device?**
Устройство с последовательным доступом (как поток байтов). Работает через системные вызовы `open`, `read`, `write`.

-----

## VI. Параметры, метаданные и безопасность

**22. Как передать параметры?**
При загрузке: `insmod mod.ko param=val`. В коде: макрос `module_param`.

**23-24. Лицензия (`MODULE_LICENSE`)**
Нужна для юридической чистоты и доступа к GPL-символам. Без нее ядро станет **"tainted"**.

**25. Правила безопасности:**
Валидация ввода, безопасное копирование, использование блокировок, избегание долгих операций в прерываниях.

**26. Бесконечный цикл?**
**Запрещен.** Приведет к зависанию ядра (deadlock/lockup).

**27. Почему нет FPU?**
Слишком дорого сохранять регистры плавающей точки при переключении контекста. Отключен для скорости.

**28. Если случился kernel panic?**
Перезагрузка -\> Анализ логов (`dmesg`, `kdump`) -\> Поиск ошибки в коде.
