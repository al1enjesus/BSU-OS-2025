# Задание A : Hello World модуль

## 1. Реализация
Код для этого задания предоставлен в файле hello_module.c

В модуле реализованы:
* параметр `message` (строка), который можно передать при загрузке;
* функция `hello_init()` — выводит приветствие (либо значение параметра, либо дефолтное сообщение);
* функция `hello_exit()` — выводит прощание;
* метаданные (`MODULE_LICENSE`, `MODULE_AUTHOR`, `MODULE_DESCRIPTION`, `MODULE_VERSION`).

## 2. Ожидаемый и реальный вывод

### Ожидаемый вывод:
* При загрузке без параметра:
```
hello_module: Hello from Malets Julia module!
```
* При загрузке с параметром:
```
hello_module: Custom greeting
```
* При выгрузке:
```
hello_module: Goodbye from Malets Julia module!
```

### Реальный вывод:
* Загрузка без параметра:
```
hello_module: Hello from Malets Julia module!
```
* Загрузка с параметром:
```
hello_module: Custom greeting
```
* Выгрузка:
```
hello_module: Goodbye from Malets Julia module!
```

### Итог:
Ожидаемый и реальный вывод полностью совпали.

## 3. Трудности и их решение

1. Ошибка при повторной загрузке модуля (`File exists`)
 * Причина: модуль уже был загружен.  
 * Решение: перед новой загрузкой использовать `sudo rmmod hello_module`.

2. Проверка параметра в sysfs
 * Нужно было убедиться, что параметр доступен через `/sys/module/hello_module/parameters/message`.  
 * Решение: выполнить команду `cat /sys/module/hello_module/parameters/message` и убедиться, что значение совпадает с переданным.



# Задание B : /proc файл с информацией

## 1. Реализация
Код для этого задания предоставлен в файле proc_module.c

В модуле реализованы:
* создание файла `/proc/student_info` через `proc_create()`;
* функция `proc_read()`, которая выводит:
  * имя студента,
  * группу и подгруппу,
  * время загрузки модуля (в jiffies),
  * счётчик обращений к файлу;
* функция `proc_exit()`, которая удаляет файл `/proc/student_info` при выгрузке;
* метаданные (`MODULE_LICENSE`, `MODULE_AUTHOR`, `MODULE_DESCRIPTION`, `MODULE_VERSION`).

## 2. Ожидаемый и реальный вывод

### Ожидаемый вывод:
* При каждом обращении к файлу `/proc/student_info`:
```
Name: Malets Julia Group: 9, Subgroup: 2 Module loaded at: <значение jiffies> Read count: <увеличивается на 1>
```

* При выгрузке модуля:
```
proc_module: Removed /proc/student_info proc_module: Exiting
```

### Реальный вывод:

* Первое чтение:
```
Name: Malets Julia Group: 9, Subgroup: 2 Module loaded at: 4313327194 jiffies Read count: 1
```

* Второе чтение:
```
Name: Malets Julia Group: 9, Subgroup: 2 Module loaded at: 4313327194 jiffies Read count: 2
```

* Третье чтение:
```
Name: Malets Julia Group: 9, Subgroup: 2 Module loaded at: 4313327194 jiffies Read count: 3
```

* Выгрузка:
```
proc_module: Removed /proc/student_info proc_module: Exiting
```

### Итог:
Ожидаемый и реальный вывод полностью совпали:
* Счётчик обращений увеличивается при каждом `cat /proc/student_info`.
* Время загрузки фиксируется при инициализации и остаётся неизменным.
* При выгрузке файл удаляется, что подтверждается логами.

## 3. Трудности и их решение

1. Проверка корректности счётчика  
 * Трудность: нужно было убедиться, что счётчик действительно увеличивается при каждом чтении.  
 * Решение: выполнить несколько последовательных `cat /proc/student_info` и сравнить вывод.

2. Удаление файла при выгрузке  
 * Трудность: при первой реализации файл мог оставаться в `/proc`.  
 * Решение: добавить вызов `proc_remove(proc_file)` в `module_exit()`.




# Задание С : Простой character device

## 1. Реализация
Код для этого задания предоставлен в файле chardev_module.c

В модуле реализованы:
* регистрация символьного устройства через `alloc_chrdev_region()`, `cdev_init()`, `cdev_add()`;
* функции `open`, `release`, `read`, `write`:
  * `open` и `release` выводят сообщения в `dmesg`;
  * `write` сохраняет данные в буфер ядра (до 1024 байт) с проверкой ошибок;
  * `read` возвращает сохранённые данные пользователю;
* функция `module_exit()` удаляет устройство и освобождает ресурсы;
* метаданные (`MODULE_LICENSE`, `MODULE_AUTHOR`, `MODULE_DESCRIPTION`, `MODULE_VERSION`).

## 2. Ожидаемый и реальный вывод

### Ожидаемый вывод:
* При загрузке модуля:
```
chardev: Initializing chardev: Registered with major <N> minor 0 chardev: Create device with: mknod /dev/mychardev c <N> 0
```

* При открытии/закрытии устройства:
```
chardev: Device opened chardev: Device closed
```

* При записи:
```
chardev: Written <X> bytes
```

* При чтении:
```
chardev: Read <X> bytes (offset now ...)
```

* При выгрузке:
```
chardev: Device unregistered
```

### Реальный вывод:
* Загрузка:
```
chardev: Initializing chardev: Registered with major 240 minor 0 chardev: Create device with: mknod /dev/mychardev c 240 0
```

* Выгрузка:
```
chardev: Device unregistered
```

* Повторная загрузка/выгрузка:
```
chardev: Initializing chardev: Registered with major 240 minor 0 chardev: Create device with: mknod /dev/mychardev c 240 0 chardev: Device unregistered
```

### Итог:
Ожидаемый и реальный вывод совпали:
- Модуль корректно регистрирует символьное устройство.
- Major number фиксируется и выводится в `dmesg`.
- При выгрузке устройство удаляется.
- Повторные загрузки/выгрузки проходят без ошибок.

## 3. Трудности и их решение

1. Ошибка при создании device-node
 * Нужно было правильно указать Major number из `dmesg`.  
 * Решение: использовать команду `sudo mknod /dev/mychardev c 240 0` и затем `sudo chmod 666 /dev/mychardev`.

2. Проверка записи/чтения
 * Трудность: убедиться, что данные сохраняются и читаются корректно.  
 * Решение: выполнить `echo "Hello" > /dev/mychardev` и затем `cat /dev/mychardev`, проверить совпадение вывода.


# Вопросы для отчёта

## 1. Базовые понятия
1. Что такое модуль ядра и зачем он нужен?  
   Модуль ядра — это загружаемый фрагмент кода, который расширяет функциональность ядра Linux без его перекомпиляции. Используется для драйверов устройств, файловых систем и сетевых протоколов.

2. Чем отличается kernel-space от user-space?  
   * Kernel-space: привилегированная область, где работает ядро и модули, полный доступ к ресурсам.  
   * User-space: область для обычных программ, ограниченный доступ, ошибки не влияют на всю систему.

3. Что произойдёт, если в модуле обратиться к NULL указателю?  
   Произойдёт аварийное завершение — kernel panic, так как ядро не защищено от таких ошибок.

4. Почему нельзя использовать printf() в модуле ядра?  
   В ядре нет стандартной библиотеки C. Вместо `printf()` используется `printk()`, который пишет в буфер логов ядра.

5. Что такое kernel panic и как его избежать?  
   Kernel panic — критическая ошибка ядра, приводящая к остановке системы. Избегают её проверкой указателей, правильным управлением памятью и использованием безопасных API.

## 2. Жизненный цикл модуля
6. Какие функции вызываются при insmod и rmmod?  
   * `insmod` → вызывает функцию `module_init()`  
   * `rmmod` → вызывает функцию `module_exit()`

7. Что должна делать функция module_exit()?  
   Освобождать все ресурсы: память, устройства, удалять созданные файлы `/proc` или `/sys`.

8. Что происходит, если module_init() возвращает ошибку?  
   Модуль не загружается, а `module_exit()` не вызывается. Все выделенные ресурсы должны быть освобождены вручную в `init`.

9. Можно ли выгрузить модуль, если он используется?  
   Нет. Сначала нужно закрыть все процессы, использующие модуль.

## 3. Логирование и отладка
10. Чем printk() отличается от printf()?  
    * `printf()` выводит в стандартный поток (терминал).  
    * `printk()` пишет в буфер ядра, доступный через `dmesg`.

11. Какие уровни логирования существуют в ядре?  
    * `KERN_EMERG` — авария  
    * `KERN_ALERT` — требует действий  
    * `KERN_CRIT` — критическая ошибка  
    * `KERN_ERR` — ошибка  
    * `KERN_WARNING` — предупреждение  
    * `KERN_NOTICE` — важное сообщение  
    * `KERN_INFO` — информационное  
    * `KERN_DEBUG` — отладка

12. Как посмотреть логи модуля?  
    Команда `dmesg`, либо `journalctl -k`.

13. Что означает "tainted kernel"?  
    Ядро помечено как «испорченное» из-за загрузки неподписанного или проприетарного модуля, либо из-за ошибки.

## 4. Память
14. Чем kmalloc() отличается от malloc()?  
    * `malloc()` — в user-space, работает с виртуальной памятью.  
    * `kmalloc()` — в kernel-space, выделяет физическую память напрямую.

15. Что такое флаги GFP и зачем они нужны?  
    Флаги GFP определяют условия выделения памяти (`GFP_KERNEL`, `GFP_ATOMIC` и др.), например, можно ли процесс «уснуть» при нехватке памяти.

16. Что произойдёт, если не освободить память в module_exit()?  
    Произойдёт утечка памяти, которая сохранится до перезагрузки системы.

17. Почему нельзя использовать user-space указатели напрямую в ядре?  
    Адреса user-space недоступны ядру напрямую. Нужно использовать `copy_to_user()` и `copy_from_user()` для безопасного обмена данными.

## 5. Взаимодействие с user-space
18. Что такое /proc и для чего он используется?  
    `/proc` — виртуальная файловая система для экспорта информации из ядра в user-space (например, `/proc/cpuinfo`).

19. Что такое /sys (sysfs) и чем отличается от procfs?  
    `/sys` — современный интерфейс для конфигурации устройств и параметров. В отличие от `/proc`, ориентирован на управление, а не только на информацию.

20. Зачем нужны функции copy_to_user() и copy_from_user()?  
    Для безопасного копирования данных между ядром и user-space, предотвращая доступ к недопустимым адресам.

21. Что такое character device и как он работает?  
    Символьное устройство — интерфейс для работы с устройством как с файлом (`open`, `read`, `write`). Данные обрабатываются посимвольно.

## 6. Параметры и метаданные
22. Как передать параметры модулю при загрузке?  
    Через `insmod module.ko param=value`. В коде параметр объявляется через `module_param()`.

23. Зачем нужен MODULE_LICENSE()?  
    Чтобы указать лицензию модуля. GPL-модули имеют доступ ко всем API ядра.

24. Что произойдёт, если не указать лицензию?  
    Ядро пометит модуль как «tainted», и некоторые функции будут недоступны.

## 7. Безопасность
25. Какие основные правила безопасного кода в ядре?  
    * Проверять указатели  
    * Освобождать ресурсы  
    * Не использовать стандартную библиотеку C  
    * Не обращаться напрямую к user-space указателям  
    * Не использовать числа с плавающей точкой

26. Можно ли использовать бесконечный цикл в модуле?  
    Нет, это заблокирует систему. Нужно использовать таймеры или планировщик.

27. Почему в ядре нет FPU операций?  
    Операции с плавающей точкой слишком затратны и не поддерживаются напрямую в kernel-space.

28. Что делать, если модуль вызвал kernel panic?  
    Перезагрузить систему, исправить код, проверить логи (`dmesg`), и повторить загрузку.

## 8. Практические вопросы
29. Как узнать, какие модули загружены в системе?  
    Команда `lsmod` или просмотр `/proc/modules`.

30. Как получить информацию о модуле (версия, параметры)?  
    Команда `modinfo module.ko` или просмотр `/sys/module/<имя>/parameters/`.
