# Лабораторная работа №5 — Модули ядра Linux

## Цель работы
Изучить основы разработки модулей ядра Linux, понять различия между kernel-space и user-space, а также освоить работу с виртуальными файловыми системами /proc и /sys. Работа выполнена на ядре Linux 6.1.0‑29‑generic.

---

## Подготовка окружения
Перед выполнением были установлены необходимые пакеты:

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Сборка модулей осуществлялась через Makefile с целями make, make clean, make load, make unload.

---

# Задание A — Модуль Hello World

## Реализация
Модуль:
- выводит сообщение при загрузке;
- выводит сообщение при выгрузке;
- поддерживает параметр message (строка);
- использует printk() для логирования.

## Проверка

make
sudo insmod hello_module.ko
dmesg | tail
sudo rmmod hello_module

## Вывод
Модуль работает корректно, параметры обрабатываются, ошибки отсутствуют.

# Задание B — Модуль /proc/my_config

## Реализация
Модуль создаёт файл /proc/my_config.
Функциональность:
- строка по умолчанию: "default";
- чтение возвращает текущее значение;
- запись заменяет строку на новую (до 256 символов);
- реализована защита от переполнения буфера.

## Проверка

sudo insmod proc_module.ko
cat /proc/my_config
echo "new_value" | sudo tee /proc/my_config
cat /proc/my_config
sudo rmmod proc_module

## Вывод
Модуль корректно обеспечивает двусторонний обмен данными через procfs.

# Задание C — Модуль /proc/sys_stats

## Реализация
Модуль создаёт файл /proc/sys_stats, в котором отображается:
- количество активных процессов;
- использованная оперативная память в МБ;
- uptime системы в секундах.

Используются:
- si_meminfo()
- jiffies_to_msecs()
- for_each_process() с RCU-блокировкой
- безопасное копирование copy_to_user()

## Проверка

sudo insmod sys_stats_module.ko
cat /proc/sys_stats
watch -n 1 cat /proc/sys_stats
sudo rmmod sys_stats_module

## Вывод
Модуль корректно взаимодействует со структурами ядра, выводит актуальные данные и безопасно обрабатывает запросы.

# Теоретические вопросы (кратко)

1. Модуль ядра — расширение функциональности ядра без перезагрузки.
2. Kernel-space — привилегированная область; user-space — обычные приложения.
3. NULL‑указатель в ядре может вызвать kernel panic.
4. printk() используется вместо printf().
5. Kernel panic — критическая ошибка; избегается проверкой указателей и границ.
6. При insmod вызывается module_init(); при rmmod — module_exit().
7. module_exit() освобождает ресурсы.
8. При ошибке module_init() модуль не загружается.
9. Модуль, который используется, нельзя выгрузить.
10. printk() пишет в журнал ядра.
11. Уровни логирования: EMERG…DEBUG.
12. Логи — через dmesg и journalctl -k.
13. Tainted kernel — ядро отмечено как недоверенное.
14. kmalloc() выделяет память в ядре; malloc() — в user-space.
15. GFP‑флаги определяют правила выделения памяти.
16. Неосвобождённая память приводит к утечке.
17. User‑space указатели нельзя использовать напрямую.
18. /proc предоставляет информацию о системе.
19. /sys отображает структуру устройств.
20. copy_to_user()/copy_from_user() — безопасный обмен данными.
21. Character device — символьное устройство с файловым интерфейсом.
22. Параметры передаются через insmod module.ko param=value.
23. MODULE_LICENSE сообщает тип лицензии.
24. Без лицензии ядро помечается как tainted.
25. Основные правила: проверки, освобождение ресурсов, границы буферов.
26. Бесконечный цикл в ядре недопустим.
27. FPU-операции в ядре не применяются.
28. При kernel panic — перезагрузка и анализ логов.
29. Загруженные модули: lsmod, /proc/modules.
30. Информация о модуле: modinfo, /sys/module/<name>.
