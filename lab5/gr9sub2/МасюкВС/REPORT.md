# Теоретические вопросы

1. **Модуль ядра** — динамически загружаемая часть кода, расширяющая функциональность ядра без его пересборки.
2. **Kernel-space** — привилегированное пространство ядра; **user-space** — область обычных программ.
3. Обращение к **NULL** приводит к аварийному завершению ядра.
4. В ядре нет стандартной библиотеки C, поэтому используется **printk()**.
5. **Kernel panic** — критическая ошибка ядра; предотвращается проверкой указателей и корректным освобождением ресурсов.
6. При `insmod` выполняется **module_init()**, при `rmmod` — **module_exit()**.
7. `module_exit()` должна освободить память, удалить созданные файлы/устройства.
8. Если `module_init()` возвращает ошибку, модуль не загружается.
9. Выгрузить модуль, который используется, невозможно.
10. `printk()` пишет в системный лог, имеет уровни важности; `printf()` работает только в user-space.
11. Уровни логирования: от `KERN_EMERG` до `KERN_DEBUG`.
12. Логи модуля смотрят через `dmesg`, `journalctl -k`.
13. **Tainted kernel** — ядро помечено как использующее недоверенный модуль.
14. `kmalloc()` выделяет память в kernel-space; `malloc()` — в user-space.
15. **GFP-флаги** задают поведение выделения памяти (можно ли спать, контекст прерывания и т.д.).
16. Неосвобождённая память остаётся утекшей до перезагрузки.
17. Указатели user-space нельзя использовать напрямую — нужны `copy_to_user()` и `copy_from_user()`.
18. `/proc` — виртуальная ФС с экспортом информации о системе.
19. `/sys` — отображает структуру устройств и параметров; отличается строгой структурой.
20. `copy_to_user()` / `copy_from_user()` обеспечивают безопасный обмен данными.
21. **Character device** — символьное устройство, работающее через операции чтения/записи как файл.
22. Параметры передаются через `insmod module.ko param=value`.
23. `MODULE_LICENSE()` сообщает тип лицензии.
24. Без лицензии ядро помечается как tainted, часть API недоступна.
25. Правила: проверки ошибок, освобождение ресурсов, отсутствие долгих блокировок.
26. Бесконечные циклы недопустимы — могут зависнуть всю систему.
27. В ядре нет FPU-операций, потому что работа с FPU небезопасна в прерываниях.
28. При kernel panic требуется перезагрузка и исправление ошибки.
29. Загруженные модули — `lsmod`, `/proc/modules`.
30. Информация о модуле — `modinfo`, `/sys/module/<name>`.
