### Вопросы для отчёта

Базовые понятия

1. Что такое модуль ядра и зачем он нужен?

Модуль ядра — это фрагмент кода, который может быть динамически загружен и выгружен из ядра Linux во время работы системы без перезагрузки.

Зачем нужен:

    Добавление драйверов устройств (USB, сетевые карты и т.д.)

    Поддержка новых файловых систем

    Расширение функциональности ядра

    Экономия памяти (загружаются только нужные модули)

2. Чем отличается kernel-space от user-space?
Kernel-space	User-space
Привилегированный режим	Непривилегированный режим
Полный доступ к аппаратуре	Ограниченный доступ
Ошибка → kernel panic	Ошибка → завершение процесса
Нет стандартной библиотеки C	Есть стандартная библиотека C
Использует printk()	Использует printf()
Не может использовать FPU	Может использовать FPU

3. Что произойдёт, если в модуле обратиться к NULL указателю?

Произойдёт kernel panic — ядро аварийно завершит работу, и система перезагрузится. В отличие от user-space, где обращение к NULL вызывает segmentation fault только в текущем процессе.

4. Почему нельзя использовать printf() в модуле ядра?

Потому что printf() — это функция стандартной библиотеки C, которая недоступна в kernel-space. Вместо неё используется printk(), которая пишет в буфер ядра и работает без зависимостей от user-space библиотек.

5. Что такое kernel panic и как его избежать?

Kernel panic — это критическая ошибка ядра, приводящая к остановке системы.

Как избежать:

    Всегда проверять указатели перед использованием

    Проверять возвращаемые значения функций

    Использовать правильные функции копирования (copy_to_user/copy_from_user)

    Освобождать все ресурсы в module_exit()

    Тестировать модули в виртуальной машине

Жизненный цикл модуля

6. Какие функции вызываются при insmod и rmmod?

    При insmod: вызывается функция, зарегистрированная через module_init()

    При rmmod: вызывается функция, зарегистрированная через module_exit()

7. Что должна делать функция module_exit()?

Должна освобождать все ресурсы, выделенные в module_init():

    Освобождать память (kfree)

    Удалять /proc и /sys файлы

    Отменять регистрацию устройств

    Закрывать открытые соединения

8. Что происходит, если module_init() возвращает ошибку?

Модуль не загружается, и функция module_exit() НЕ вызывается. Поэтому если в init произошла ошибка после выделения ресурсов, нужно освободить их вручную перед возвратом ошибки.

9. Можно ли выгрузить модуль, если он используется?

Нет, нельзя. Система вернёт ошибку:
bash

rmmod: ERROR: Module my_module is in use

Нужно сначала закрыть все процессы, использующие модуль.
Логирование и отладка

10. Чем printk() отличается от printf()?
printk()	printf()
Пишет в буфер ядра	Пишет в stdout
Есть уровни важности (KERN_INFO и т.д.)	Нет уровней важности
Просмотр через dmesg	Просмотр сразу в терминале
Работает всегда, даже при сбоях	Может блокироваться

11. Какие уровни логирования существуют в ядре?

    KERN_EMERG (0) - Аварийная ситуация

    KERN_ALERT (1) - Требует немедленных действий

    KERN_CRIT (2) - Критическая ошибка

    KERN_ERR (3) - Ошибка

    KERN_WARNING (4) - Предупреждение

    KERN_NOTICE (5) - Важное уведомление

    KERN_INFO (6) - Информация

    KERN_DEBUG (7) - Отладочная информация

12. Как посмотреть логи модуля?
bash

dmesg | tail -20              # Последние 20 сообщений
dmesg | grep "module_name"    # Поиск по имени модуля
dmesg -w                      # Режим реального времени
journalctl -k -f              # Через systemd (если есть)
cat /var/log/kern.log         # Файл логов (Debian/Ubuntu)

13. Что означает "tainted kernel"?

"Tainted kernel" означает, что ядро "испорчено" — загружен неподписанный или проприетарный модуль. Проверить можно:
bash

cat /proc/sys/kernel/tainted

Если значение не 0 — ядро помечено как tainted.
Память

14. Чем kmalloc() отличается от malloc()?
kmalloc()	malloc()
Выделяет физически непрерывную память	Выделяет виртуальную память
Работает в kernel-space	Работает в user-space
Использует флаги GFP	Использует размер
Не может использовать swap	Может использовать swap
Ошибка → kernel panic	Ошибка → возврат NULL

15. Что такое флаги GFP и зачем они нужны?

GFP (Get Free Pages) — флаги управления памятью:

    GFP_KERNEL - обычное выделение (может спать)

    GFP_ATOMIC - атомарное выделение (не может спать, для прерываний)

    GFP_USER - для user-space данных

    GFP_DMA - для DMA-памяти

16. Что произойдёт, если не освободить память в module_exit()?

Произойдёт утечка памяти — выделенная память будет потеряна до перезагрузки системы. В ядре нет garbage collector.

17. Почему нельзя использовать user-space указатели напрямую в ядре?

Потому что:

    User-space использует виртуальную память

    Указатели user-space невалидны в kernel-space

    Прямое использование может вызвать kernel panic

Нужно использовать:

    copy_to_user() - для копирования из ядра в user-space

    copy_from_user() - для копирования из user-space в ядро

Взаимодействие с user-space

18. Что такое /proc и для чего он используется?

/proc (procfs) — виртуальная файловая система для предоставления информации о системе и процессах.

Примеры:
bash

cat /proc/cpuinfo      # Информация о процессоре
cat /proc/meminfo      # Информация о памяти
cat /proc/version      # Версия ядра

19. Что такое /sys (sysfs) и чем отличается от procfs?

/sys (sysfs) — современная файловая система для экспорта информации об устройствах и драйверах.

Отличия:

    procfs - для информации о процессах и системе

    sysfs - для информации об устройствах и их конфигурации

    В sysfs один файл = одно значение

20. Зачем нужны функции copy_to_user() и copy_from_user()?

Для безопасного копирования данных между kernel-space и user-space. Они:

    Проверяют валидность user-space указателей

    Обрабатывают ошибки корректно

    Предотвращают kernel panic

21. Что такое character device и как он работает?

Character device — это устройство, с которым можно работать как с файлом (последовательный доступ).

Примеры: /dev/null, /dev/random, /dev/tty

Как работает:

    Регистрируется major/minor номер

    Создаётся файл в /dev

    Программы работают с ним через файловые операции (open, read, write, close)

Параметры и метаданные

22. Как передать параметры модулю при загрузке?
bash

sudo insmod module.ko param1=value1 param2=value2

В коде:
c

static int my_param = 10;
module_param(my_param, int, 0644);

23. Зачем нужен MODULE_LICENSE()?

    Указывает лицензию модуля

    Даёт доступ к GPL-only функциям ядра

    Предотвращает пометку ядра как "tainted" для GPL модулей

24. Что произойдёт, если не указать лицензию?

Ядро пометит модуль как проприетарный (tainted), и некоторые функции ядра будут недоступны.
Безопасность

25. Какие основные правила безопасного кода в ядре?

    Всегда проверять возвращаемые значения

    Освобождать все ресурсы в exit

    Использовать copy_to_user/copy_from_user

    Проверять границы массивов

    Не использовать стандартную библиотеку C

    Тестировать в виртуальной машине

26. Можно ли использовать бесконечный цикл в модуле?

Нет! Бесконечный цикл может заблокировать ядро и вызвать kernel panic, особенно в обработчиках прерываний.

27. Почему в ядре нет FPU операций?

Потому что FPU (Floating Point Unit) операции:

    Требуют сохранения/восстановления состояния

    Медленные

    Не атомарные

    В ядре обычно не нужны (используется целочисленная арифметика)

28. Что делать, если модуль вызвал kernel panic?

    Перезагрузить систему (модуль не загрузится автоматически)

    Проанализировать код, найти ошибку

    Исправить проблему (проверка указателей, границ и т.д.)

    Протестировать исправленную версию

Практические вопросы

29. Как узнать, какие модули загружены в системе?
bash

lsmod                      # Список загруженных модулей
cat /proc/modules          # Детальная информация
lsmod | grep module_name   # Поиск конкретного модуля

30. Как получить информацию о модуле (версия, параметры)?
bash

modinfo module_name        # Информация о загруженном модуле
modinfo module.ko          # Информация о файле модуля
cat /sys/module/module_name/parameters/*  # Параметры модуля
