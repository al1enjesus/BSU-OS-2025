## Задание A: Hello World модуль

### Цель
- Создать простой модуль, который:
	- При загрузке (insmod) выводит "Hello from [ВАШ_ИМЯ] module!"
	- При выгрузке (rmmod) выводит "Goodbye from [ВАШ_ИМЯ] module!"
	- Принимает параметр message (строка)
	- Если параметр задан, выводит его вместо дефолтного сообщения 
### Шаги решения
1. Создать файл модуля `hello_module.c` и подключить необходимые заголовки.
2. Объявить строковый параметр `message` через `module_param`.
3. Реализовать функции `hello_init` (printk с приветствием) и `hello_exit` (printk с прощанием).
4. Зарегистрировать функции с помощью `module_init` и `module_exit`.
5. Указать метаданные: `MODULE_LICENSE, MODULE_AUTHOR, MODULE_DESCRIPTION`.
6. Создать `Makefile` для сборки модуля.
7. Собрать модуль командой `make`.
8. Загрузить модуль `insmod`, проверить вывод через `dmesg`.
9. Загрузить модуль с параметром `message="..."`, снова проверить вывод.
10. Выгрузить модуль `rmmod` и убедиться в корректных сообщениях через `dmesg`.

Создать модуль, который создаёт файл `/proc/student_info` с информацией:
   - Ваше имя
   - Группа и подгруппа
   - Текущее время загрузки модуля (в секундах с boot, используйте jiffies)
   - Счётчик обращений к файлу
### Шаги решения
1. Создать модуль `student_info_module.c` и подключить нужные заголовки.

## Задание C

### Цель
- Изучить Page Faults в реальном времени

### Шаги решения
1. Написать программу в которой:
    1. Выделяет большой массив (например, 100 MB).
    2. Заполняет его данными с разными паттернами доступа: 
        - Последовательное заполнение 
        - Случайное заполнение
    3. Во время работы выводит количество minor/major page faults.
2. Проанализировать полученные данные.

### Решение

Запустим программу написанную в файле `page_faults.c`.

Вывод в консоли:
```
Minor faults: 78, Major faults: 0
Minor faults: 25682, Major faults: 0
Minor faults: 25683, Major faults: 0
```
Проанализируем полученный результат:
1. Почему при последовательном доступе больше page faults?
    Цикл:
    ```c
    for (size_t i = 0; i < size; i += 4096)
    arr[i] = 'A';
    ```
    Проходит по массиву страница за страницей (4096 байт = размер одной страницы).
    Каждая итерация затрагивает новую страницу, а значит — впервые обращается к памяти, которая ещё не выделена физически.

    На каждую такую страницу ОС вызывает один minor page fault.

    100 MB / 4 KB = примерно 25 600 страниц — ровно столько и видно в выводе:
    ```
    Minor faults: 78, Major faults: 0         ← до доступа
    Minor faults: 25682, Major faults: 0      ← после последовательного прохода
    ```
2. Почему major faults появляются (или нет)?
    ```c
    char *arr = malloc(size);
    for (size_t i = 0; i < size; i += 4096)
    arr[i] = 'A';
    ```
    - `malloc()` или `mmap(MAP_ANONYMOUS)` выделяет анонимную память — без связи с файлом.
    - При первом доступе ОС просто создаёт новую страницу в RAM (обнуляет её).
    - Никаких обращений к диску нет → `major fault` не нужен.

3. Как изменится поведение при повторном запуске?
    - Minor faults повторяются
    При каждом запуске программа вызывает:
    ```c
    arr = malloc(size);
    for (size_t i = 0; i < size; i += 4096)
    arr[i] = 'A';
    ```
    То есть — заново выделяет новый виртуальный диапазон (новые адреса в памяти).
    Эти адреса раньше не использовались текущим процессом, поэтому:
    - ОС снова лениво выделяет страницы при первом обращении
    - на каждую страницу возникает minor page fault,
    - и количество page faults остаётся примерно тем же (≈ 25 600).

    Major faults означают, что страница загружается с диска (например, файл через mmap, или страница подкачки).
    А программа:
    - работает только с анонимной памятью (через malloc),
    - не использует swap,
    - не читает файлы с диска.
    Поэтому при каждом запуске всё выделяется прямо из RAM — major faults не появляются вообще.

    Можно подумать, что ОС могла бы «запомнить» страницы и не выделять заново.
    Но это невозможно, потому что:
    - При завершении процесса ОС освобождает всю его память.
    - У нового процесса — новое адресное пространство (новая таблица страниц).
    - Старые страницы либо возвращаются в пул свободных страниц, либо очищаются.
    Поэтому при каждом запуске память выделяется с нуля, и minor page faults возникают заново — ровно так же, как в первый раз.

В ходе выполнения лабораторной работы было изучено поведение системы при возникновении page faults (ошибок страниц) в реальном времени.

1. В процессе эксперимента была написана и запущена программа, выделяющая большой участок памяти (100 МБ) и заполняющая его разными способами:
